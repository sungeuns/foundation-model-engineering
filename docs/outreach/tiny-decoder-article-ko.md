# 디코더가 미래를 훔쳐보고 있지는 않을까? CPU로 확인하는 실험

상태: AI의 도움을 받아 작성한 게시용 초안이며, 아직 제출하지 않았습니다. 책의 합성 토큰 복사 실습을 바탕으로 합니다. 2026-11-18 로컬 Linux/Jupyter에서 실행을 검증했으며, 호스팅된 Colab 실행은 검증하지 않았습니다. 실제 서비스 모델의 성능을 주장하는 글이 아닙니다.

디코더는 다음 토큰을 예측합니다. 그런데 학습 때 입력 텐서에는 이미 그 뒤의 토큰도 들어 있습니다. 정답을 미리 보지 못하도록 막는 것이 어텐션 마스크입니다.

그렇다면 손실 곡선부터 보기 전에 확인할 수 있는 것이 있습니다. 미래 입력을 바꿨을 때, 그보다 앞선 위치의 예측도 바뀔까요?

## 실행하기 전에 결과를 예측해보세요

[CPU 실습 노트북](https://colab.research.google.com/github/sungeuns/foundation-model-engineering/blob/main/public/labs/tiny-decoder-lab-ko.ipynb)은 파라미터 10,161개인 한 층짜리 디코더를 학습합니다. 과제는 간단합니다. `3, 8, 2, 11`처럼 서로 다른 기호 네 개를 반복합니다. 모델은 처음 네 기호를 보고 나머지 패턴을 이어 쓰도록 학습합니다. 자연어 문서가 아니라 직접 생성한 기호 데이터입니다.

모델 다운로드나 API 키는 필요하지 않습니다. 노트북 안에 전체 실습 코드가 있으며 CPU PyTorch로 실행합니다. Colab에서는 Google 로그인이 필요합니다. [노트북을 내려받아 로컬 Jupyter](https://sungeuns.github.io/foundation-model-engineering/labs/tiny-decoder-lab-ko.ipynb)에서 실행해도 됩니다. 의존성과 정확한 학습 조건은 [실습 안내](https://sungeuns.github.io/foundation-model-engineering/ko/chapter-7/tiny-decoder-lab/)에 있습니다.

다음 세 가지를 먼저 예측해보세요.

1. 인과 마스크를 쓰는 모델에서 미래 기호만 바꾸면 앞선 위치의 로짓도 달라질까요?
2. 어텐션이 현재 위치만 볼 수 있도록 바꾸면 복사 성능을 유지할까요?
3. 학습을 절반에서 멈췄다가 체크포인트를 복원하면, 이 고정된 CPU 환경에서 남은 갱신이 정확히 재현될까요?

노트북은 세 가지를 실제로 확인합니다. 별도로 만든 학습 전 모델에서는 인과 마스크를 의도적으로 제거합니다. 그러면 미래 입력이 바뀔 때 앞선 로짓도 달라집니다. 이 검사는 접근하면 안 되는 정보가 흘러들어오는 경로를 보여줍니다. 마스크 없이 학습한 모델의 성능을 측정한 것은 아닙니다.

## 한 가지 능력만 빼고 비교하기

복사 실험에서는 어텐션이 볼 수 있는 위치만 바꿉니다. 초기화, 파라미터, 데이터 샘플링, 옵티마이저, 갱신 횟수는 같습니다. 현재 위치만 보는 모델에도 임베딩, 위치 정보, 비선형 층은 그대로 있습니다.

기록된 seed-7 실행에서 테스트 손실은 인과 어텐션 모델이 **타깃당 약 0.0508 nats**, 현재 위치만 보는 모델이 **2.7042 nats**였습니다. 유효 기호 16개에 균등한 확률을 주면 손실은 `ln(16) ≈ 2.773`입니다.

앞선 문맥을 볼 수 있다는 점이 이 합성 과제에 도움이 됐다는 근거입니다. 특정 헤드가 복사 패턴을 어떻게 표현하는지, 자연어 모델도 얼마나 잘할지는 입증하지 않습니다. 테스트 시퀀스도 16개뿐입니다. 탐욕적 생성에서는 그중 15개를 끝까지 맞혔습니다. 토큰 정확도만 보면 틀린 시퀀스 하나를 놓치기 쉽습니다.

## 재개도 검증할 가설로 다루기

가중치만 저장해서는 학습을 재현할 수 없습니다. 이 실습은 옵티마이저 상태, 난수 생성기 상태, 샘플러 위치, 학습 단계, 데이터와 설정을 연결하는 해시도 기록합니다. 체크포인트의 무결성을 검사하고 복원한 다음, 남은 갱신을 비교합니다.

노트북은 체크포인트의 **복사본** 을 손상시켜 로더가 거부하는지 확인하고, 정상 파일은 그대로 복원합니다. 여기서 정확한 재현이 확인되더라도 하나의 로컬 CPU 실행 조건에 대한 결과입니다. 분산 장애 복구나 PyTorch 버전 사이의 동일한 결과까지 보장하지 않습니다.

노트북을 실행하고 결과 묶음을 저장한 뒤, 예상과 달랐던 결과 하나를 설명해보세요. [전체 실습](https://sungeuns.github.io/foundation-model-engineering/ko/chapter-7/tiny-decoder-lab/)에서는 마스킹, 데이터 분할, 복구 조건을 연결합니다. [소스 저장소](https://github.com/sungeuns/foundation-model-engineering)에는 동등한 영문 노트북도 있으며, 구체적인 오류 제보와 수정 제안을 받고 있습니다.
