## Search discovery and AI search

Existing canonical URLs, hreflang, unique summaries, structured data, and sitemap coverage were already sound. A project-level `/foundation-model-engineering/robots.txt` is not the host-root robots file. The host root currently returns 404, which is not itself a crawling block. Do not present a comment in the project file as a crawl fix.

The unresolved question is which **specific** Search Console exclusion reason affects which URLs. When access is available, group excluded URLs by reason and language, then inspect five representative valuable pages. For duplicate/canonical statuses, compare declared and selected canonical; for crawled/discovered-not-indexed, inspect fetched content, internal links, relevance, and crawl history. Only change the site in response to evidence. Submit the canonical sitemap once if it is missing; repeated requests do not replace quality or guarantee indexing.

Google's [AI search guidance](https://developers.google.com/search/docs/appearance/ai-features) says normal Search eligibility and helpful, reliable content remain the basis for inclusion. Its [generative AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) does not support special-schema shortcuts. This work improves readable server-rendered content, clear explanations, source attribution, and discoverable links. It makes no promise that an `llms.txt` file or a GEO trick will produce citations.

## Four-week experiment, not a posting flood

1. **Establish the funnel.** Save a consistent 28-day Search Console baseline when accessible: query, landing page, language, impressions, clicks, CTR, position, and indexing status. Save GitHub stars and available aggregate traffic at the same observation time. Do not infer individual star conversion from unrelated aggregate counts.
2. **Share one useful result at a time.** Candidate sequence: KV cache capacity, RAG diagnosis, order-sensitive judges. Use the relevant original lesson and a genuine example. Publish only where current rules permit, with author participation. Keep the three prepared drafts as editorial material until those conditions hold.
3. **Use reader failures as the backlog.** Prioritize corrections and requests showing a reader could not reproduce or understand a specific step. A rigorous counterexample or lab result is a stronger reason to return than an unverified “latest model” table.
4. **Compare after an observation window.** Look for more qualified visitors reaching a lesson, useful issues, repeat readership, and star growth. Check query mix before attributing CTR changes to titles. Small counts are noisy; do not optimize on a single day's spike.

Working checkpoints: 100 stars, then 300, then 1,000+. These are decision checkpoints without forecast dates. If discovery grows without reader engagement, improve the selected lesson. If readers engage but discovery stays low, try another relevant venue or search-intent entry point. Do not buy stars, solicit coordinated votes, mass-post, or invent testimonials.
