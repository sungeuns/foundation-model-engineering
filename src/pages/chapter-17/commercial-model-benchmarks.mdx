# 17.6 Commercial and Open-weight Model Benchmarks

Suppose a model is cheaper per token but takes twice as many tool turns to finish your task. Has your system become cheaper? A leaderboard cannot answer that by itself. You need the evaluated configuration, the billing rules and a definition of a successful task.

**As of 2026-11-24.** This static snapshot covers 45 selected profiles, including GLM-5.4, Ling-3.2-air, GPT-6.2 Astra/Sol and Gemini 4 Neon/Carbon. A row dates the event its source establishes, such as an API launch, publication of weights or a checkpoint revision. The last two numerical columns give the Artificial Analysis index and estimated cost per task where available. Reverify access and pricing before using a row to budget a deployment.

## 1. Know What the Number Measures

The table and explorer preserve **Artificial Analysis Intelligence Index v5.0.1**. It combines nine evaluations across knowledge work, coding, science and general tasks. [[1]](#ref-1)

On November 24, 2026, Artificial Analysis released **v5.0.2**. Terminal-Bench moved from 4.0 to 4.1. The 66 tasks, instructions and agent environments stayed the same, but the tests that determine whether a solution passes changed. For FrontierCode-AA 2.0, AA regraded existing attempts with an updated trajectory scanner and used an LLM judge to review attempts the scanner flagged for further inspection. [[1]](#ref-1) [[124]](#ref-124)

Consider Gemini 4 Carbon at High reasoning effort. AA reports **65.2%** on Terminal-Bench 4.0 and **66.2%** on 4.1. In both versions, AA used the same agent harness (`mini-swe-agent`) and averaged first-attempt success over three runs per task. A team claiming a one-percentage-point model improvement from those figures would also be counting a change in how success was judged. Evaluate both candidates with the same benchmark version. [[125]](#ref-125) [[126]](#ref-126)

Each point represents a model **plus** an effort setting and evaluation system. Fallback, tools, scaffold, token budgets, sampling and grader can all affect the result. These are not equal-compute experiments. An index is not an accuracy percentage, and a context limit is not retrieval accuracy. “Not reported” means that this record has no verified value for the mapped revision and methodology; it never means zero.

**Read the cost column carefully.** AA computes a weighted cost per task using its workload, provider prices and typical cache-hit assumptions. It is not a captured invoice for your deployment. Prices can change without changing the model's score. On this snapshot, AA's Argon and Carbon profiles use \$4/\$20 per million input/output tokens, while Google's official introductory rates are \$2/\$10 through November 30, with \$4/\$20 scheduled from December 1. The table preserves AA's published calculation; the token-price explorer uses the dated provider rates. Do not silently mix them [[2]](#ref-2) [[3]](#ref-3) [[4]](#ref-4).

## 3. What the Latest Releases Change

### GLM-5.4: usable service, pending weights

Z.ai's November 23 release makes **GLM-5.4** available through Coding Plan, ZCode and Z.ai Chat. Its standard pay-as-you-go API is still marked coming soon; downloadable weights are planned after further safety work. Coding Plan already has subscription API access, so “no API” would also be wrong. Do not inherit GLM-5.3 Flash's MIT license or translate subscription-credit multipliers into USD token prices [[5]](#ref-5) [[6]](#ref-6) [[7]](#ref-7).

The disclosed design reuses a 28-layer block twice in a 750B-scale model, with gated updates and a combination of shared global KV and local attention. [Section 4.5](/chapter-4/various-llm-architectures#glm-54-reusing-layers-separates-depth-from-capacity) works through what gets stored once and what runs twice. Exact total/active counts, the full training mixture and the eventual weight license remain undisclosed. Its 30B architecture ablation is not a controlled evaluation of the full deployed model [[5]](#ref-5).

**Pricing follow-up, as of 2026-11-25.** Suppose one text request uses 10,000 uncached input tokens and 2,000 billed output tokens, with no tools. Z.ai lists GLM-5.3 at USD 1.40 per million input tokens and 4.40 per million output tokens. That request costs USD 0.0228. GLM-5.3 Flash lists 0.15 and 0.50 respectively, giving USD 0.0025. The same public price sheet has no token rate for GLM-5.4. Budget a 5.4 Coding Plan workload against the plan's quota until a pay-as-you-go rate is published. [[7]](#ref-7)

### GPT-6.2 Astra and Sol: measure the operating point

On November 17, OpenAI released **GPT-6.2 Astra and Sol** through the API and made both available in ChatGPT Work and Codex on eligible paid plans. OpenAI hosts both models and has not published their weights or detailed architecture. [[94]](#ref-94) In the API, both accept text and images and return text. The 1,050,000-token context window has separate limits of 922,000 input and 128,000 output tokens. Tool calling requires Responses, and neither model accepts reasoning effort `none`. [[8]](#ref-8) [[9]](#ref-9) [[10]](#ref-10)

On November 23, OpenAI began rolling out a version of GPT-6.2 optimized for the **ChatGPT chat tab** to Plus, Pro, Business and Enterprise. The system card calls it “GPT-6.2 (November 23).” [[115]](#ref-115) [[116]](#ref-116)

On November 24, OpenAI updated the API alias `chat-latest` to follow the latest chat model on those plans. The model card lists the rolling alias without a dated snapshot ID that callers can pin. A support team testing a difficult ticket today may reach a different model with the same alias next month. Save the original ticket, date, tool settings and reply for comparison. Before deploying, rerun the same tickets with the API model ID and reasoning effort the service will use. The Astra and Sol scores above apply to their respective API evaluation profiles. [[8]](#ref-8) [[123]](#ref-123)

On November 24 the Responses API added four healthcare configurations, `gpt-6.2-astra-healthcare`, `gpt-6.2-sol-healthcare`, `gpt-6-astra-healthcare` and `gpt-6.1-sol-healthcare`. [[8]](#ref-8) These configurations add instructions for clinical questions and can search a dedicated medical index when web search is enabled. [[127]](#ref-127) Suppose you are evaluating a summary of two published studies. Record the configuration ID, whether search was on and which sources actually support the summary. The table’s general Astra and Sol scores do not test that retrieval-and-citation task under the clinical instructions.

The chart's Max-effort profiles do not tell you the best effort for a latency-sensitive application. Compare at the effort and service tier you intend to operate. The cost example below shows why even a correctly copied base token price is insufficient.

### Gemini 4: shared context and dated prices

Google announced the **Gemini 4 Neon** API release on November 18 and a Gemini app rollout for Google AI Pro and Ultra subscribers. For **Carbon**, the November 10 launch included the API and a Gemini app rollout for Ultra subscribers. [[128]](#ref-128) [[129]](#ref-129)

Neon's 1,048,576-token budget is shared by input and output. Its default synchronous output cap is 65,536 tokens; a background long-decode path can use more of the shared budget. “One million input plus one million output” is therefore an incorrect interpretation. Neon supports implicit caching rather than an explicit-cache API; do not assume identical cache controls across a family [[11]](#ref-11) [[12]](#ref-12).

Google's November 12 launch brought **Hydrogen** to the Gemini API, all tiers of Google AI Studio, the Gemini app and Google Search. Google also tested Hydrogen as a worker in a multi-model system. The reported result depends on the coordinator, workers and execution policy together. [[13]](#ref-13)

### Will a 300,000-token prompt fit Ling-3.2-air?

InclusionAI’s published SGLang recipe gives the prompt and generated output **262,144 tokens combined**. A 300,000-token prompt exceeds that budget by 37,856 tokens before generation starts. The checkpoint’s `text_config` sets `max_position_embeddings` to 262144, and the model card starts the server with `--context-length 262144`. [[112]](#ref-112) [[117]](#ref-117)

InclusionAI released the MIT-licensed weights on November 23. The model card reports 124B total parameters and 5.5B active per token. Artificial Analysis links to those weights and reports 23 index points, no task cost and a one-million-token context window. The explorer leaves the context field blank because the profile and the published serving recipe give different limits. For a hosted API, check the endpoint’s own input and output limits before sizing a request. [[112]](#ref-112) [[113]](#ref-113) [[114]](#ref-114)

**Qwen4-Max** launched on November 16 through QwenCloud (API and Token Plan), QwenWork and QwenStudio, following the November 11 Token Plan preview. Alibaba announced plans to release weights for smaller Qwen4 models. [[14]](#ref-14) [[130]](#ref-130)

## 4. A Worked Cost Example: Crossing 272K Input Tokens

**Rates checked 2026-11-25.** At Standard short-context rates, GPT-6.2 Astra costs \$8 input/\$40 output per million tokens and Sol costs \$2/\$10. Above **272,000 input tokens**, the input rate doubles and the output rate becomes 1.5 times the base rate **for the whole request** [[9]](#ref-9) [[10]](#ref-10).

Imagine a repository review with 300,000 uncached input tokens and 10,000 billed output tokens. Using Sol's base rates gives \$0.70. Applying the long-context rule gives **\$1.35**. Astra's corresponding amount is **\$5.40**. Reducing the input can affect both token count and the applicable rate; whether it preserves quality needs a separate evaluation.

Now compare two pairs of Sol requests. Each pair sends 544,000 input tokens and produces 20,000 billed output tokens in total. Split the input evenly and both calls qualify for the short rate: the pair costs **\$1.288000**. Move just one input token from the first call to the second, keeping output fixed at 10,000 each, and the pair costs **\$1.882002**. Applying the rate to the average request hides the extra \$0.594002. Price individual requests before you aggregate.

<a id="background-completion-cost"></a>

### How much does a GPT-6.2 background request save overnight?

Suppose a daytime report and an overnight report each use 50,000 uncached input tokens and 2,000 billed output tokens on GPT-6.2 Sol. At Standard rates, the input costs \$0.10 and the output costs \$0.02. As of 2026-11-25, OpenAI's Responses API offers discounted background completion windows in public beta. With those same token counts, `soonest` costs **\$0.120**, `2h` costs **\$0.084**, and `8h` costs **\$0.072**. Giving the overnight job eight hours saves 4.8 cents on model tokens [[10]](#ref-10) [[132]](#ref-132) [[133]](#ref-133).

The discounted requests use Standard processing with `background: true`, streaming off, and the selected `background_options.completion_window`. The clock starts when the API accepts the request and targets its initial response. If a tool call requires another round trip, the first window does not set a deadline for that whole workflow [[132]](#ref-132).

Run `python request_cost.py` to reproduce both the 272K boundary and the background-window example with the standard library. The calculation includes billed reasoning tokens in output and excludes cache reads, tools, images and taxes. [[9]](#ref-9) [[10]](#ref-10) [[133]](#ref-133)

## 6. Turn a Shortlist into a Release Decision

Use the quality/cost/latency/context/openness/safety Pareto surface to choose candidates. Evaluate the same private tasks with pinned tools, permissions, scaffold, effort, retries, limits and grader. Report paired uncertainty, language/domain slices, base-capability retention, format/tool correctness, safety, tail latency, error rate and cost per successful workflow. A critical slice failure blocks release even if the mean improves.

Keep weights or API revision, tokenizer/template, quantization, runtime, generation configuration, tool schema and safety policy in one immutable artifact bundle. Evaluate hosted and local versions separately. Canary with bounded permissions, retain a known-good route and rehearse rollback of cached state and pending effects. Typed decision models need separate calibration and selective-risk evaluation; see [Section 16.7](/chapter-16/decision-models-and-selective-prediction).

## Quizzes

<details>
<summary>Quiz 1: Can an unchanged model have different v4.3.2 and v5.0.1 scores?</summary>
*Yes. The tasks, grading rules and aggregation define the measurement. To test whether the model improved, evaluate both model versions with the same procedure. All index scores in the November 24 table use v5.0.1.*
</details>

<details>
<summary>Quiz 2: Why is GLM-5.4 neither “fully open-weight” nor “unavailable” here?</summary>
*Its hosted subscription services are usable, including subscription API access, but standard pay-as-you-go access and weight publication are separate pending milestones. A license from an earlier model cannot establish the eventual weight license.*
</details>

<details>
<summary>Quiz 3: Why not copy an AA score onto every checkpoint with a similar name?</summary>
*Model revision, context contract, safeguards and serving configuration identify the evaluated system. The Ling 3.1 Flash and Agnes gaps illustrate why a family-name match alone is insufficient.*
</details>

<details>
<summary>Quiz 4: Why can the Google token-price axis and AA task-cost column use different rates?</summary>
*The provider has a dated introductory rate, while the captured evaluator profile uses another stated rate. Preserve both source conventions and explain the mismatch instead of claiming either is the reader's invoice.*
</details>

<details>
<summary>Quiz 5: Why does the 300K-input Sol example cost \$1.35 rather than \$0.70?</summary>
*Crossing 272K input tokens applies doubled input and 1.5-times output rates to the whole request: 0.3 × \$4 + 0.01 × \$15 = \$1.35. The output count includes billed reasoning tokens.*
</details>

<details>
<summary>Quiz 6: Does Neon's 1,048,576-token context permit that much input plus the same amount of output?</summary>
*No. It is a shared budget, with additional output-mode limits. Check the remaining budget and the chosen execution mode; advertised context size is also not a guarantee of retrieval quality.*
</details>
