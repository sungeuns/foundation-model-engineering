# 17.6 Commercial Model Benchmarks

A model release can change three things at once: what the system can solve, how much it costs to complete a task, and which deployment routes are actually available. Reading only the headline score misses the engineering decision. A public preview can be worth evaluating while still being unavailable for self-hosting; a cheap token can become an expensive task when a model emits long reasoning traces.

**As of 2026-10-13.** This page is a dated historical snapshot, not a live leaderboard. Availability and mutable values **must be reverified** before publication or procurement. The selected August–October releases below extend the previous September snapshot. Older releases remain useful historical examples elsewhere in the book; their old index values are not carried into the new comparison.

## 1. One Evaluation Version, Explicit Operating Points

The chart uses **Artificial Analysis Intelligence Index v4.3.2**. Its methodology now includes Terminal-Bench 4.0 and revised professional-work evaluations [[1]](#ref-1). A score from the previous v4.2 snapshot is not a compatible longitudinal measurement. A lower number after a suite revision does not establish that model capability deteriorated.

All index observations below come from the evaluator's model-specific pages. **Effort and fallback settings are part of each system's identity.** Different providers' `max` settings do not imply equal FLOPs, tokens, or latency. These are observed quality/cost operating points under one evaluation suite, not a controlled experiment isolating model weights. Run matched-budget private evaluations before making a causal claim or replacement decision.

The default x-axis is measured **cost per AA evaluation task**. Switching to token price uses the explicit proxy $p_b=(3p_{in}+p_{out})/4$, where $p_{in}$ and $p_{out}$ are dollars per million uncached input and output tokens. This assumes a 3:1 token mixture and excludes cache writes/reads, service tiers, tools, retries, and long-context surcharges. It is not a task-cost estimate. Missing values are omitted from plots and shown as **not reported** in details; they never become zero.

## 3. What These Releases Change for Engineers

### Hosted models: API compatibility is a release gate

GPT-6.1 Sol's documented contract differs from GPT-6 Sol: it does not support `none` reasoning, and tool calling uses Responses. Neither an endpoint's familiar name nor an unchanged token price proves request compatibility. Validate the exact model ID, effort, tool protocol, tokenizer behavior where exposed, maximum output, error handling, and routing before a canary. Input context and maximum output are different limits.

The Claude 5.5 family adds another operational lesson. The independent Opus and Sonnet measurements above include **fallback**, so the evaluated object includes the provider's routing and safety policy. Haiku 5.5 exposes adjustable effort. The current overview lists input/output prices of $4/$20 for Opus, $2/$10 for Sonnet, and **from** $0.10/$0.50 for Haiku per million tokens [[2]](#ref-2). Preserve the price qualifier rather than assigning the minimum to every operating mode. Cache pricing also deserves its own versioned field: a release-day article can become stale without a model-name change.

### Open weights: inspect the artifact that will run

DeepSeek V4.1 Flash and GLM-5.3 have public model repositories. The former changes the architecture and cache contract; the latter documents text-only inputs and always-on reasoning. These are different migration problems. Weight availability does not disclose the full data mixture, establish a reproducible training recipe, or guarantee that your serving engine supports the intended precision, attention state, and chat template.

Kimi K3 and Qwen3.8 remain relevant open-weight examples in [Chapter 4.5](/chapter-4/various-llm-architectures). Keep their hosted and local artifacts distinct: Qwen3.8's local configuration declares 262,144 positions, while extended or hosted context claims require their own scaling and serving evidence. Do not transfer a hosted endpoint's result or limit to a similarly named downloadable checkpoint.

### Announcements: a future weight release is not present access

Mistral Large 4 is an API preview, with weights promised later in October. Beam's announcement invites early-access signup and also promises weights and technical artifacts later in October. Gemini 4 Argon's initial rollout is restricted to trusted cyber defenders. Their launch material can establish provider claims and release plans; it cannot establish completed self-hostable releases. In particular, Argon's announced 1M **output** limit must not be entered as a measured **input-context** value.

## 4. A Benchmark Result Needs a Reproduction Record

Record the following before accepting a public result into an internal comparison:

| Field | Required distinction |
|---|---|
| Task | Dataset, split, version, exclusions, and contamination checks |
| System | Model revision, provider fallback, scaffold, tools, and permissions |
| Budget | Effort, sampling, attempts, token/context limits, timeout, and total cost |
| Grader | Test suite or judge revision, prompt/rubric, and aggregation |
| Evidence | Report date, source URL, uncertainty, and per-case outcomes where available |

Terminal-Bench 2.1, 3.0, and 4.0 are separate evaluations. SWE-bench Verified, Pro, DeepSWE, and private coding suites are also separate. HLE with tools and HLE without tools must not share a series. A GDPval-AA Elo-like rating must not receive a percent sign. A leaderboard's ranking can change when the harness, task mix, or population changes even if the model does not.

## 5. From Public Signal to a Deployment Decision

Start with a Pareto shortlist across quality, task cost, p95 latency, context behavior, deployment control, and safety. Then compare candidate and champion on the same private prompts, tool state, and declared budgets. Measure successful tasks per dollar and per minute, critical-slice failures, and repeated-run reliability. Averages must not hide unauthorized tool effects or severe failures.

For API models, record provider routing and model revisions and detect alias changes. For local models, pin weights, tokenizer, template, quantization scales, kernels, and distributed topology as one artifact bundle. Finish with a canary and a rehearsed switch to the last-known-good system, following [Chapter 17.5](/chapter-17/production-evaluation-and-release-gates).

## Quizzes

<details>
<summary>Quiz 1: Why can a model's index decline after the evaluator changes its suite?</summary>
*The tasks, versions, and weighting changed. Comparing v4.2 and v4.3.2 does not isolate model capability; rerun both systems under one version.*
</details>

<details>
<summary>Quiz 2: Why is a 3:1 blended token price insufficient for choosing an agent model?</summary>
*Agents consume different reasoning lengths, cached prefixes, retries, and tool calls. Measure completed-task cost and latency on the intended workload.*
</details>

<details>
<summary>Quiz 3: Can an announcement calling a model open-weight establish that weights are released?</summary>
*No. Inspect accessible weight files and usable configuration. A promise of a later release remains announced/planned even when an API preview exists.*
</details>

<details>
<summary>Quiz 4: What changes when a benchmark explicitly includes fallback?</summary>
*The measured system includes provider routing and safeguards. Its result cannot be attributed to the named model's weights alone.*
</details>

<details>
<summary>Quiz 5: Why keep a hosted context limit separate from a local checkpoint's configuration?</summary>
*They can use different revisions, position scaling, templates, or serving policies. The local artifact must pass its own long-context correctness and capacity tests.*
</details>
