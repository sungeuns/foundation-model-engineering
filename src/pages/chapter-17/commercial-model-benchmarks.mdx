# 17.6 Commercial and Open-weight Model Benchmarks

Suppose a model is cheaper per token but takes twice as many tool turns to finish your task. Has your system become cheaper? A leaderboard cannot answer that by itself. You need the evaluated configuration, the billing rules and a definition of a successful task.

**As of 2026-11-24.** This static snapshot covers 43 selected profiles, including GLM-5.4, GPT-6.2 Astra/Sol and Gemini 4 Neon/Carbon. It is a checked selection, not a complete release feed. Dates in the table identify a launch, weight-publication milestone or checked artifact revision; they do not all mean first launch. Release evidence and independently measured results are separate records. Reverify the linked sources before a later publication or deployment.

## 1. Know What the Number Measures

The numerical comparison uses **Artificial Analysis Intelligence Index v5.0.1**. Its nine evaluations cover knowledge work, coding, science and general tasks [[1]](#ref-1). The methodology is unchanged from this book's November 15 snapshot. Older v4.3.2 values are a different measurement: subtracting them from v5.0.1 values does not measure model improvement.

Each point represents a model **plus** an effort setting and evaluation system. Fallback, tools, scaffold, token budgets, sampling and grader can all affect the result. These are not equal-compute experiments. An index is not an accuracy percentage, and a context limit is not retrieval accuracy. “Not reported” means that this record has no verified value for the mapped revision and methodology; it never means zero.

**Read the cost column carefully.** AA computes a weighted cost per task using its workload, provider prices and typical cache-hit assumptions. It is not a captured invoice for your deployment. Prices can change without changing the model's score. On this snapshot, AA's Argon and Carbon profiles use \$4/\$20 per million input/output tokens, while Google's official introductory rates are \$2/\$10 through November 30, with \$4/\$20 scheduled from December 1. The table preserves AA's published calculation; the token-price explorer uses the dated provider rates. Do not silently mix them [[2]](#ref-2) [[3]](#ref-3) [[4]](#ref-4).

Several gaps are deliberate. The September DeepSeek entry and Bolt 74B lack a verified current index here. Ling's evaluated 1019 variant is not established as the listed checkpoint. Agnes's public configuration specifies 262,144 tokens, while the hosted AA profile advertises a different context contract; that score is not transferred to the local artifact. GLM-5.4 has no verified matching AA measurement in this snapshot. Wonder Full has an index but no verified public API task cost.

## 3. What the Latest Releases Change

### GLM-5.4: usable service, pending weights

Z.ai's November 23 release makes **GLM-5.4** available through Coding Plan, ZCode and Z.ai Chat. Its standard pay-as-you-go API is still marked coming soon; downloadable weights are planned after further safety work. Coding Plan already has subscription API access, so “no API” would also be wrong. Do not inherit GLM-5.3 Flash's MIT license or translate subscription-credit multipliers into USD token prices [[5]](#ref-5) [[6]](#ref-6) [[7]](#ref-7).

The disclosed design reuses a 28-layer block twice in a 750B-scale model, with gated updates and a combination of shared global KV and local attention. This is a useful example of separating stored parameters from executed computation; [Section 4.5](/chapter-4/various-llm-architectures) works through that distinction. Exact total/active counts, the full training mixture and the eventual weight license remain undisclosed. Its 30B architecture ablation is not a controlled evaluation of the full deployed model [[5]](#ref-5).

### GPT-6.2 Astra and Sol: measure the operating point

OpenAI released **GPT-6.2 Astra and Sol** on November 17. Both are hosted text/image-to-text models; public weights and architectural details are not supplied. The API separates a 1,050,000-token context window, 922,000 maximum input tokens and 128,000 maximum output tokens. Tool calling uses Responses, and reasoning effort `none` is rejected. Those contracts matter when migrating an existing agent [[8]](#ref-8) [[9]](#ref-9) [[10]](#ref-10).

The chart's Max-effort profiles do not tell you the best effort for a latency-sensitive application. Compare at the effort and service tier you intend to operate. The cost example below shows why even a correctly copied base token price is insufficient.

### Gemini 4: shared context and dated prices

**Gemini 4 Neon** reached general availability on November 18; **Carbon** reached API general availability on November 10. Neon's 1,048,576-token budget is shared by input and output. Its default synchronous output cap is 65,536 tokens; a background long-decode path can use more of the shared budget. “One million input plus one million output” is therefore an incorrect interpretation. Neon supports implicit caching rather than an explicit-cache API; do not assume identical cache controls across a family [[11]](#ref-11) [[12]](#ref-12).

**Hydrogen** adds another operating point, including a role in provider-tested multi-model systems. An orchestration result measures the coordinator, workers and execution policy together, not the isolated causal contribution of one model [[13]](#ref-13).

### Public weights do not settle serving equivalence

**Qwen4-Max** is API-only in the checked sources. Its November 16 general release is distinct from its earlier preview. The protocol distinguishes readable reasoning summaries from encrypted reasoning history required by later tool turns; a summary is not a substitute for that history [[14]](#ref-14) [[15]](#ref-15).

**LongCat-2.5, Agnes 2.5 Pro Theta and Inkling 2 Mini** broaden the public-weight options in the table. Downloadability permits inspection, but a local run still depends on the exact template, quantization, runtime, memory and license. Pin these artifacts before comparing them with a hosted profile. The same applies to Kimi K3.1 Pro and Mistral Large 4: public weights do not establish hosted/local equivalence, and Mistral's custom license includes conditions for Model-as-a-Service businesses [[16]](#ref-16) [[17]](#ref-17) [[18]](#ref-18).

Text-agent indices also cannot rank the new speech, image or interactive-world systems. See [speech integration](/chapter-11/audio-and-speech-integration), [image generation](/chapter-11/image-diffusion-models) and [video/world models](/chapter-11/commercial-video-models) for their distinct interfaces and evaluation limits.

## 4. A Worked Cost Example: Crossing 272K Input Tokens

**Rates checked 2026-11-24.** At Standard short-context rates, GPT-6.2 Astra costs \$8 input/\$40 output per million tokens; Sol costs \$2/\$10. Above **272,000 input tokens**, the input rate doubles and the output rate becomes 1.5 times the base rate **for the whole request** [[9]](#ref-9) [[10]](#ref-10).

Imagine a repository review with 300,000 uncached input tokens and 10,000 billed output tokens. Using Sol's base rates gives \$0.70. Applying the long-context rule gives **\$1.35**. Astra's corresponding amount is **\$5.40**. Reducing the input can affect both token count and the applicable rate; whether it preserves quality needs a separate evaluation.

**Scope of this example:** executable Python standard-library arithmetic for one uncached, Standard-tier text request. `billed_output_tokens` must include billed reasoning tokens, not just visible text. This is not a billing engine: it excludes caching, images, tools, other processing tiers and taxes. Use actual usage records for a real workload.

```python
from decimal import Decimal as D

RATES = {
    "gpt-6.2-astra": (D("8"), D("40")),
    "gpt-6.2-sol": (D("2"), D("10")),
}

def text_request_usd(model, input_tokens, billed_output_tokens):
    if any(type(n) is not int or n < 0
           for n in (input_tokens, billed_output_tokens)):
        raise ValueError("Token counts must be nonnegative integers")
    if input_tokens > 922_000 or billed_output_tokens > 128_000:
        raise ValueError("Exceeds this example's documented model limits")
    pin, pout = RATES[model]
    if input_tokens > 272_000:
        pin *= 2
        pout *= D("1.5")
    return (input_tokens * pin + billed_output_tokens * pout) / D("1000000")

assert text_request_usd("gpt-6.2-sol", 300_000, 10_000) == D("1.35")
assert text_request_usd("gpt-6.2-astra", 300_000, 10_000) == D("5.40")
print(text_request_usd("gpt-6.2-sol", 300_000, 10_000))  # 1.35
```

For an agent, sum every request, including failed attempts and retries. Then divide by the number of successfully completed tasks. A lower price per request can still produce a higher cost per successful task.

## 6. Turn a Shortlist into a Release Decision

Use the quality/cost/latency/context/openness/safety Pareto surface to choose candidates. Evaluate the same private tasks with pinned tools, permissions, scaffold, effort, retries, limits and grader. Report paired uncertainty, language/domain slices, base-capability retention, format/tool correctness, safety, tail latency, error rate and cost per successful workflow. A critical slice failure blocks release even if the mean improves.

Keep weights or API revision, tokenizer/template, quantization, runtime, generation configuration, tool schema and safety policy in one immutable artifact bundle. Evaluate hosted and local versions separately. Canary with bounded permissions, retain a known-good route and rehearse rollback of cached state and pending effects. Typed decision models need separate calibration and selective-risk evaluation; see [Section 16.7](/chapter-16/decision-models-and-selective-prediction).

## Quizzes

<details>
<summary>Quiz 1: Can an unchanged model have different v4.3.2 and v5.0.1 scores?</summary>
*Yes. The tasks and aggregation define the measurement. Their difference is not a controlled estimate of improvement or regression. This November 24 snapshot uses v5.0.1 throughout.*
</details>

<details>
<summary>Quiz 2: Why is GLM-5.4 neither “fully open-weight” nor “unavailable” here?</summary>
*Its hosted subscription services are usable, including subscription API access, but standard pay-as-you-go access and weight publication are separate pending milestones. A license from an earlier model cannot establish the eventual weight license.*
</details>

<details>
<summary>Quiz 3: Why not copy an AA score onto every checkpoint with a similar name?</summary>
*Model revision, context contract, safeguards and serving configuration identify the evaluated system. The Ling and Agnes gaps illustrate why a family-name match alone is insufficient.*
</details>

<details>
<summary>Quiz 4: Why can the Google token-price axis and AA task-cost column use different rates?</summary>
*The provider has a dated introductory rate, while the captured evaluator profile uses another stated rate. Preserve both source conventions and explain the mismatch instead of claiming either is the reader's invoice.*
</details>

<details>
<summary>Quiz 5: Why does the 300K-input Sol example cost \$1.35 rather than \$0.70?</summary>
*Crossing 272K input tokens applies doubled input and 1.5-times output rates to the whole request: 0.3 × \$4 + 0.01 × \$15 = \$1.35. The output count includes billed reasoning tokens.*
</details>

<details>
<summary>Quiz 6: Does Neon's 1,048,576-token context permit that much input plus the same amount of output?</summary>
*No. It is a shared budget, with additional output-mode limits. Check the remaining budget and the chosen execution mode; advertised context size is also not a guarantee of retrieval quality.*
</details>
