# 11.3 Unified Multimodal (Any-to-Any)

A model that reads images is not necessarily a model that generates them. A system that understands speech may still answer only in text. **Any-to-any** is therefore a capability matrix to test, not an architectural conclusion to draw from the word “native.”

The engineering problem is to coordinate representations, temporal alignment, objectives, and output paths across modalities. A jointly trained system can still have specialized encoders, codecs, projectors, and generation modules.

## 1. Shared Representations Do Not Eliminate Modality Interfaces

Let a modality encoder produce $f_m\in\mathbb R^{B\times S_m\times d_m}$ for modality $m$. A projection $P_m$ maps width $d_m$ to shared width $D$, producing $z_m\in\mathbb R^{B\times S_m\times D}$. $B$ is batch size and $S_m$ the modality's representation length. Compatible width permits joint processing; it does not require increasing the backbone's hidden dimension or using the same tokenizer for every modality.

Image patch positions, audio timing, video frames, and text order must remain recoverable after projection. Concatenating tensors can illustrate shapes, but it does not implement timestamp alignment, interleaving, padding masks, or cross-modal training. The projection layer alone is not a complete multimodal model.

## 2. A Disclosed Example: Qwen2.5-Omni

The 2025 Qwen2.5-Omni report describes text, image, audio, and video input with streaming text and speech output. Its **Thinker–Talker** design separates text generation from an autoregressive audio-token path, and uses time-aligned positional encoding and a streaming audio decoder [[1]](#ref-1).

This is a useful counterexample to the claim that native integration means one undifferentiated output head. The report discloses a coordinated system with specialized components. Its demonstrated output modes do not establish unrestricted image or video generation, and its mechanisms must not be assigned to another provider's undisclosed model.

## 3. October Update: Three Different Output Contracts

**As of 2026-10-13.** Keep modality support separate from a generative model's marketing category.

| Example | Input contract | Output contract | Evidence boundary |
|---|---|---|---|
| Qwen2.5-Omni, historical technical example | Text, image, audio, video | Text and speech | Published Thinker–Talker system; not arbitrary output modalities [[1]](#ref-1) |
| DeepSeek V4.1 Flash, released/open-weight | Native image and text | Autoregressive text | Its card does not establish speech/video generation [[2]](#ref-2) |
| EmbeddingGemma 2, October release | Shared multimodal representations | Embedding vectors | Retrieval representation is different from generated media [[3]](#ref-3) |

A matrix should also include combinations, streaming, timestamps, supported input lengths, and the exact API or local artifact. “Supports audio” can mean recognition, speech generation, audio embeddings, or several of these. Test each intended path and preserve missing capabilities as not reported.

## 4. Temporal and Serving Contracts

For live audio/video, measure end-to-end time to usable output, chunk boundaries, synchronization drift, buffering, cancellation, and interruption recovery. Audio processing time is not speech-response latency. Frame sampling can miss a short event; apparent alignment can still lose causally important order.

Budget modality encoders, representation expansion, backbone prefill/decode, codecs or diffusion decoders where actually disclosed, memory transfer, and tool orchestration separately. A short text request with a long recording may have a large representation and processing cost. Shared context does not make all modalities equally cheap.

Cache identities must include preprocessing, encoder/tokenizer revisions, sampling rate or frame policy, positional alignment, dtype/scales, and model revision. Reusing a prefix after changing audio chunking or image resizing can restore incompatible state. Validate cold and restored execution as well as throughput.

## 5. Training, Evaluation, and Release

Pin input checkpoints, each tokenizer/encoder/codec, native chat template, modality objectives and weights, dataset manifests, licenses/consent, PII/secrets handling, sample IDs and shard hashes. Cluster related recordings, clips, documents, conversations, and synthetic variants before splitting; quarantine evaluation assets and semantic neighbors.

Specify learning rate, modality mixture, sequence/representation lengths, precision, sharding, recomputation, response caps, and reference identity or explicit absence. For text/tool SFT, verify BOS/EOS, `add_generation_prompt`, truncation, padding, assistant-span masks and packed-sample attention isolation. Audio/video targets require their own valid-frame/token masks and aligned conditioning; do not treat an input recording as an assistant text completion.

Separate parameters, gradients, optimizer states, activations, temporary buffers, collectives, checkpoints and evaluation resources. Observe token/frame-normalized training and validation losses, domain and modality slices, alignment drift, nonfinite/overflow, gradient/activation norms, throughput, MFU, data wait, collectives/stragglers and reconstructable batch IDs. Predeclare pause/abort bounds for numerical failures, drift, retention, unsafe outputs, and cost/latency regressions, with an owner and observation window.

Checkpoint sharded model/optimizer, scheduler, scaler/FP8 state, step and exposure counts, RNG, sampler and exact data cursor, all component/config/data hashes. Publish atomically with checksums and a completion marker; define retention, remote replication, world-size limits, restore drills and continuation checks. Release one immutable component/template/tool/safety bundle only after domain, base-retention, safety, format/tool, latency, cost and error gates pass with paired uncertainty or justified sample sizes. Rehearse rollback for partial media streams and session state.

## 6. Practical Takeaway

The useful question is which modalities a specific artifact can consume and produce under the intended timing and quality constraints. Joint training can improve coordination while specialized modules remain. Validate the whole path and label undisclosed architecture, data mixtures, and training details as **undisclosed**.

## Quizzes

<details>
<summary>Quiz 1: Does native image input establish image generation?</summary>
*No. Input encoders and output generation paths have different contracts. Verify the exact input/output matrix.*
</details>

<details>
<summary>Quiz 2: Why is projecting all modalities to width D insufficient?</summary>
*Compatible tensor width does not implement timestamp alignment, positional encoding, masking, objectives, or output decoders.*
</details>

<details>
<summary>Quiz 3: What does Thinker–Talker teach about native integration?</summary>
*A jointly trained system can retain specialized text and audio generation modules. Native does not mean one encoder, tokenizer, or output head.*
</details>

<details>
<summary>Quiz 4: Why include preprocessing in cache and artifact identity?</summary>
*Resizing, frame selection, sample rate, and chunking change representations and alignment. Identical backbone weights do not make those states interchangeable.*
</details>
