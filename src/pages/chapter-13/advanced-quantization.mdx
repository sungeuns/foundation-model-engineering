# 13.5 Advanced Quantization: TurboQuant and Extreme Compression

A “2-bit model” can describe quantized pretrained weights, quantization-aware training, or an architecture trained with low-precision linear layers. A “2-bit cache” describes a different object again. Before comparing compression claims, identify **which tensors**, metadata, kernels, and error metric the bit count covers.

## 1. Separate Three Compression Problems

| Object | Main question | Validation target |
|---|---|---|
| Stored weights | Can the runtime load and multiply the packed representation? | Capability and measured device memory |
| KV or recurrent state | What distortion accumulates over long generation? | Attention behavior, long-context quality, and state size |
| Training representation | Does low-precision training preserve useful optimization? | Learning curves, retained capabilities, and exported-runtime parity |

Outliers can make quantization difficult, but they are not a universal four-bit floor. Distribution, group size, clipping, calibration, reconstruction, training, and kernel layout all affect the operating point.

## 2. Rotation and TurboQuant

For an orthogonal matrix $R$ with $R^TR=I$, vectors $q$ and $k$ satisfy

$$
(Rq)^T(Rk)=q^Tk.
$$

This preserves the exact inner product **before quantization**. Rotation can distribute a large coordinate across dimensions; subsequent rounding still introduces error. A small Hadamard example is not the complete TurboQuant algorithm and does not guarantee an easier quantization distribution for every vector.

TurboQuant studies online vector quantization for mean-squared and inner-product distortion. Its method combines rotation-based scalar quantization with a residual correction for inner products [[1]](#ref-1). Its reported KV results concern the tested models and tasks; they do not establish universally lossless low-bit serving.

For an engineering experiment, compare attention-logit distortion and end-task errors at matched total bits, including norms, scales, residual metadata, and padding. Include long generations and out-of-distribution activation slices. A low average reconstruction error can hide a rare but consequential attention error.

## 3. Ternary Training Is Not an Entire Addition-Only Transformer

BitNet b1.58 investigates ternary weights $w_i\in\{-1,0,1\}$ in its linear-layer training design [[2]](#ref-2). For a dot product,

$$
\sum_i w_i x_i=\sum_{i:w_i=1}x_i-\sum_{i:w_i=-1}x_i,
$$

where $x_i$ is an input coordinate. This identity permits specialized linear kernels. It does not remove normalization, scaling, attention, softmax, or all multiplications from the complete model. The ideal alphabet rate $\log_2 3\approx1.585$ bits per ternary value is not the physical size of an arbitrary exported checkpoint.

Do not post-quantize a conventional checkpoint to three values and assume it reproduces a model trained for ternary arithmetic. Kernel availability and memory traffic determine whether the representation becomes faster on the target hardware.

## 4. October Case: Bolt's Native Two-Bit Release

**As of 2026-10-18**, NVIDIA's Nemotron 3.5 Bolt 74B-A9B 24GB card describes IQ2 quantization-aware training for a hybrid Mamba-2/Transformer LatentMoE vision-language model [[3]](#ref-3). This is a concrete low-bit release, not evidence that any 74B checkpoint can be compressed into the same operating point. The card's packed-model target does not reserve arbitrary KV, recurrent state, batch, or vision-processing memory.

For perspective, a hypothetical uniformly two-bit array of 74 billion scalars occupies $74\times10^9\times2/8=18.5\times10^9$ bytes. That **18.5 GB** ideal payload excludes higher-precision tensors, scale/packing overhead, state, workspace, and fragmentation. It is not a 24 GB deployment guarantee. Measure peak allocation at the intended context and concurrency using the compatible runtime and kernels.

## 5. Reproducible Quantization and Training Contract

An experiment must pin base/model revision, tokenizer/template, calibration or training-data manifest, tensor grouping, clipping/scales, precision exceptions, and runtime/container. State whether the objective minimizes reconstruction, logit distortion, or task loss. Predeclare bit width, group size, calibration length, sequence policy, and—if training—learning rate, token batch, accumulation, schedule, and seeds.

State precision, sharding, recomputation, sequence length, and active-expert assumptions. For QAT, separate weights, gradients, optimizer/master states, activations, temporary buffers, collectives, checkpoints, and evaluation overhead. Preserve prompt/completion masks and template parity when adapting on chat data. Track token-normalized train/validation loss, domain slices, saturation, nonfinite/overflow counts, gradient/activation norms, throughput, MFU, data wait, stragglers, and reconstructable batch IDs.

Checkpoint model/optimizer shards, scheduler, scaler/low-precision state, steps/tokens, RNG, sampler and exact data cursor, and dataset/tokenizer/config hashes. Publish atomically with checksums; test restoration and exported-runtime equivalence. Specify retention, remote replication, supported world-size changes, and continuation-equivalence checks. Assign an owner and observation window to abort and rollback gates. Abort on persistent nonfinite values, critical slice loss, or unexplained quantizer/runtime mismatch.

Release only after domain quality, base retention, safety, tool/format validity, latency, cost, error rate, and peak memory pass paired or sample-size-justified gates. Keep the prior model/runtime bundle and rehearse rollback. Compression earns deployment value through a measured system improvement, not the bit count alone.

## Quizzes

<details>
<summary>Quiz 1: Why compare total bits rather than nominal bit width?</summary>
*Scales, norms, residual corrections, padding, and higher-precision tensors consume storage. Ignoring them can reverse an apparent compression advantage.*
</details>

<details>
<summary>Quiz 2: Does orthogonal rotation guarantee exact quantized attention scores?</summary>
*No. It preserves exact pre-quantization inner products; rounding and approximation still introduce error that must be measured.*
</details>

<details>
<summary>Quiz 3: Why is a ternary linear layer not an addition-only Transformer?</summary>
*The dot-product identity applies to those weights. Other layers, attention operations, normalization, and scaling retain their own arithmetic.*
</details>

<details>
<summary>Quiz 4: Why is an ideal 18.5 GB weight payload insufficient for a 24 GB capacity claim?</summary>
*The running system also needs precision exceptions, metadata, KV/recurrent state, vision processing, workspace, and allocator headroom. Context and concurrency change the peak.*
</details>

<details>
<summary>Quiz 5: Why test the exported runtime after successful QAT?</summary>
*Training-time fake or native quantization may differ from packed serving kernels. A model can pass offline training evaluation and fail after export.*
</details>
