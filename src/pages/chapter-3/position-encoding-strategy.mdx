# 3.3 Position Encoding Strategy

Use the same three tokens in two orders, `dogs chase cats` and `cats chase dogs`. In an encoder with full self-attention, no positional inputs and no mask, swapping *dogs* and *cats* swaps their output vectors. The middle word *chase* gets exactly the same output in both sentences. That is a problem if the task is to decide who is doing the chasing.

## Where does order enter?

An RNN changes state after each word, so the second word already sees the first. A convolution assigns separate weights to the left, middle and right positions of its filter. Unmasked self-attention uses the same query, key and value projections at every position. Reordering the rows reorders the pairwise scores and values together. This property is called **permutation equivariance**. A causal mask changes the argument because the set of earlier tokens that each position can read depends on its index.

The original Transformer added a position vector to each token embedding before the first encoder or decoder layer. Put *dogs* at position 0 in one sentence and at position 2 in another, and its input vector changes even though its token embedding stays the same. [[1]](#ref-1)

<a id="the-mathematics-of-sinusoidal-positional-encoding"></a>
<a id="why-sinusoidal"></a>
## One clock per dimension pair

Let $p$ be a zero-based position and $d$ the embedding width. Each pair index $i$ supplies two coordinates, $2i$ and $2i+1$, with the same angular frequency $\omega_i$ in radians per position. For even $d$, the pairs run from $i=0$ through $d/2-1$. [[1]](#ref-1)

$$
\omega_i=10000^{-2i/d},\qquad
PE_{p,2i}=\sin(p\omega_i),\qquad
PE_{p,2i+1}=\cos(p\omega_i).
$$

At position zero, every complete pair is $(0,1)$. Move one position to the right with $d=32$. Pair 0 turns by one radian and becomes approximately $(0.841471,0.540302)$. Pair 8, in dimensions 16 and 17, turns by only $0.01$ radians and becomes $(0.010000,0.999950)$. A single shift changes the fast pair visibly while the slow pair hardly moves.

## Moving a fixed number of positions

Can we compute a pair at position $p+k$ from the same pair at $p$? The sine and cosine addition formulas give the following matrix for an offset $k$.

$$
\begin{bmatrix}
\sin((p+k)\omega_i)\\ \cos((p+k)\omega_i)
\end{bmatrix}
=
\begin{bmatrix}
\cos(k\omega_i) & \sin(k\omega_i)\\
-\sin(k\omega_i) & \cos(k\omega_i)
\end{bmatrix}
\begin{bmatrix}
\sin(p\omega_i)\\ \cos(p\omega_i)
\end{bmatrix}.
$$

Once $k$ and the frequency pair are chosen, the matrix stays the same for every starting position. This was one reason the Transformer authors tried sine and cosine features. Their translation experiments found similar results for learned and sinusoidal position embeddings. The formula alone cannot predict how well a trained model will use a longer context. [[1]](#ref-1)

## Where four approaches change the computation

| Method | What changes in the model? | What happens at a new position or distance? |
| --- | --- | --- |
| Absolute position | Add a learned table row or a fixed sinusoidal vector to the token embedding. | A learned table needs a row for the index. A sinusoid is defined at any index, though an implementation can cache only a finite table. [[1]](#ref-1) |
| Relative representations | Add learned representations of token displacement to the key and optionally the value. | In Shaw et al., offsets outside the clipping distance share their outermost learned representation. [[3]](#ref-3) |
| Rotary position embedding (RoPE) | Rotate projected query and key pairs before taking their dot product. | Their relative rotation depends on the signed offset. [[2]](#ref-2) |
| Attention with Linear Biases (ALiBi) | Apply a head-specific distance penalty to the attention score. | The causal distance penalty continues linearly over longer ranges. The final weight also depends on token content. [[4]](#ref-4) |

## What a rotary attention score measures

Consider one query pair $q$ at position $m$ and one key pair $k$ at position $n$. Write $R_t$ for a rotation by $t\theta$, where $\theta$ is this pair's angular frequency. RoPE rotates both vectors. The two rotations combine inside the dot product. [[2]](#ref-2)

$$
(R_m q)^\top(R_n k)=q^\top R_m^\top R_n k=q^\top R_{n-m} k .
$$

Move the query and key together from positions $(2,5)$ to $(9,12)$ while holding their content vectors fixed. Both scores now use $R_3$, so they are equal. Change the key vector and the scores can differ even at the same separation. In a longer deployment, test retrieval or answer quality at the target length and at several evidence positions before extending the serving limit.

## PyTorch Implementation

This CPU example adds a cached position table to floating-point embeddings shaped $[B,S,d]$ for batch size $B$, sequence length $S$ and width $d$. The first token in every row has position 0. For an odd width, the example keeps the final unpaired sine coordinate. The relative-shift identity above applies to complete pairs. Batched decoding with different cache offsets would need explicit per-request positions.

```python
import math
import torch
from torch import nn

class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=5000):
        super().__init__()
        if d_model < 1 or max_len < 1:
            raise ValueError("d_model and max_len must be positive")
        position = torch.arange(max_len, dtype=torch.float32)[:, None]
        even = torch.arange(0, d_model, 2, dtype=torch.float32)
        angle = position * torch.exp(-math.log(10000.0) * even / d_model)
        table = torch.zeros(max_len, d_model)
        table[:, 0::2] = angle.sin()
        # An odd width has one fewer cosine column.
        table[:, 1::2] = angle[:, :d_model // 2].cos()
        self.register_buffer("pe", table.unsqueeze(0))

    def forward(self, x):
        if x.ndim != 3 or x.size(2) != self.pe.size(2):
            raise ValueError("expected [batch, positions, d_model]")
        if x.size(1) > self.pe.size(1):
            raise ValueError("sequence exceeds max_len")
        return x + self.pe[:, :x.size(1)].to(dtype=x.dtype)

encoder = PositionalEncoding(32, max_len=20)
y = encoder(torch.zeros(2, 20, 32))
torch.testing.assert_close(y[0, 1, :2], torch.tensor([0.841471, 0.540302]))
torch.testing.assert_close(y[0, 1, 16:18], torch.tensor([0.00999983, 0.999950]))
odd = PositionalEncoding(3, max_len=2)(torch.zeros(1, 2, 3))
torch.testing.assert_close(odd[0, 0], torch.tensor([0., 1., 0.]))
```

The checks reproduce the two pairs from the diagram and exercise an odd-width input. Try increasing $S$ above 20 with this instance. The formula still exists, but this module's saved table has no row for the next token.

## Quizzes

<details>
<summary>Quiz 1: Why does the output for chase stay the same when the two nouns swap in the opening example?</summary>
*The middle query is unchanged. The keys and values swap together, so the same values receive the same weights in the weighted sum. A position-dependent input or mask can change that result.*
</details>

<details>
<summary>Quiz 2: At position zero, what values do dimensions 30 and 31 have?</summary>
*They form pair 15. Its angle is zero regardless of frequency, giving sin(0) = 0 and cos(0) = 1.*
</details>

<details>
<summary>Quiz 3: Why does a one-position move change dimensions 16 and 17 less than dimensions 0 and 1 in the example?</summary>
*Pair 8 turns through 0.01 radians per position, while pair 0 turns through 1 radian per position. Both pairs use unit-amplitude waves.*
</details>

<details>
<summary>Quiz 4: Why could a position fail in the CPU example even though the sinusoid is mathematically defined there?</summary>
*The module precomputes a finite table. Registering it as a buffer saves it with the module and moves it with the module, but it does not extend the table.*
</details>

<details>
<summary>Quiz 5: If a query and key stay three tokens apart, when does RoPE preserve their dot product?</summary>
*For the same frequency schedule and unchanged pre-rotation query and key vectors, the relative rotation is unchanged. New content or a change in earlier hidden states can change the score.*
</details>
