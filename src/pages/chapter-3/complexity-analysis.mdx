# 3.5 Complexity Analysis

Complexity is a budget model, not a latency benchmark. Distinguish the attention kernel from the complete layer, and parallel processing of known tokens from generation of unknown tokens. Those distinctions explain why a model can prefill a prompt efficiently yet decode slowly.

## Count the operation being compared

Let $n$ be sequence length, $d$ the hidden width, and $k$ a convolution's kernel width. Ignore constant factors and batch size initially. The original Transformer comparison describes an attention core operating on already-projected queries, keys and values. [[1]](#ref-1)

| Operation | Leading arithmetic | Sequential dependency across known tokens |
|---|---|---|
| Attention core $QK^T$ and $AV$ | $O(n^2d)$ | All queries can be processed in parallel |
| Q/K/V/output projections | $O(nd^2)$ | Parallel over tokens |
| Dense recurrent layer | $O(nd^2)$ | $n$ recurrent steps |
| Width-$k$ dense convolution | $O(knd^2)$ | Parallel within a layer |

An attention layer therefore costs $O(n^2d+nd^2)$; an FFN adds another width-dependent $O(nd^2)$ term. The slogan “attention is cheaper when $n<d$” compares only the core to a dense recurrent layer. Constants, kernels and memory traffic decide actual latency.

## Derive the attention terms

For one head, $Q,K,V$ have shape $[n,d]$. Forming $QK^T$ computes $n^2$ dot products of width $d$, and multiplying the $[n,n]$ probability matrix by $V$ has the same leading cost. Softmax adds $O(n^2)$ work. Projecting an input $[n,d]$ through a $[d,d]$ matrix instead costs $O(nd^2)$.

One attention layer directly connects visible query–key positions; causal masking limits visibility to the past. An ordinary RNN passes a signal through recurrent steps. A convolution needs enough depth to cover the desired distance: logarithmic depth assumes a suitable dilation schedule, not arbitrary fixed-width convolutions.

## Parallel prefill is different from autoregressive decode

During teacher-forced training or prefill, all input tokens are known. Their queries can be evaluated together. This is the meaning of the comparison table's constant number of sequence-level sequential stages; it does not mean constant elapsed time on finite hardware.

During autoregressive decoding, the next token depends on the sampled previous token. With a KV cache, one new query attends to $n$ stored keys, costing $O(nd)$ for the attention core plus projections and FFN work. Generating many tokens still requires sequential decoding steps. Vanilla nonlinear RNNs have a recurrent dependency during both modes; specialized state-space scans are a separate case discussed in Chapter 20.

## Materialized attention memory

A naive score tensor of shape $[B,H,n,n]$ consumes $BHn^2s$ bytes, where $B$ is batch size, $H$ is head count and $s$ is bytes per score. This is one tensor, not total training memory. Tiled exact attention can avoid storing the complete quadratic score matrix in device memory without removing quadratic dense-attention arithmetic; Chapter 7 explains FlashAttention. [[2]](#ref-2)

> **Educational payload estimate.** No tensor is allocated. This excludes weights, gradients, optimizer state, activations other than scores, temporary buffers, collectives, checkpoints and evaluation overhead.

```python
def score_memory_mib(n, batch=1, heads=8, bytes_per_score=4):
    if min(n, batch, heads, bytes_per_score) < 1:
        raise ValueError("positive dimensions required")
    return batch * heads * n * n * bytes_per_score / 2**20

for n in [1000, 5000, 10000, 50000]:
    print(f"n={n:,}: {score_memory_mib(n):,.2f} MiB")
```

## The next design questions

Linear attention targets sequence-linear arithmetic at fixed feature dimension. Reformer’s LSH attention instead targets $O(n\log n)$; these methods should not all be called linear. Approximation quality, memory and hardware efficiency must be evaluated together. Chapter 20 develops these trade-offs. [[3]](#ref-3)

## Quizzes

<details>
<summary>Quiz 1: Why does $n<d$ not prove a full Transformer layer is faster than an RNN?</summary>
*The comparison omits projections and FFN work, and arithmetic scaling omits hardware, kernels and memory traffic.*
</details>

<details>
<summary>Quiz 2: Does FlashAttention make dense attention arithmetic linear in sequence length?</summary>
*No. It avoids materializing the full score matrix through tiling and recomputation, while dense pairwise attention still has quadratic arithmetic.*
</details>

<details>
<summary>Quiz 3: Why can training process known tokens in parallel while decoding cannot generate all tokens at once?</summary>
*Teacher forcing supplies the full sequence; decoding must obtain a token before conditioning on it in the next generation step.*
</details>

<details>
<summary>Quiz 4: What would double when doubling sequence length, and what would quadruple?</summary>
*At fixed width and batch, the RNN arithmetic term doubles, while naive attention-score storage and dense attention-core arithmetic quadruple. This does not predict whole-system latency.*
</details>
