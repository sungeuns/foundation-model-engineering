# 4.3 Encoder-Decoder (T5/BART)

An editor wants to shorten the caption `a red fox` to `red fox`. When the model produces its first word, can it already read `fox`? Yes, on the **source** side. On the **target** side, it has only the start token. An encoder-decoder Transformer keeps these two sequences separate. The encoder reads the source once. At each output step, the decoder reads the target prefix and uses **cross-attention** to consult the encoder's representations. [[4]](#ref-4)

## Reading the source while writing the target

Treat each word as one token for this example. The batch has four source slots, `a red fox PAD`. During training, the two decoder inputs are `START red` and their labels are `red fox`. `START` stands for the model's decoder-start token. We stop after the second word. An end-of-sequence prediction would need one more row.

The original Transformer applies self-attention and then a feed-forward network within **each encoder block**. Within **each decoder block**, it applies causal self-attention, cross-attention to the final encoder states, then a feed-forward network. The tables show which keys a query can read at each kind of attention. [[4]](#ref-4)

<EncoderDecoderMasks lang="en" />

Read the `START` row twice. Its decoder self-attention can see only `START`, so it cannot copy the target label `red`. Its cross-attention can read all three source words, including the source word `red`. The source caption will also be present at inference. The next decoder row can read both `START` and the supplied target word `red` to predict `fox`. At inference the decoder feeds back its generated word. For the one-sequence versions of these rules, see [the encoder mask in §4.1](/chapter-4/encoder-only/#mlm-target-example) and [the shifted labels in §4.2](/chapter-4/decoder-only/#shifted-target-example).

<a id="core-mechanism-cross-attention"></a>

## Why the cross-attention scores have two rows and four columns

In one decoder block, take queries $Q$ from its target states after causal self-attention. Project keys $K$ and values $V$ from the final encoder states. For one head of key dimension $d_k$, the rows of the result are weighted sums of source values. [[4]](#ref-4)

$$
A=\operatorname{softmax}_{\text{source}}\!\left(QK^{\mathsf T}/\sqrt{d_k}+M\right),\qquad O=AV.
$$

Here $M$ adds zero to a valid source score and $-\infty$ to a padding score. For $T$ target input positions and $S$ padded source slots, both $A$ and the broadcast mask have effective shape $T\times S$ per head. In the example $T=2$, $S=4$. Each row sums to one over the three valid source slots. Two rows with the same visibility can assign very different weights.

<a id="pytorch-implementation-cross-attention"></a>

## Test the padding mask by changing one value

The CPU example below starts at the projected queries, keys and values. It uses one batch item, one head, one feature and at least one valid source key. It omits learned projections, residual connections, dropout, batching across examples and the training loop. PyTorch's scaled dot-product attention accepts a Boolean mask in which `True` allows a key. A single source-mask row broadcasts over both decoder queries. [[5]](#ref-5)

<CrossAttentionExample lang="en" />

Run `python cross_attention.py`. The first query is zero, so its three valid keys have equal weight and return $(3+6+12)/3=7$. For the second query the three unnormalized weights are $1,2,4$, so it returns $(3+12+48)/7=9$. Changing the padding value from 90 to 900 leaves both outputs unchanged. Raising the source value for `fox` by 21 adds 7 to the first output and 12 to the second. A triangular cross-attention mask would incorrectly hide `fox` from the first query and fail this test.

## What should the decoder reconstruct in T5 and BART?

Take the sentence `the red fox crossed the bridge` and hide `red fox`. Both models can put the damaged sentence in the encoder. Write down the target labels before choosing your loss. These are illustrative word-level strings, with tokenizer-specific start and end IDs omitted.

| Training objective | Encoder input | Decoder target |
| --- | --- | --- |
| T5 span corruption | `the <X> crossed the bridge` | `<X> red fox <Y>` |
| BART text infilling | `the <mask> crossed the bridge` | `the red fox crossed the bridge` |

In the T5 paper's example format, each missing span gets a distinct **sentinel**, and a final sentinel closes the target. The decoder predicts the missing spans and their delimiters. The same text-to-text interface can later emit a class label such as `positive`. Raffel et al. used the C4 corpus for pre-training. [[1]](#ref-1)

BART reconstructs the entire original sequence, including unchanged words. Lewis et al. tested several ways to damage a document. Their large model combined span infilling with sentence permutation. If a data pipeline gives both models the full original sentence as labels, it has silently changed the T5 objective. [[2]](#ref-2)

<a id="a-recent-counterexample-causal-encoder-decoder"></a>

## A causal encoder changes the visibility rule

**Research snapshot as of 2026-11-25.** DeepSeek's V4.1-Flash report describes a causal encoder-decoder (CED). For global attention, the lower half of the stack is a causal encoder. Upper layers derive global cache entries from the midpoint states through layer-specific projections. The report distinguishes work during prompt prefill and token decoding. A later prompt token therefore cannot change an earlier causal encoder state. In the T5/BART-style source encoder above, an earlier source word *can* read a later one. The distinction matters when deciding which representations can be reused as a prompt grows. [[3]](#ref-3) [Chapter 4.5](/chapter-4/various-llm-architectures)

## Quizzes

<details>
<summary>Quiz 1: Why can the first target row read the source word “red” while predicting the target word “red”?</summary>
*The source is available at inference. On the target side, only the start token is visible in that row. Feeding the target label itself into the first decoder row would leak the answer.*
</details>

<details>
<summary>Quiz 2: Why does a batch with two target inputs and four source slots need a rectangular cross-attention mask?</summary>
*Each query belongs to a target input and each key belongs to a source slot. Both target queries may read all three real source words. A target-side triangular mask would wrongly hide later source words.*
</details>

<details>
<summary>Quiz 3: A padding-value change leaves the output unchanged. Why also change a real source value?</summary>
*A broken computation that ignores every source value could also pass the padding test. In this fixture changing the final real value shifts both outputs by known, different amounts.*
</details>

<details>
<summary>Quiz 4: After hiding “red fox,” which model has a training label for the unchanged word “crossed”?</summary>
*BART reconstructs the full original sentence. The T5 span-corruption target contains only the hidden span and its sentinel delimiters.*
</details>

<details>
<summary>Quiz 5: Can the first source state from a T5-style encoder be reused unchanged after extending its source?</summary>
*It can attend to the new source token, so extending the source can change that state. A strictly causal encoder keeps its earlier positions independent of appended tokens.*
</details>
