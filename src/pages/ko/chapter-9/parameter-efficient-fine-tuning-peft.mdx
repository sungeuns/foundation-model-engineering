# 9.3 매개변수 효율적 미세 조정(PEFT)

입력 폭이 4,096이고 출력 폭이 1,024인 트랜스포머 투영에는 가중치가 4,194,304개 있습니다. 이 가중치를 고정하고도 랭크 16에서 값 81,920개만 학습해 투영을 바꿀 수 있습니다. 그 값들은 어디에 들어갈까요? [투영의 크기와 랭크를 바꿔 보고](#lora-projection-count), 학습한 변화를 추론용 가중치에 합쳐 보세요. 매개변수 효율적 미세 조정(PEFT)을 쓰면 여러 과제가 베이스 모델 하나를 공유하고 과제별 어댑터만 따로 보관할 수 있습니다.

---

## 메모리 예산부터 계산하기

전체 가중치를 학습할 때는 가중치, 고정밀 원본을 따로 유지하는 경우 그 복사본, 그래디언트, 옵티마이저 상태, 활성값, 임시 연산·통신 버퍼와 체크포인트를 나누어 계산합니다. 같은 70B 모델도 정밀도, 샤딩, 시퀀스 길이, 마이크로배치 크기, 활성값 재계산 여부에 따라 필요한 메모리가 달라집니다.

LoRA를 적용하면 고정한 가중치의 그래디언트와 옵티마이저 상태를 보관할 필요가 없습니다. 그래도 역전파에 필요한 활성값은 배치 크기와 시퀀스 길이에 따라 늘어납니다. 그래디언트 체크포인팅(gradient checkpointing)은 연산을 다시 수행해 활성값 메모리를 줄입니다. FSDP나 ZeRO는 모델·옵티마이저 상태를 여러 장치에 나누고, 텐서·문맥 병렬화는 한 장치에 들어가지 않는 층이나 긴 시퀀스를 나누는 방법입니다. 어떤 항목이 예산을 넘었는지 측정한 뒤 선택하세요.

## LoRA: Low-Rank Update

입력 특성 수를 $k$, 출력 특성 수를 $d$라고 하겠습니다. PyTorch 선형층에서 가중치 $W_0$의 크기는 $d\times k$입니다. LoRA는 이 가중치를 고정하고 작은 행렬 두 개를 학습합니다. 입력은 먼저 $A$($r\times k$)를 거친 뒤 $B$($d\times r$)를 통과합니다. 랭크 $r$은 두 행렬 사이의 폭이며, 갱신 행렬의 실제 랭크는 이 값을 넘을 수 없습니다. B를 0으로 초기화하면 갱신 행렬의 랭크도 처음에는 0입니다. $\alpha$는 갱신량을 조절하는 상수입니다. [[1]](#ref-1) [[4]](#ref-4)

$$
W = W_0 + \frac{\alpha}{r}BA.
$$

$k=4096$, $d=1024$, $r=16$이면 A에는 $16\times4096=65{,}536$개, B에는 $1024\times16=16{,}384$개의 값이 들어갑니다. 둘을 합치면 **81,920개** 로, 원래 가중치 4,194,304개의 약 **1.95%** 입니다. 다른 투영에도 어댑터를 붙인다면 그 층의 입력·출력 폭으로 다시 계산합니다. 편향은 이 수치에서 제외합니다.

입력 폭을 12, 출력 폭을 8로 바꿔 보세요. 원래 가중치는 96개입니다. 랭크 4에서는 두 행렬에 값 80개가 들어가지만, 랭크 8에서는 160개가 필요합니다. $r(k+d)<kd$일 때만 학습할 파라미터 수가 줄어듭니다. 실제 학습에서는 랭크와 함께 어느 층에 적용할지, $\alpha$, 학습률, 드롭아웃, 업데이트당 지도 학습 토큰 수와 전체 토큰 예산을 정합니다. 쿼리·값 투영만 학습하는 구성을 기준선으로 삼을 수 있습니다. 모든 선형층을 대상으로 하면 학습할 값과 체크포인트 크기가 함께 늘어납니다. 임베딩이나 출력층까지 학습할 때는 두 층이 가중치를 공유하는지 먼저 확인하세요.

### 교육용 Merge 의미론

**예제의 범위.** 아래 두 코드 블록을 CPU용 PyTorch에서 순서대로 실행하세요. 부동소수점 밀집 선형층 `nn.Linear` 하나를 감싸고, 고정한 편향은 두 계산 경로에서 그대로 사용합니다. 추론용 가중치를 따로 보관하는 동안 행렬 하나만큼 메모리가 더 필요합니다. 파라미터를 불러오거나, 자료형을 바꾸거나, 값을 수정하려면 먼저 병합을 해제하세요. 드롭아웃, 가중치 공유, 분산 학습, 양자화, 동시 업데이트는 이 예제의 범위를 벗어납니다.

```python
import math
import torch
from torch import nn
from torch.nn import functional as F


class LoRAWrapper(nn.Module):
    def __init__(self, base: nn.Linear, rank: int, alpha: float):
        super().__init__()
        if not 1 <= rank <= min(base.in_features, base.out_features):
            raise ValueError("rank must fit both feature dimensions")
        self.base = base.requires_grad_(False)
        self.A = nn.Parameter(base.weight.new_empty(rank, base.in_features))
        self.B = nn.Parameter(base.weight.new_zeros(base.out_features, rank))
        nn.init.kaiming_uniform_(self.A, a=math.sqrt(5))
        self.scale = alpha / rank
        self.register_buffer("merged_weight", None, persistent=False)

    def forward(self, x):
        if self.merged_weight is not None:
            return F.linear(x, self.merged_weight, self.base.bias)
        return self.base(x) + F.linear(F.linear(x, self.A), self.B) * self.scale

    @torch.no_grad()
    def merge(self):
        if self.training:
            raise RuntimeError("switch to eval mode before merging")
        if self.merged_weight is None:
            self.merged_weight = self.base.weight + (self.B @ self.A) * self.scale

    def unmerge(self):
        self.merged_weight = None

    def train(self, mode=True):
        if mode:
            self.unmerge()
        return super().train(mode)
```

A는 무작위 값으로, B는 0으로 시작하므로 첫 출력은 넘겨준 베이스 층과 같아야 합니다. 길이 3인 합성 수열 두 개에 대해 목표 출력을 모두 0으로 두고 SGD를 한 번 수행합니다. 그러면 갱신량이 0이 아니어서 병합을 실제로 검증할 수 있습니다. 추론용 병합은 원래 가중치로부터 새 행렬을 계산해 보관하며, `merge()`를 다시 호출해도 결과는 그대로입니다(멱등성). 병합을 해제하면 사본만 버립니다. 반올림된 합에서 갱신량을 다시 빼 원래 비트가 달라지는 문제를 피할 수 있습니다. 단, 곱셈과 덧셈의 순서가 달라서 병합 전후 출력은 조금 다를 수 있습니다.

```python
for dtype in (torch.float32, torch.float64):
    torch.manual_seed(7)
    base = nn.Linear(12, 8, bias=True, dtype=dtype)
    layer = LoRAWrapper(base, rank=4, alpha=8)
    x = torch.randn(2, 3, 12, dtype=dtype)
    target = torch.zeros(2, 3, 8, dtype=dtype)
    original = base.weight.detach().clone()
    assert sum(p.numel() for p in layer.parameters() if p.requires_grad) == 80
    assert torch.equal(layer(x), base(x))

    optimizer = torch.optim.SGD([layer.A, layer.B], lr=0.1)
    F.mse_loss(layer(x), target).backward()
    optimizer.step()
    layer.eval()
    with torch.no_grad():
        expected = layer(x)
        assert not torch.equal(expected, base(x))
        for _ in range(3):
            layer.merge()
            layer.merge()
            torch.testing.assert_close(layer(x), expected)
            layer.unmerge()
            assert torch.equal(base.weight, original)
            assert torch.equal(layer(x), expected)
    print(dtype, expected.shape)
```

두 자료형 모두 출력의 모양은 `[2, 3, 8]`입니다. 예제는 병합 전후 출력을 자료형별 허용 오차 안에서 비교하고, 병합을 해제할 때마다 원래 가중치가 정확히 같은지 검사합니다.

## QLoRA: 양자화 저장과 부동소수점 Update

QLoRA에서는 베이스 가중치를 4비트 형식인 **NF4** 로 저장합니다. 가중치를 복원할 때 쓰는 양자화 상수도 다시 양자화하는 방법을 **이중 양자화** 라고 합니다. 행렬 연산에는 복원한 부동소수점 값을 쓰고 어댑터 파라미터를 학습합니다. 아래 설정은 연산 dtype으로 BF16을 선택합니다. [[2]](#ref-2)

**CUDA 장치 하나를 가정한 설정 예시입니다.** 검증한 로컬 베이스 체크포인트와 호환되는 양자화 백엔드가 필요합니다. 어댑터 설정까지만 다루며 학습 루프, 데이터, 평가, 분산 배치는 생략했습니다. [[3]](#ref-3)

```python
import torch
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

model_id = "your-pinned-base-checkpoint"
quant = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
)
model = AutoModelForCausalLM.from_pretrained(
    model_id, quantization_config=quant, device_map={"": 0}
)
model = prepare_model_for_kbit_training(model, use_gradient_checkpointing=True)
model = get_peft_model(model, LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules="all-linear",
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
))
```

학습 전에 BF16 커널 지원 여부, 정규화 층과 출력층의 자료형, 최대 메모리 사용량, 실제로 학습되는 파라미터 이름을 확인하세요. 그래디언트 체크포인팅을 켰을 때 캐시가 예상대로 동작하는지도 점검합니다. 양자화 오차가 달라지면 적절한 학습률과 랭크도 달라질 수 있습니다.

## Adapter 선택과 배포

먼저 쿼리·값 투영만 학습한 어댑터와 더 많은 층이나 더 높은 랭크를 사용한 어댑터를 비교합니다. 예산이 허용하면 전체 미세 조정도 같은 조건에서 실행합니다. 데이터 순서, 토큰 예산, 평가 항목과 하이퍼파라미터 탐색 예산을 맞추세요. DoRA나 프롬프트 튜닝의 장점도 배포할 모델과 과제에서 확인해야 합니다.

배포할 때는 다음 항목을 한 묶음으로 버전 관리합니다.

- 베이스 체크포인트의 리비전과 해시
- 토크나이저, 채팅 템플릿, 특수 토큰 표와 생성 설정
- 어댑터 가중치와 적용 층, 학습 설정, 라이브러리 버전
- 연산 정밀도와 양자화 설정
- 데이터셋 명세, 코드·설정·컨테이너 버전과 평가 보고서

다른 베이스 모델에 어댑터를 얹어도 출력이 그럴듯해 보일 수 있습니다. 로딩 단계에서 해시를 대조하세요. 병합해 배포할 때는 부동소수점 자료형을 명시해 새 체크포인트로 저장하고, 병합 전후의 로짓과 생성 결과를 비교합니다. 4비트 가중치를 재양자화하면 오차가 생길 수 있으므로 복구용 원본 베이스와 어댑터를 보관하세요.

## 실행 및 Release Gate

채팅 과제에서는 베이스와 토크나이저 버전을 고정하고, 서빙에 쓸 채팅 템플릿을 적용해 학습 대상으로 지정한 어시스턴트 토큰에만 손실을 계산합니다. 남겨 둔 답변의 EOS를 보존하고, 패딩과 프롬프트를 마스킹하며, 패킹한 예시끼리 서로를 참조하는지 점검하세요. 구체적인 마스크와 경계 검사는 [SFT 예제](../sft-fundamentals/)에서 다룹니다. 학습과 다른 출처 그룹에서 평가용 대화를 고릅니다. 앞의 선형 회귀 실습은 패딩 없는 합성 텐서에 평균제곱오차를 사용합니다.

학습과 검증 손실을 지도 학습 토큰당 값으로 기록하고 도메인·길이별로 나누어 살펴봅니다. 어댑터의 그래디언트·활성값 노름, 비유한 값·오버플로 횟수, 최대 메모리 사용량, 초당 토큰 수, 데이터 대기 시간도 측정합니다. 분산 학습에서는 모델 FLOP 활용률과 집단 통신 대기 시간을 함께 봅니다. 문제가 생긴 업데이트를 재현할 수 있도록 배치 식별자를 남기세요. 재개용 체크포인트에는 어댑터와 베이스 식별자, 옵티마이저, 스케줄러, 스케일러, 누적 토큰 수, 난수·샘플러 상태, 데이터 읽기 위치와 데이터셋·설정 해시가 필요합니다.

고정한 베이스에 그래디언트가 생기거나, 지정한 층이 누락되거나, 오버플로가 반복되거나, 메모리 예산을 넘으면 멈춥니다. 배포 전에 도메인 품질, 기존 능력 유지, 안전성, 출력 형식과 도구 사용, 지연 시간, 비용, 오류율의 허용 범위를 정합니다. 같은 평가 사례에 대해 현재 버전과 후보를 비교하고 집단별 불확실성을 확인하세요. 중요한 집단에서 기준을 넘으면 이전 버전을 계속 사용합니다. 다음 배포 전에 이전 묶음을 복원하고 검증 예제를 다시 실행하는 연습도 필요합니다.
