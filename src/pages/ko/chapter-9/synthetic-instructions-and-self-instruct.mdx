# 9.5 합성 지시문과 Self-Instruct

전문가가 직접 쓴 예시만으로는 필요한 과제를 다 담기 어려울 때가 있습니다. 이때 모델로 지시문과 답변을 만들어 부족한 부분을 채울 수 있습니다. 전문가는 어떤 과제를 만들지 정하고, 정답이 확인된 기준 자료를 마련하고, 모델이 자주 틀리는 사례를 검토합니다. 생성한 예시가 학습에 쓰이려면 어디서 왔는지 추적할 수 있어야 하고 내용도 검증을 통과해야 합니다.

---

<a id="세-가지-생성-패턴"></a>

## 지시문을 만드는 세 가지 방법

**Self-Instruct** 는 소수의 예시에서 출발해 새 지시문을 만들고, 각 지시문에 맞는 입력과 답변을 생성합니다. 내용이 거의 같은 예시를 걸러내면서 과제의 종류를 늘려 갑니다 [[1]](#ref-1). **Evol-Instruct** 는 기존 지시문을 변형합니다. 조건을 더하면 같은 과제가 어려워지고, 주제를 바꾸면 다루는 범위가 넓어집니다 [[2]](#ref-2). **Magpie** 는 지시 튜닝을 거친 모델에 사용자 질문이 시작되기 직전까지만 입력합니다. 그러면 모델이 자신이 학습한 대화에서 나올 법한 질문을 이어 씁니다 [[3]](#ref-3).

과제 종류를 늘릴 때와 특정 과제의 난이도를 조절할 때는 만드는 방식이 다릅니다. Magpie를 택하면 어떤 질문이 많이 나올지도 교사 모델의 학습 경험에 좌우됩니다. 세 방법 모두 결과가 정확하고 안전한지, 기존 예시와 충분히 다른지, 실제 사용자가 필요로 하는지 따로 살펴야 합니다.

## 질문은 어디서 시작하고 끝나는가?

Magpie를 쓸 때는 모델의 토크나이저가 사용하는 대화 형식을 확인해야 합니다. 다른 모델에서 본 `<|user|>` 같은 표시를 그대로 넣으면 사용자 발화의 시작으로 인식하지 못할 수 있습니다. 생성 모델과 심판 모델 각각에 맞는 `tokenizer.apply_chat_template`을 쓰고, 두 템플릿의 버전도 따로 고정합니다.

먼저 모델이 사용자 질문을 쓰게 합니다. 다음 역할의 시작이나 한 차례 발화의 끝을 알리는 표시에 도달하면 질문 생성을 멈추도록 **중단 토큰** 을 지정합니다. 그렇지 않으면 모델이 답변까지 이어 쓰고, 그 일부가 사용자 질문으로 저장될 수 있습니다. 질문을 얻고 나면 이를 온전한 사용자 메시지로 템플릿에 다시 넣습니다. 이번에는 `add_generation_prompt=True`로 답변을 시작합니다.

**의사 코드.** 첫 호출에 넣는 토큰은 사용자의 첫 단어가 들어갈 자리 바로 앞에서 끝나야 합니다. 빈 사용자 메시지에도 종료 표시를 붙이는 템플릿이라면 경계가 이미 닫혀 있습니다. 예를 들어 Magpie 연구진이 설명한 Llama-2-chat 형식에서는 `[INST]`와 `[/INST]` 사이에 질문이 들어갑니다. 모델 고유의 템플릿에서 질문 앞부분의 토큰 ID를 확인하세요. 이 부분을 만드는 함수와 생성·중단·디코딩 함수는 사용하는 추론 엔진에 맞춰 구현해야 합니다. 예제는 중단 표시 하나가 토큰 하나에 해당한다고 가정합니다. 여러 토큰으로 된 표시라면 그 토큰들이 순서대로 모두 나타났을 때 멈추세요. [[3]](#ref-3)

```python
def render_answer_prefix(tokenizer, query):
    return tokenizer.apply_chat_template(
        [{"role": "user", "content": query}],
        tokenize=True,
        add_generation_prompt=True,
        return_dict=True,
    )["input_ids"]

# 버전을 고정한 생성 모델의 토크나이저와 템플릿에서 ID를 구합니다.
query_prefix_ids = verified_open_user_prefix_ids(generator_tokenizer)
query_stop_token_ids = resolve_next_role_or_eot_ids(generator_tokenizer)
query_ids = generate(
    query_prefix_ids,
    stop_token_ids=query_stop_token_ids,
    max_new_tokens=512,
)
query = decode_generated_span_only(generator_tokenizer, query_ids)  # 중단 표시는 제외합니다.
answer_ids = generate(
    render_answer_prefix(generator_tokenizer, query),
    stop_token_ids=[generator_tokenizer.eos_token_id],
    max_new_tokens=1024,
)
```

입력과 출력을 합쳐 디코딩한 문자열을 `len(prompt)`에서 자르면 질문이 시작되는 위치를 잘못 짚을 수 있습니다. 토크나이저가 유니코드 문자를 정규화하는 과정에서 문자열 길이가 달라질 수 있기 때문입니다. 입력이 끝나는 위치를 토큰 단위로 기록하고 새로 생성한 토큰 ID만 디코딩하세요.

## 어떤 예시를 학습에 쓸까?

1. **형식과 경계를 확인합니다.** 메시지의 역할과 종료 토큰(EOS)이 맞는지, 언어와 길이 조건을 지켰는지, 빈 필드는 없는지, 도구 호출이 스키마에 맞는지 봅니다.
2. **정답을 검사할 수 있는 것은 직접 검사합니다.** 생성된 코드는 격리된 환경에서 실행하고, 수학 답안은 검증기로 확인합니다. JSON과 도구 호출 인자도 정해진 규칙과 대조합니다.
3. **중복을 제거하고 평가 자료를 분리합니다.** 완전히 같거나 거의 같은 예시와 표현만 다르고 뜻이 같은 예시를 찾습니다. 벤치마크 문항이나 비공개 평가 질문과 의미가 가까운 예시가 학습 자료에 섞였는지도 확인합니다.
4. **심판 모델에 채점을 맡깁니다.** 적용할 분야에 맞는 채점 기준을 쓰고, 심판 모델의 대화 템플릿은 생성 모델의 것과 별도로 버전을 고정합니다.
5. **사람이 표본을 검토합니다.** 무작위로 뽑은 예시 외에도 위험도가 높거나 판단이 불확실한 사례, 심판들의 의견이 갈린 사례는 모두 확인합니다.

어느 점수부터 예시를 받아들일지는 사람이 미리 판정한 기준 자료(골드 세트)로 보정합니다. 채택·재검토·제외 구간을 정한 뒤에는 채택한 예시 중 실제로 기준을 충족한 비율인 정밀도를 언어·분야·길이·난이도·안전성 범주별로 집계합니다. 심판 모델이 그럴듯한 설명에 높은 점수를 줘도 코드를 실행하면 오류가 날 수 있습니다. 이렇게 서로 독립적인 검사를 함께 쓰는 편이 좋습니다.

## 생성 이력을 남기고 학습 데이터의 비율 정하기

채택한 예시와 제외한 예시 모두 다음 기록을 남깁니다.

- 교사 모델의 버전, 토크나이저와 대화 템플릿의 해시
- 생성에 쓴 프롬프트나 출발점이 된 과제, 이를 차례로 변형한 내역, 난수 시드, 디코딩 설정
- 심판·검증 모델과 채점 기준의 버전, 보정 전 점수, 실행 결과, **거부 사유**
- 원자료의 라이선스와 이용 동의 여부, 개인정보·비밀정보·안전성에 관한 처리 결정, 바뀌지 않는 샘플 ID와 군집 ID
- 생성 시각, 파이프라인 코드·설정·컨테이너, 원본이 된 상위 샘플의 ID

각 검사 단계에서 범주별로 몇 건이 통과했는지 기록합니다. 전체 통과율이 높아도 소수 언어의 질문이나 어려운 과제, 안전성을 시험하는 사례가 거의 다 탈락했을 수 있습니다. 사람이 쓴 예시, 검증을 거친 합성 예시, 모델의 약점을 시험하는 적대적 예시, 기존 능력을 유지하기 위한 예시마다 추출 비율을 정하세요. 그래야 교사 모델이 즐겨 고른 주제와 장황한 답변이 학생 모델의 학습 자료를 지배하지 않습니다.

학습용과 평가용으로 나누기 전에 서로 관련된 질문과 답변, 그 변형본, 같은 예시에서 파생된 합성 샘플을 의미상 같은 군집으로 묶습니다. 공개 벤치마크, 비공개 평가셋, 채점 기준표와 더불어 이들과 뜻이 비슷한 예시나 교사 모델이 만든 변형본도 학습 자료에서 격리합니다. 벤치마크 문제를 다른 말로 바꾸어 학습에 써도 **벤치마크 오염** 이 일어납니다.

<a id="재귀적-성능-저하-막기"></a>

## 합성 데이터를 다음 모델의 학습에 다시 쓸 때

모델이 만든 자료로 다음 모델을 학습하는 과정을 반복하면 드문 표현이나 사례가 사라지고 특정 오류가 두드러질 수 있습니다. 이런 현상을 모델 붕괴라고 부릅니다. 반복할 때마다 반드시 한 가지 결과로 수렴하는 것은 아닙니다. 위험은 합성 자료와 실제 자료를 어떻게 고르고 섞으며 결과를 어떻게 평가하느냐에 따라 달라집니다 [[4]](#ref-4).

사람이 쓴 자료를 계속 보충하고 출처를 다양하게 확보하세요. 드문 범주에서 확보할 예시 수를 정하고, 생성물을 걸러내는 거부 샘플링 기준을 보정합니다. 표현뿐 아니라 의미도 다양한지 측정하고, 기존 능력을 여전히 발휘하는지는 사람이 작성해 고정해 둔 평가셋으로 확인합니다. 생성 온도만 높이면 이미 사라진 유형을 되살리기 어렵고 오류가 늘 수도 있습니다.

같은 토큰 예산으로 한쪽은 사람이 쓴 자료만, 다른 쪽은 합성 자료를 섞어 학습하도록 소규모 비교 실험을 설계합니다. 목표 범주의 성능이 좋아졌고 기존 능력·안전성·다양성 저하가 미리 정한 한도 안에 있을 때 규모를 늘리세요. 결과가 나빠져 되돌려야 할 때를 위해 이전 데이터 명세와 모델 아티팩트 묶음을 보관합니다.

먼저 어떤 문제를 풀어야 하는지도 확인하세요. 자주 바뀌고 출처를 밝혀야 하는 지식이라면 검색을, 새로운 분야의 언어 전반에 적응해야 한다면 [지속 사전 학습](/ko/chapter-8/continued-pretraining-and-domain-adaptation)을 시험합니다. 원하는 응답 행동을 예시로 가르치는 편이 낫다는 근거가 별도의 평가셋에서 확인되면 지도 미세 조정(SFT)을 선택합니다.

</details>
