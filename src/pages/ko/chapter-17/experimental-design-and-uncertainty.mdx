# 17.7 실험 설계와 불확실성

후보 모델의 정답률이 56%, 기준 모델이 54%라고 합시다. 이 2%p 차이만으로 개선을 입증할 수 있을까요? 먼저 어느 모집단에 대한 결론인지, 사례들이 독립적인지, 같은 사례를 비교했는지, 얼마나 나아져야 하는지 확인해야 합니다. 통계 기법으로 오염된 평가셋이나 일관되지 않은 평가 조건을 고칠 수는 없습니다.

후보 두 개 모두 목표 과제의 정답률이 15%p 올랐습니다. [목표 과제 개선](?scenario=gain#release-lab)과 [기존 능력 하락](?scenario=regression#release-lab) 시나리오를 각각 실행해 기존 능력을 측정한 행을 비교해 보세요. 어느 후보를 배포하시겠습니까?

## 측정 전에 주장 정의하기

**추정 대상(estimand)** 은 알고 싶은 모집단의 양입니다. 여기서는 독립 과제 집단에 같은 가중치를 주어 계산한 후보 모델과 기준 모델의 평균 성공률 차이입니다. 하나의 문서·대화·저장소나 같은 원본에서 파생한 합성 사례들을 한 집단으로 묶을 수 있습니다. 관련 사례는 같은 노출 상태로 관리하고 같은 데이터 분할에 배정합니다. 트래픽에 따라 가중한 평균은 다른 질문에 답하므로 결과를 보기 전에 가중치를 정하세요.

집단 $c$의 사례 $i$에서 대응된 이진 결과의 차이를 $d_{ci}=y^{candidate}_{ci}-y^{champion}_{ci}$라 합시다. 집단 수가 $C$, 집단별 사례 수가 $n_c$이면 다음과 같습니다.

$$
\widehat\Delta=\frac{1}{C}\sum_{c=1}^{C}\left(\frac{1}{n_c}\sum_{i=1}^{n_c}d_{ci}\right).
$$

예를 들어 `gain`과 `regression`의 목표 과제에는 네 사례씩 묶인 집단이 80개 있습니다. 후보 모델은 64개 집단에서 한 건씩 더 맞히고, 나머지 16개 집단에서는 한 건씩 덜 맞힙니다. 모든 집단의 크기가 같으므로 평균 차이는 다음과 같습니다.

$$
\widehat\Delta=\frac{64-16}{80\times4}=0.15.
$$

즉 **15%p 개선** 입니다. 두 시나리오의 목표 과제 개선 폭은 같습니다. 둘을 가르는 것은 기존 능력을 평가한 결과입니다.

비교하는 각 시스템의 모델 버전, 프롬프트, 실행 구조, 도구, 디코딩 예산과 채점기를 고정합니다. 집단 전체를 복원 추출해 대응 쌍과 관련 사례를 함께 유지한 뒤 같은 통계량을 다시 계산합니다. 서로 상관된 사례를 독립 행처럼 추출하면 유효 표본 수를 부풀립니다. 대응 재표집은 두 시스템에 같은 표집 단위를 적용한다는 뜻입니다 [[1]](#ref-1).

## 평가 결과로 배포 여부 판단하기

실습에 쓰는 두 모델의 결과는 같은 사례에 대해 직접 만든 합성 자료입니다. 관련 사례를 집단째 다시 뽑아 성공률 차이의 불확실성을 계산합니다. 통과하려면 목표 과제의 하한이 +5%p보다 높고, 기존 능력 평가의 하한도 −2%p보다 높아야 합니다.

같은 실습을 로컬에서 실행하려면 [paired_release.py](../../../labs/paired_release.py)를 내려받으세요. Python 3.10 이상이면 추가 패키지는 필요 없습니다. 파일을 저장한 폴더에서 실행합니다.

```bash
python paired_release.py --scenario gain
python paired_release.py --scenario uncertain
python paired_release.py --scenario regression
python paired_release.py --scenario missing
```

목표 과제와 기존 능력 평가에 각각 위와 같은 80개 집단, 집단당 네 사례를 사용합니다. 프로그램은 이미 노출된 사고 사례 집단을 제외하고, 중복 ID와 누락된 대응 결과를 검사합니다. Seed 23으로 4,000회 부트스트랩한 뒤 JSON으로 판단 근거를 출력합니다. 실제 평가에서는 시간 초과를 실패로 셀지 미리 정하세요. 관측하지 못한 결과를 조용히 제거하면 안 됩니다. 이 실습에서 누락이 해결되지 않으면 **Review(재검토)** 로 판단합니다.

| 시나리오 | 결과 | 이유 |
|---|---|---|
| `gain` | Pass(통과) | 목표 개선은 15%p이고 단측 95% 하한 11.25%p가 요구한 5%p보다 큽니다. 기존 능력 보존도 −2%p 허용 한계를 통과합니다. |
| `uncertain` | Review(재검토) | 요구한 목표 개선을 입증할 증거가 부족합니다. |
| `regression` | Block(차단) | 목표 과제는 개선됐지만 기존 능력 평가에서 25%p 하락합니다. |
| `missing` | Review(재검토) | 대응 결과 하나가 누락됐습니다. |

왜 기존 능력 평가의 구간 폭은 0일까요? `regression`에서는 네 사례로 구성된 **모든 집단** 에서 후보 모델이 기준 모델보다 한 건씩 덜 맞힙니다. 어떤 집단을 다시 뽑아도 평균 차이는 −25%p입니다. `gain`에서는 집단마다 차이가 0입니다. 두 시나리오 모두 구간 폭이 0이지만 보존 기준을 통과하는 쪽은 하나뿐입니다. 합성 자료의 이런 성질이 모집단의 불확실성까지 없다는 뜻은 아닙니다. 표본이 작거나 이처럼 분포가 한 값에 몰리면 백분위 부트스트랩 구간이 참값을 포함하는 비율이 명목 신뢰수준보다 낮아질 수 있습니다.

하한이 0보다 크면 방법의 가정 아래 개선의 증거가 됩니다. 0.05보다 커야 더 강한 5%p 기준을 지지합니다. 비열등성은 하한이 사전에 정한 허용 손실, 여기서는 −0.02보다 큰지 묻습니다. “유의한 악화가 없다”는 비열등성 입증이 아닙니다. 프로그램은 각각의 단측 경계를 사용합니다. 표시한 상·하한을 함께 보면 중앙 90% 구간이지 양측 95% 구간이 아닙니다. Pass는 합성 오프라인 기준만 뜻하며 배포 승인이 아닙니다.

## 관측된 실패 0회는 위험 0이 아님

독립 Bernoulli 시행 $n$회에서 실패율이 $p$일 때 실패를 한 번도 보지 않을 확률은 $(1-p)^n$입니다. 이를 $\alpha$와 같게 놓으면 정확한 단측 상한 $p_U=1-\alpha^{1/n}$를 얻습니다 [[2]](#ref-2). 95% 신뢰수준에서 1,000회 무실패의 상한은 약 **0.299%** 로 실습의 0.5% 기준을 통과합니다. 100회라면 약 **2.95%** 입니다. 상한을 0.1% 미만으로 낮추려면 $\log(0.05)/\log(0.999)\approx2994.2$회보다 많은 독립 무실패 시행이 필요하므로 최소 2,995회가 필요합니다.

프로그램의 안전 표본은 별도로 작성한 시나리오입니다. 상관된 재시도는 독립 시행이 아니며, 선별한 red-team prompt로 운영 환경 발생률을 추정할 수 없습니다. 실제 안전성에는 위협 범위, 심각도 처리, judge 검증과 운영 통제도 필요합니다. 이항 비율 하나로 충분하지 않습니다.

## 예산, 선택, 중단 규칙

봉인된 출시셋 밖의 pilot 데이터로 의미 있는 효과, 두 모델의 결과가 다른 쌍의 빈도, 집단 변동, 원하는 검정력을 고려해 표본 크기를 계획합니다. 닫힌 형태의 근사가 적절하지 않으면 예정된 분석을 시뮬레이션하세요. Bootstrap 반복 수를 늘리면 Monte Carlo 잡음은 줄지만 독립 과제가 늘지는 않습니다.

체크포인트와 하이퍼파라미터는 개발셋으로 선택합니다. 출시셋을 열기 전에 최종 비교를 고정하세요. 여러 후보를 반복 선택하거나 유리한 slice만 강조한다면 다중 비교 통제나 새로운 확인셋이 필요합니다. 사전에 정한 모든 기준의 통과를 요구하는 것과 유리한 결과 하나를 탐색하는 것은 다릅니다. 적절한 보정 없이 모든 구간을 동시 신뢰구간으로 광고하면 안 됩니다.

Canary에서는 간섭 구조에 맞는 사용자·세션 단위로 처리군을 지속적으로 고정합니다. 실용적인 기본값은 고정 표본 크기와 종료 시 효능 분석 한 번입니다. 안전 문제는 그동안 계속 감시하고 즉시 중단할 수 있습니다. 일반 신뢰구간을 반복 확인하다 처음 유리해질 때 승격하면 명목 해석이 무너집니다. 조기 효능 판단에는 순차 실험 설계가 필요하며 운영 hysteresis로 대신할 수 없습니다. 단계별 ramp에서 기존 관측을 재사용하는지도 명시하세요.

고정 체크포인트의 과제를 재표집하면 과제 불확실성을 추정할 뿐 재학습 변동은 추정하지 못합니다. 레시피에 관한 주장은 학습 seed를 반복하고 그 계층까지 모델링해야 합니다. 확장 과제로 같은 집단 안에 다른 case ID를 주어 형제 사례를 복제해보세요. 증거를 복사했다고 집단 추정이 더 확실해져서는 안 됩니다. 일부러 잘못된 행 단위 bootstrap과 비교하고 구간이 좁아지는 이유를 설명합니다.

</details>
