# 17.6 상용 및 오픈 웨이트 모델 벤치마크

토큰 단가가 낮은 모델로 바꿨는데, 같은 작업을 끝내기까지 도구를 두 배 더 호출한다면 비용이 줄었다고 할 수 있을까? 순위표만으로는 답할 수 없다. 평가에 쓴 설정, 과금 규칙, 과업 성공의 기준을 함께 알아야 한다.

**2026-11-24 기준.** GLM-5.4, Ling-3.2-air, GPT-6.2 Astra/Sol, Gemini 4 Neon/Carbon 등을 포함해 45개 프로필을 담은 스냅샷이다. 각 행의 날짜는 출처에서 확인한 API 출시일, 가중치 공개일 또는 체크포인트 갱신일이다. 뒤쪽 두 숫자 열을 보면 Artificial Analysis(AA)가 어떤 모델을 평가했고 어느 모델의 과업 비용까지 공개했는지 알 수 있다. 배포 예산을 잡을 때는 접근 조건과 가격을 출처에서 다시 확인하자.

## 1. 숫자가 무엇을 측정하는지 먼저 확인하기

수치 비교에는 **Artificial Analysis Intelligence Index v5.0.1** 을 사용한다. 지식 노동, 코딩, 과학, 일반 과업에 걸친 아홉 평가를 결합한 지수다 [[1]](#ref-1). 이 책의 11월 15일 스냅샷과 평가 버전은 같다. 이전 v4.3.2 값은 다른 측정값이므로, 두 버전의 차이를 모델 성능 향상으로 해석하면 안 된다.

각 점은 모델에 **추론 강도와 평가 시스템을 결합한 결과** 다. Fallback, 도구, scaffold, 토큰 예산, 샘플링, 채점기가 결과에 영향을 준다. 동일한 연산량을 쓴 실험이 아니다. 지수는 정확도 백분율이 아니고, 문맥 한도는 검색 정확도가 아니다. “미공개”는 해당 리비전과 평가 방식에 대응하는 값을 이 자료에서 확인하지 못했다는 뜻이며, 0이라는 뜻이 아니다.

**비용 열의 계산 기준에 주의하자.** AA는 평가 작업량, 제공사 가격, 일반적인 캐시 적중 가정을 이용해 과업당 가중 비용을 계산한다. 독자의 배포 환경에서 수집한 청구서가 아니다. 모델 점수가 그대로여도 가격에 따라 값이 달라질 수 있다. 이 스냅샷의 AA Argon·Carbon 프로필은 입력·출력 백만 토큰당 \$4/\$20을 사용한다. 반면 Google 공식 요금은 11월 30일까지 \$2/\$10이며, 12월 1일부터 \$4/\$20으로 바뀔 예정이다. 표에는 AA의 계산을 보존하고, 토큰 단가 탐색기에는 기준일의 제공사 요금을 사용한다. 두 기준을 설명 없이 섞어서는 안 된다 [[2]](#ref-2) [[3]](#ref-3) [[4]](#ref-4).

빈값 중에는 의도적으로 남긴 항목이 있다. 9월 DeepSeek 항목과 Bolt 74B에는 현재 지수의 대응 관계를 확인하지 못했다. Ling 3.1 Flash의 평가 대상인 1019 변형도 표의 체크포인트와 같다고 확인되지 않았다. Agnes 공개 설정은 262,144 토큰이지만 AA의 호스팅 프로필은 다른 문맥 조건을 제시하므로, 그 점수를 로컬 아티팩트에 옮기지 않았다. GLM-5.4에는 이 스냅샷에서 확인한 AA 측정값이 없다. Wonder Full은 지수는 있지만 검증된 공개 API 과업 비용은 없다.

## 3. 최근 공개에서 달라진 점

### GLM-5.4: 서비스는 사용 가능하지만 가중치는 공개 예정

Z.ai가 11월 23일 공개한 **GLM-5.4** 는 Coding Plan, ZCode, Z.ai Chat에서 사용할 수 있다. 일반 종량제 API는 아직 공개 예정이며, 가중치는 추가 안전성 작업 후 공개할 계획이다. Coding Plan에는 이미 구독형 API 접근이 있으므로 “API가 전혀 없다”는 설명도 틀리다. GLM-5.3 Flash의 MIT 라이선스를 그대로 적용하거나, 구독 크레딧 배수를 달러 토큰 단가로 바꿔 적어서는 안 된다 [[5]](#ref-5) [[6]](#ref-6) [[7]](#ref-7).

공개된 설계는 750B급 모델에서 28층 블록을 두 번 실행하며, 게이트를 이용한 상태 갱신과 공유 전역 KV·지역 어텐션을 결합한다. 한 번만 저장하는 가중치와 두 번 수행하는 연산의 차이는 [4.5절](/ko/chapter-4/various-llm-architectures#glm-54-레이어-재사용으로-깊이와-용량을-구분하기)에서 살펴볼 수 있다. 정확한 전체·활성 파라미터 수, 학습 데이터의 전체 혼합 비율, 향후 가중치 라이선스는 미공개다. 구조를 바꿔 가며 비교한 실험은 30B 모델에서 수행했다 [[5]](#ref-5).

**종량제 요금 확인일은 2026-11-25이다.** 도구를 사용하지 않는 텍스트 요청 하나에 캐시되지 않은 입력 10,000토큰과 과금 대상 출력 2,000토큰이 필요하다고 하자. Z.ai의 GLM-5.3은 백만 토큰당 입력 1.40달러, 출력 4.40달러이므로 이 요청에 0.0228달러가 든다. GLM-5.3 Flash는 각각 0.15달러와 0.50달러로 같은 요청에 0.0025달러가 든다. 같은 공식 요금표에서 GLM-5.4의 토큰 단가는 아직 확인할 수 없다. 종량제 단가가 공개될 때까지 5.4로 처리할 수 있는 작업량은 Coding Plan의 사용 한도를 기준으로 추산한다. [[7]](#ref-7)

### GPT-6.2 Astra와 Sol: 실제 운영할 설정을 평가하기

OpenAI는 11월 17일 **GPT-6.2 Astra와 Sol** 을 공개했다. 둘 다 텍스트·이미지를 입력받아 텍스트를 출력하는 호스팅 모델이며, 가중치와 내부 아키텍처 상세는 제공하지 않는다. API는 문맥 창 1,050,000 토큰, 최대 입력 922,000 토큰, 최대 출력 128,000 토큰을 구분한다. 도구 호출에는 Responses를 사용하며 추론 강도 `none`은 거부한다. 기존 에이전트를 이전할 때 확인해야 할 조건이다 [[8]](#ref-8) [[9]](#ref-9) [[10]](#ref-10).

11월 23일 OpenAI는 Plus·Pro·Business·Enterprise 이용자에게 **ChatGPT 채팅 탭** 에 맞춘 GPT-6.2를 순차 배포하기 시작했다. 시스템 카드에서는 이 버전을 “GPT-6.2 (November 23)”이라고 부른다. 고객지원팀이 채팅 탭에서 더 나은 답변을 얻었다면 API로 만든 상담 서비스에서도 같은 결과를 기대할 수 있을까? 채팅 릴리스 노트에는 대응하는 API 체크포인트가 명시돼 있지 않다. 채팅을 실행한 날짜와 요금제, 사용한 도구를 기록하고, 같은 상담 사례를 서비스에 배포할 API 모델 ID와 추론 강도로 다시 평가해야 한다. 표의 Astra와 Sol 점수는 각 API 평가 프로필에서 측정한 값이다. [[115]](#ref-115) [[116]](#ref-116)

차트의 Max 추론 프로필만 보고 지연 시간에 민감한 서비스의 적정 추론 강도를 정할 수는 없다. 실제로 운영할 추론 강도와 서비스 등급에서 비교해야 한다. 아래 비용 예제는 기본 토큰 단가를 정확히 옮겼더라도 비용 계산이 틀릴 수 있는 이유를 보여준다.

### Gemini 4: 공유 문맥 예산과 기간별 요금

**Gemini 4 Neon** 은 11월 18일 정식 공개되었고, **Carbon** 의 API 정식 공개일은 11월 10일이다. Neon의 1,048,576 토큰은 입력과 출력이 공유하는 예산이다. 기본 동기 출력 한도는 65,536 토큰이며, 백그라운드 long-decode 경로에서는 공유 예산의 더 큰 부분을 출력에 쓸 수 있다. 따라서 “입력 백만 토큰에 출력 백만 토큰을 더할 수 있다”는 해석은 틀리다. Neon은 명시적 캐시 API 대신 암묵적 캐싱을 지원하므로, 같은 모델 계열의 캐시 제어가 모두 같다고 가정해서도 안 된다 [[11]](#ref-11) [[12]](#ref-12).

## 4. 비용 계산 예제: 입력 272K 토큰을 넘었을 때

**요금 확인일: 2026-11-24.** Standard의 짧은 문맥 요금은 백만 토큰당 GPT-6.2 Astra 입력 \$8·출력 \$40, Sol 입력 \$2·출력 \$10이다. 입력이 **272,000 토큰을 초과하면 요청 전체에** 입력 요금 2배, 출력 요금 1.5배가 적용된다 [[9]](#ref-9) [[10]](#ref-10).

저장소 리뷰 한 번에 캐시되지 않은 입력 300,000 토큰과 과금 대상 출력 10,000 토큰을 쓴다고 하자. Sol 기본 단가만 곱하면 \$0.70이지만, 긴 문맥 규칙을 적용하면 **\$1.35** 다. 같은 조건에서 Astra는 **\$5.40** 이다. 입력을 줄이면 토큰 수뿐 아니라 적용 요율도 바뀔 수 있다. 그때 품질이 유지되는지는 별도로 평가해야 한다.

Sol 요청 두 건에 입력 544,000토큰과 과금 대상 출력 20,000토큰을 쓴다고 하자. 출력을 요청당 10,000토큰으로 고정하고 입력을 반씩 나누면 둘 다 짧은 문맥 요금이 적용돼 합계는 **\$1.288000** 이다. 첫 요청의 입력에서 토큰 하나를 빼서 두 번째 요청에 옮겨 보자. 전체 토큰 수는 그대로인데 합계가 **\$1.882002** 가 된다. 요청당 평균 토큰 수로 예산을 잡으면 이 차액 \$0.594002를 놓친다. 요청별로 요금을 계산한 뒤 더해야 한다.

`python request_cost.py`를 실행하면 표준 라이브러리만으로 두 금액을 재현할 수 있다. 예제는 캐시를 쓰지 않는 Standard 등급의 텍스트 요청을 다룬다. 출력에는 과금 대상 추론 토큰을 포함한다. 캐시, 도구, 이미지, 세금과 다른 처리 등급의 요금은 별도다. [[9]](#ref-9) [[10]](#ref-10)

## 5. 비용·성능 관계 탐색하기

지표, 축, 제공사를 선택하자. 두 좌표 값이 모두 있는 모델만 표시하며, 선택 항목도 필터 결과를 따라간다. 빈 차트는 유효한 결과다. 이름순 선택 목록은 순위가 아니다.

토큰 단가 축에는 **캐시 없는 예시 혼합비** $(3p_{in}+p_{out})/4$를 사용한다. $p_{in}$과 $p_{out}$은 각각 입력·출력 백만 토큰당 달러 가격이다. 캐시, 도구, 모달리티 요금, 긴 문맥 요율, 출력 길이 차이를 제외한다. AA의 혼합 단가 정의도, 완료된 워크플로의 비용도 아니다. 문맥은 천 토큰 단위로 표시하며, 제공사별 입력·출력 제한은 별도로 적용된다.

## 6. 후보 선정에서 릴리스 결정으로

품질·비용·지연·문맥·공개성·안전성의 Pareto 표면에서 후보를 고르자. 같은 비공개 과업을 사용하고 도구, 권한, scaffold, 추론 강도, 재시도, 한도, 채점기를 고정한다. 쌍체 불확실성, 언어·도메인별 결과, 기본 능력 유지, 형식·도구 정확성, 안전성, 꼬리 지연, 오류율, 성공 과업당 비용을 보고한다. 평균이 좋아져도 중요한 평가 구간이 실패하면 릴리스를 막아야 한다.

가중치 또는 API 리비전, 토크나이저·템플릿, 양자화, 런타임, 생성 설정, 도구 스키마, 안전 정책을 하나의 불변 아티팩트 묶음으로 보존한다. 호스팅과 로컬 버전은 따로 평가한다. 제한된 권한으로 canary를 운영하고 정상 동작이 확인된 경로를 유지하며, 캐시 상태와 대기 중인 외부 효과까지 롤백하는 연습을 한다. 구조화된 의사결정 모델에는 별도의 보정·선택적 위험 평가가 필요하다. [16.7절](/ko/chapter-16/decision-models-and-selective-prediction)을 참고하자.
