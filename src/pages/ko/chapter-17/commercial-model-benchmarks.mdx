# 17.6 상용 모델 벤치마크

새 모델이 나오면 해결할 수 있는 과업, 과업을 끝내는 비용, 실제로 선택할 수 있는 배포 방식이 함께 달라집니다. 대표 점수만 읽으면 이 의사결정을 놓칩니다. API 프리뷰는 평가할 가치가 있어도 자체 호스팅은 불가능할 수 있고, 토큰 단가가 낮아도 긴 추론을 생성하면 과업 비용은 커질 수 있습니다.

**2026-10-13 기준.** 이 페이지는 실시간 순위표가 아닌 날짜가 고정된 **과거 스냅샷** 입니다. 게시나 구매 전에는 접근 상태와 변동 가능한 값을 **다시 검증** 해야 합니다. 아래 8~10월 사례는 기존 9월 스냅샷 이후의 공개를 반영합니다. 이전 모델은 책의 역사적 사례로 남기되, 과거 지수 값을 새 비교에 그대로 섞지 않습니다.

## 1. 평가 버전과 실행 조건을 명시하기

그래프는 **Artificial Analysis 지능 지수 v4.3.2** 를 사용합니다. 현재 방법론에는 Terminal-Bench 4.0과 개정된 전문 업무 평가가 포함됩니다 [[1]](#ref-1). 이전 v4.2 점수와는 직접적인 시계열 비교가 불가능합니다. 평가 개정 후 숫자가 낮아졌다고 모델 능력이 떨어졌다고 결론 내릴 수 없습니다.

지수 값은 모두 평가 기관의 모델별 페이지에서 확인했습니다. **추론 강도와 fallback 조건도 평가 시스템의 정체성에 포함됩니다.** 제공사마다 `max` 가 뜻하는 FLOPs·토큰 수·지연 시간은 다릅니다. 아래 값은 동일 평가 모음에서 관측한 품질·비용 지점이며, 가중치의 효과만 분리한 통제 실험은 아닙니다. 모델 교체나 인과적 주장을 위해서는 예산을 맞춘 내부 평가가 필요합니다.

기본 x축은 관측된 **AA 평가 과업당 비용** 입니다. 토큰 단가 축은 $p_b=(3p_{in}+p_{out})/4$ 를 사용합니다. $p_{in}$ 과 $p_{out}$ 은 각각 캐시되지 않은 입력과 출력 백만 토큰당 달러 단가입니다. 3:1 토큰 비율을 가정하며 캐시 읽기·쓰기, 서비스 등급, 도구, 재시도, 장문 할증은 제외합니다. 따라서 과업 비용 추정값이 아닙니다. 필요한 값이 없으면 그래프에서 제외하고 상세 정보에 **not reported** 에 해당하는 미공개 표시를 합니다. 0점으로 바꾸지 않습니다.

## 2. 확인한 공개 상태와 평가 스냅샷

모든 모델을 망라한 목록이 아니라 비교 방법을 가르치는 사례 모음입니다. 지수는 백분율이 아닌 **지수 점수** 입니다. 과업당 비용도 평가 기관의 작업량을 기준으로 하므로 서비스 비용과 같지 않습니다. 제한형·프리뷰 시스템에 평가 점수가 있다고 일반 접근이 가능한 것은 아닙니다. 조회한 순위표와 모델별 페이지의 서비스 스냅샷에서 속도 값이 일치하지 않아 속도는 표시하지 않았습니다.

## 3. 최근 공개가 엔지니어링에 미치는 영향

### 호스팅 모델: API 호환성도 출시 조건이다

GPT-6.1 Sol의 문서상 조건은 GPT-6 Sol과 다릅니다. `none` 추론을 지원하지 않으며 도구 호출은 Responses를 사용합니다. 익숙한 엔드포인트 이름이나 같은 토큰 단가만으로 요청 호환성을 판단할 수 없습니다. canary 전에 정확한 모델 ID, 추론 강도, 도구 프로토콜, 공개된 토크나이저 동작, 최대 출력, 오류 처리, 라우팅을 확인합니다. 입력 문맥 한도와 최대 출력은 별도 조건입니다.

Claude 5.5 제품군도 운영상 중요한 차이를 보여 줍니다. 위 Opus·Sonnet의 독립 평가에는 **fallback** 이 포함되어 제공사의 라우팅·안전 정책도 측정 대상이 됩니다. Haiku 5.5는 추론 강도를 조절할 수 있습니다. 현재 공식 개요는 백만 토큰당 입력/출력 단가를 Opus $4/$20, Sonnet $2/$10, Haiku **$0.10/$0.50부터** 로 안내합니다 [[2]](#ref-2). 최저 가격을 모든 모드에 적용하지 말고 이 조건을 보존합니다. 캐시 단가도 별도로 버전 관리해야 합니다. 모델 이름이 그대로여도 출시 당일 문서의 가격은 달라질 수 있습니다.

### 공개 가중치: 실제로 실행할 아티팩트를 확인한다

DeepSeek V4.1 Flash와 GLM-5.3은 공개 모델 저장소가 있습니다. 전자는 아키텍처와 캐시 조건을 바꾸었고, 후자는 텍스트 전용 입력과 항상 켜진 추론을 문서화했습니다. 서로 다른 전환 검사가 필요합니다. 가중치 공개만으로 전체 데이터 혼합이나 재현 가능한 학습법이 공개되는 것은 아니며, 사용할 서빙 엔진의 정밀도·어텐션 상태·채팅 템플릿 지원도 따로 확인해야 합니다.

Kimi K3와 Qwen3.8도 [4.5절](/ko/chapter-4/various-llm-architectures)의 중요한 공개 가중치 사례입니다. 호스팅 제품과 로컬 아티팩트를 구분해야 합니다. Qwen3.8의 로컬 설정은 262,144 위치를 선언하며, 확장·호스팅 문맥 길이는 별도의 위치 스케일링과 서빙 근거가 필요합니다. 이름이 비슷하다는 이유로 호스팅 엔드포인트의 점수나 한도를 다운로드한 체크포인트에 옮기지 않습니다.

### 발표: 미래의 가중치 공개는 현재의 접근이 아니다

Mistral Large 4는 API 프리뷰이며 가중치는 10월 중 추후 공개 예정입니다. Beam도 사전 접근 신청을 받으며 가중치와 기술 자료를 10월 중 나중에 공개하겠다고 발표했습니다. Gemini 4 Argon의 초기 접근은 신뢰받는 사이버 방어 파트너로 제한됩니다. 발표문은 제공사의 주장과 공개 계획의 근거가 되지만, 자체 호스팅 가능한 공개가 완료됐다는 증거는 아닙니다. 특히 Argon이 발표한 1M **출력** 한도를 **입력 문맥** 값으로 넣어서는 안 됩니다.

## 4. 벤치마크 결과에 필요한 재현 기록

공개 결과를 내부 비교에 넣기 전에 다음 조건을 기록합니다.

| 항목 | 필요한 구분 |
|---|---|
| 과업 | 데이터셋·분할·버전·제외 사례·오염 검사 |
| 시스템 | 모델 리비전·제공사 fallback·scaffold·도구·권한 |
| 예산 | 추론 강도·샘플링·시도 횟수·토큰/문맥 한도·timeout·총비용 |
| 채점 | 테스트 또는 judge 리비전·프롬프트/루브릭·집계법 |
| 근거 | 보고일·출처 URL·불확실성·공개된 사례별 결과 |

Terminal-Bench 2.1·3.0·4.0은 별도 평가입니다. SWE-bench Verified·Pro, DeepSWE, 비공개 코딩 평가도 서로 다릅니다. 도구를 쓰는 HLE와 도구 없는 HLE를 같은 계열로 그리지 않습니다. GDPval-AA의 Elo 성격 평점에 %를 붙이지 않습니다. 모델이 같아도 평가 도구, 과업 혼합, 비교 집단이 달라지면 순위가 바뀔 수 있습니다.

## 5. 공개 신호에서 배포 결정으로

품질·과업 비용·p95 지연·장문 동작·배포 통제권·안전을 기준으로 Pareto 후보군을 만듭니다. 이어 같은 내부 프롬프트, 도구 상태, 명시한 예산으로 후보와 기존 시스템을 비교합니다. 달러당·분당 성공 과업, 중요 구간의 실패, 반복 실행의 신뢰도를 측정합니다. 평균 점수가 권한 밖 도구 효과나 심각한 실패를 가려서는 안 됩니다.

API 모델은 제공사의 라우팅과 모델 리비전을 기록하고 별칭 변경을 감지합니다. 로컬 모델은 가중치·토크나이저·템플릿·양자화 scale·커널·분산 구성을 하나의 아티팩트 묶음으로 고정합니다. [17.5절](/ko/chapter-17/production-evaluation-and-release-gates)에 따라 canary와 정상 동작이 확인된 이전 시스템으로의 전환 훈련으로 마무리합니다.
