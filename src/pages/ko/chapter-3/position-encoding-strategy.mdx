# 3.3 위치 인코딩 전략

같은 토큰 세 개를 `dogs chase cats`와 `cats chase dogs` 두 순서로 놓아 봅시다. 첫 문장에서는 개가 고양이를 쫓고, 둘째 문장에서는 고양이가 개를 쫓습니다. 위치 정보나 마스크 없이 모든 토큰을 볼 수 있는 인코더에서 두 명사를 맞바꾸면 어떻게 될까요? 두 명사의 출력 벡터는 서로 자리를 바꾸지만, 가운데 동사 *chase*의 출력 벡터는 그대로입니다. 누가 누구를 쫓는지 구별하려면 어순이 계산에 들어가야 합니다.

## 어순은 어디에서 생길까?

RNN은 단어 하나를 읽을 때마다 상태를 갱신하므로 두 번째 단어를 처리할 때 첫 단어의 정보가 이미 들어 있습니다. 합성곱은 필터의 왼쪽, 가운데, 오른쪽에 서로 다른 가중치를 둡니다. 반면 마스크 없는 셀프 어텐션은 모든 위치에 같은 쿼리·키·값 투영을 적용합니다. 입력의 행 순서를 바꾸면 단어 쌍의 점수와 그 점수가 가리키는 값도 함께 자리를 바꿉니다. 이런 성질을 **순열 등변성** 이라고 합니다. 인과 마스크를 쓰면 각 토큰이 읽을 수 있는 앞선 단어들의 범위가 달라져 이 설명을 그대로 적용할 수 없습니다.

초기 트랜스포머는 첫 인코더·디코더 층에 들어가기 전에 각 토큰 임베딩에 위치 벡터를 더했습니다. *dogs*를 0번 위치에서 2번 위치로 옮기면 단어 임베딩은 같아도 첫 층에 들어가는 벡터는 달라집니다. [[1]](#ref-1)

## 차원 두 개가 공유하는 주파수

$p$는 0부터 시작하는 토큰 위치, $d$는 임베딩 차원 수입니다. 쌍 번호 $i$에 속한 두 차원 $2i$와 $2i+1$은 같은 각주파수 $\omega_i$를 씁니다. 단위는 한 위치당 라디안입니다. $d$가 짝수라면 쌍 번호는 0부터 $d/2-1$까지입니다. [[1]](#ref-1)

$$
\omega_i=10000^{-2i/d},\qquad
PE_{p,2i}=\sin(p\omega_i),\qquad
PE_{p,2i+1}=\cos(p\omega_i).
$$

위치가 0일 때는 모든 쌍의 값이 $(0,1)$입니다. 차원 수를 32로 두고 한 칸 이동해 봅시다. 0번 쌍은 1라디안 회전해 약 $(0.841471,0.540302)$가 됩니다. 16번과 17번 차원으로 이루어진 8번 쌍은 $0.01$라디안만 회전하므로 약 $(0.010000,0.999950)$입니다. 같은 한 칸을 움직여도 첫 번째 쌍은 눈에 띄게 변하고 8번 쌍은 거의 그대로입니다.

## 일정한 간격만큼 이동하면

위치 $p$에서 구한 두 값만으로 $k$칸 뒤의 값을 계산할 수 있을까요? 사인과 코사인의 덧셈 정리를 쓰면 다음 행렬을 얻습니다.

$$
\begin{bmatrix}
\sin((p+k)\omega_i)\\ \cos((p+k)\omega_i)
\end{bmatrix}
=
\begin{bmatrix}
\cos(k\omega_i) & \sin(k\omega_i)\\
-\sin(k\omega_i) & \cos(k\omega_i)
\end{bmatrix}
\begin{bmatrix}
\sin(p\omega_i)\\ \cos(p\omega_i)
\end{bmatrix}.
$$

간격 $k$와 주파수 쌍을 정하면 출발 위치가 어디든 같은 행렬을 곱하면 됩니다. 초기 트랜스포머가 사인과 코사인을 시험한 이유 가운데 하나입니다. 논문의 번역 실험에서는 학습형 위치 임베딩과 사인파 인코딩의 성능이 비슷했습니다. 훈련 때보다 긴 문맥에서도 정답을 찾을 수 있는지는 별도로 평가해야 합니다. [[1]](#ref-1)

## 회전한 쿼리와 키의 내적

위치 $m$에 있는 쿼리의 한 차원 쌍을 $q$, 위치 $n$에 있는 키의 한 차원 쌍을 $k$라 하겠습니다. 이 쌍의 각주파수가 $\theta$일 때 $R_t$는 $t\theta$만큼 회전시키는 행렬입니다. RoPE로 두 벡터를 회전시키면 내적 안에서 두 회전이 하나로 합쳐집니다. [[2]](#ref-2)

$$
(R_m q)^\top(R_n k)=q^\top R_m^\top R_n k=q^\top R_{n-m} k .
$$

회전 전의 쿼리와 키를 고정한 채 두 위치를 $(2,5)$에서 $(9,12)$로 함께 옮겨 보세요. 두 경우 모두 $R_3$을 곱하므로 내적은 같습니다. 키 벡터가 바뀌면 같은 간격에서도 점수가 달라질 수 있습니다. 서비스의 문맥 길이 한도를 늘릴 때는 목표 길이에서 근거 문장의 위치도 바꿔 가며 검색이나 답변 품질을 측정하세요.

### 한 칸 차이가 0칸이나 2칸이 되면

SmolLM2-135M에 `red cat` 두 토큰을 넣고 첫째 층의 0번 헤드를 살펴봅시다. `cat`이 바로 앞의 `red`에 준 가중치는 얼마일까요? 두 토큰에는 위치 ID만 다르게 부여합니다. 토큰을 앞에 덧붙이지 않으므로 모델이 읽는 토큰과 인과 마스크는 그대로입니다. [[5]](#ref-5)

정수 ID를 유지하면 두 위치를 함께 옮겨도 가중치는 이번 CPU 측정에서 33.814% 근처에 머뭅니다. 이번에는 ID를 회전에 쓰기 *전에* BF16으로 바꿨다가 정수로 되돌려 보세요. BF16으로 255와 256은 정확히 나타낼 수 있지만, 256부터 512 사이에서는 짝수만 정확히 나타낼 수 있습니다. 중간값인 257은 256으로 반올림됩니다. 나중에 정수로 바꿔도 사라진 한 칸은 복원되지 않습니다.

시작 위치를 255, 256, 257로 바꿔 보세요. BF16을 거친 두 ID는 차례로 `[255, 256]`, `[256, 256]`, `[256, 258]`입니다. 두 위치의 간격이 1, 0, 2칸이 되면서 가중치도 33.814%, 29.034%, 37.178%로 달라집니다. 모델 가중치와 회전 계산은 두 조건 모두 FP32입니다. ID를 일부러 일찍 반올림해 어디서 정보가 사라지는지 드러낸 실험입니다. 실제로 Transformers에서도 자동 혼합 정밀도 때문에 회전각을 구하는 행렬곱의 정밀도가 낮아지는 문제를 수정했습니다. [[6]](#ref-6)

서빙 코드를 옮길 때는 먼저 같은 두 토큰과 마스크로 시작 위치만 바꿔 보세요. 차이가 커지면 회전 직전 ID와 각도 계산의 자료형을 기록하세요. 긴 문서 검색 품질은 별도로 측정해야 합니다. 위 그래프는 2026-11-25에 PyTorch 2.15.0과 Transformers 5.24.1로 실행한 CPU 결과입니다. <a href={withBasePath('/labs/rope_position_ids.py')} download>CPU 실험 코드 (Python)</a> · <a href={withBasePath('/labs/2026-11/rope-position-ids.json')} download>시작 위치 17개의 측정값 (JSON)</a>

## PyTorch 구현

다음 CPU 예제는 배치 크기 $B$, 시퀀스 길이 $S$, 임베딩 차원 수 $d$인 실수 텐서 $[B,S,d]$에 미리 계산해 둔 위치 벡터를 더합니다. 모든 행의 첫 토큰을 위치 0으로 둡니다. $d$가 홀수이면 마지막에는 사인 차원 하나가 남습니다. 앞에서 구한 이동 행렬은 온전한 두 차원 쌍에 적용됩니다. 캐시에 쌓인 길이가 서로 다른 요청을 한 배치에서 디코딩할 때는 요청별 위치를 따로 넘겨야 합니다.

```python
import math
import torch
from torch import nn

class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=5000):
        super().__init__()
        if d_model < 1 or max_len < 1:
            raise ValueError("d_model and max_len must be positive")
        position = torch.arange(max_len, dtype=torch.float32)[:, None]
        even = torch.arange(0, d_model, 2, dtype=torch.float32)
        angle = position * torch.exp(-math.log(10000.0) * even / d_model)
        table = torch.zeros(max_len, d_model)
        table[:, 0::2] = angle.sin()
        # An odd width has one fewer cosine column.
        table[:, 1::2] = angle[:, :d_model // 2].cos()
        self.register_buffer("pe", table.unsqueeze(0))

    def forward(self, x):
        if x.ndim != 3 or x.size(2) != self.pe.size(2):
            raise ValueError("expected [batch, positions, d_model]")
        if x.size(1) > self.pe.size(1):
            raise ValueError("sequence exceeds max_len")
        return x + self.pe[:, :x.size(1)].to(dtype=x.dtype)

encoder = PositionalEncoding(32, max_len=20)
y = encoder(torch.zeros(2, 20, 32))
torch.testing.assert_close(y[0, 1, :2], torch.tensor([0.841471, 0.540302]))
torch.testing.assert_close(y[0, 1, 16:18], torch.tensor([0.00999983, 0.999950]))
odd = PositionalEncoding(3, max_len=2)(torch.zeros(1, 2, 3))
torch.testing.assert_close(odd[0, 0], torch.tensor([0., 1., 0.]))
```

코드의 검증문은 그림에서 읽은 두 쌍의 값을 재현하고, 차원 수가 홀수인 입력도 확인합니다. 이 인스턴스에 길이 20을 넘는 입력을 넣어 보세요. 사인파는 정의돼 있지만 저장한 표에는 다음 토큰에 해당하는 행이 없습니다.
