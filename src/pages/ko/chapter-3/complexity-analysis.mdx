# 3.5 어텐션 연산량과 KV 캐시 메모리

프롬프트를 4,096토큰에서 8,192토큰으로 늘려 봅시다. 모든 어텐션 점수를 행렬로 저장한다면 그 행렬은 네 배가 되지만, 일반적인 KV 캐시는 두 배만 커집니다. 두 텐서에서 토큰 수가 늘어나는 축이 다르기 때문입니다. [한 층의 바이트 수를 직접 세어 보고](#attention-scores-vs-kv-cache), 프롬프트 전체를 읽을 때와 토큰 하나를 더 생성할 때의 연산을 비교해 봅시다.

## 어떤 연산을 비교하는가

시퀀스 길이는 $n$, 은닉 차원은 $d$, 합성곱 커널 폭은 $k$ 로 둡니다. 우선 상수와 배치 크기는 생략합니다. 원 Transformer의 비교는 이미 투영된 query·key·value에 적용하는 어텐션 핵심 연산을 다룹니다. [[1]](#ref-1)

| 연산 | 주요 연산량 | 주어진 토큰 사이의 순차 의존성 |
|---|---|---|
| 어텐션 핵심 $QK^T$ 와 $AV$ | $O(n^2d)$ | 모든 query를 병렬 처리 가능 |
| Q/K/V/출력 투영 | $O(nd^2)$ | 토큰별 병렬 처리 |
| 밀집 순환 레이어 | $O(nd^2)$ | 순환 단계 $n$ 개 |
| 폭 $k$ 의 밀집 합성곱 | $O(knd^2)$ | 레이어 내부 병렬 처리 |

따라서 어텐션 레이어 비용은 $O(n^2d+nd^2)$ 이고 FFN도 폭에 따른 $O(nd^2)$ 항을 추가합니다. “$n<d$ 이면 어텐션이 저렴하다”는 설명은 핵심 연산만 순환 레이어와 비교한 것입니다. 실제 지연은 상수·커널·메모리 전송에 달려 있습니다.

## 어텐션 비용 유도

헤드 하나의 차원이 $d_h$ 라면 쿼리·키·값의 행렬 모양은 각각 $[n,d_h]$ 입니다. $QK^T$ 를 만들 때 길이 $d_h$ 인 내적을 $n^2$ 번 계산합니다. $[n,n]$ 확률 행렬에 $V$ 를 곱하는 연산량도 같은 차수입니다. 쿼리 헤드가 $H$ 개이고 $d=Hd_h$ 라면, 모든 헤드에서 두 행렬 곱을 수행하는 연산량은 $O(n^2d)$ 입니다. 소프트맥스도 헤드마다 $n^2$ 개의 점수를 읽습니다. 반면 $[n,d]$ 입력에 $[d,d]$ 가중치 행렬을 한 번 곱하는 투영 비용은 $O(nd^2)$ 입니다.

어텐션 한 층은 허용된 query–key 위치를 직접 연결하며 인과 마스크는 과거로 가시 범위를 제한합니다. 일반적인 RNN은 순환 단계를 거쳐 신호를 전달합니다. 합성곱이 먼 위치를 연결하려면 충분한 깊이가 필요합니다. 로그 깊이는 적절한 dilation 구성의 결과이지 임의의 고정 폭 합성곱의 성질은 아닙니다.

## 병렬 prefill과 자기회귀 decode의 차이

교사 강요 학습이나 prefill에서는 입력 토큰이 모두 주어져 query를 함께 계산할 수 있습니다. 표의 상수 개 순차 단계는 이런 시퀀스 수준의 의존성을 뜻하며, 유한한 하드웨어의 실제 실행 시간이 상수라는 뜻은 아닙니다.

자기회귀 decode에서는 다음 토큰이 직전에 생성한 토큰에 의존합니다. KV 캐시를 쓰면 새 query 하나가 저장된 key $n$ 개를 보므로 핵심 어텐션 비용은 $O(nd)$ 이며 투영과 FFN 비용이 더해집니다. 여러 토큰 생성은 여전히 순차 단계가 필요합니다. 일반적인 비선형 RNN은 두 모드 모두 순환 의존성을 가지며, 특수한 상태공간 scan은 20장에서 따로 다룹니다.

## 어텐션 점수가 네 배가 될 때 KV 캐시는 왜 두 배만 커질까?

그룹 쿼리 어텐션(GQA) 한 층에서 요청 하나를 처리한다고 합시다. 쿼리 헤드는 32개, KV 헤드는 8개이고 헤드 하나의 차원은 128입니다. GQA에서는 여러 쿼리 헤드가 같은 키와 값 헤드를 사용합니다 [[4]](#ref-4). 점수·키·값은 모두 원소 하나당 2바이트로 저장한다고 가정합니다.

| 프롬프트 길이 | 프리필의 전체 점수 텐서 한 개 | 디코딩에 쓸 키와 값의 합계 |
| --- | ---: | ---: |
| 4,096토큰 | 1,024 MiB | 16 MiB |
| 8,192토큰 | 4,096 MiB | 32 MiB |

점수 행렬은 쿼리 헤드마다 토큰 하나에 행 하나와 열 하나가 대응합니다. 프롬프트 길이가 두 배가 되면 행과 열이 모두 두 배로 늘어납니다. 반면 캐시에는 새 토큰마다 KV 헤드별로 키 벡터 하나와 값 벡터 하나만 추가합니다. 표의 점수 용량은 마스크로 가린 자리까지 포함해 전체 행렬을 실제로 저장하는 구현을 가정한 값입니다. [FlashAttention](/ko/chapter-7/flash-attention/)은 블록 단위로 계산해 이 행렬 전체를 장치 메모리에 쓰는 일을 피합니다 [[2]](#ref-2). 여러 층과 요청에 남겨 둘 키·값의 합계는 [KV 캐시 계산기](/ko/chapter-12/kv-cache-management/#kv-cache-capacity)에서 구할 수 있습니다.

아래 Python 코드는 텐서를 만들지 않고 모양만으로 원소 수를 셉니다. 가중치, 작업 공간, 패딩, 할당기 부가 비용은 계산에서 제외합니다.

```python
from math import prod

def attention_bytes(tokens):
    # One sequence, one layer. All three tensors store 2-byte elements.
    score_shape = (1, 32, tokens, tokens)
    key_shape = value_shape = (1, 8, tokens, 128)
    return 2 * prod(score_shape), 2 * (prod(key_shape) + prod(value_shape))

for tokens in (4096, 8192):
    scores, kv = attention_bytes(tokens)
    print(tokens, scores // 2**20, kv // 2**20)
# tokens, score MiB, KV MiB
# 4096 1024 16
# 8192 4096 32
```

## 다음 설계 질문

선형 어텐션은 특징 차원을 고정한 조건에서 시퀀스 선형 연산을 목표로 합니다. Reformer의 LSH 어텐션은 대표적으로 $O(n\log n)$ 을 목표로 하므로 모두 선형이라고 묶으면 안 됩니다. 근사 품질·메모리·하드웨어 효율을 함께 평가해야 합니다. 20장은 이 절충을 다룹니다. [[3]](#ref-3)

</details>
