# 4.4 하이브리드 언어 모델과 접두사 언어 모델(Prefix LM)

번역 서비스는 번역문의 첫 단어를 쓰기 전에 원문 전체를 받습니다. 원문을 읽을 때는 문장 끝의 단어가 첫 단어의 뜻을 알려 줄 수 있습니다. 번역문을 쓸 때는 아직 쓰지 않은 단어를 들여다볼 수 없습니다. **접두사 언어 모델(Prefix LM)** 은 하나의 트랜스포머에서 이 두 가지 읽기 규칙을 함께 적용합니다. [[2]](#ref-2)

<a id="the-metaphor-the-guided-storyteller-안내를-받는-이야기꾼"></a>
<a id="prefix-lm-non-causal-attention-on-the-prompt"></a>

## 각 위치에서 어느 토큰을 읽을 수 있을까요?

원문이 P1~P3 세 토큰, 번역문이 T1~T4 네 토큰이라고 합시다. P1은 P3을 읽을 수 있습니다. 그러나 P1에서 T1을 읽을 수 있으면 정답인 번역문이 원문의 표현에 섞여 뒤쪽 층에 전달됩니다. 학습할 때 이미 번역문 전체가 메모리에 올라와 있어도 이 경로는 차단해야 합니다.

질의 위치를 $i$, 키 위치를 $j$, 접두사 길이를 $L_p$ 라 하고, 위치 번호는 1부터 셉니다. $j \le L_p$ 또는 $j \le i$ 이면 해당 키를 읽을 수 있습니다. 모든 행에서 원문 전체를 읽습니다. 번역 구간의 행에서는 지금까지 쓴 번역과 현재 토큰도 읽습니다. 이때 각 행으로 예측하는 것은 **다음 토큰** 입니다. [[2]](#ref-2)

<PrefixMaskFigure lang="ko" />

T1 행을 따라가 보세요. P1, P2, P3, T1 네 곳의 값을 읽어 그다음 토큰인 **T2** 를 예측합니다. 첫 번역 토큰 T1을 예측하는 곳은 이 예제의 마지막 원문 위치인 P3입니다. 대각선이 열려 있어도 정답을 미리 보는 일이 없는 이유가 여기에 있습니다.

## GLM은 이 경계를 어떻게 이용할까요?

초기 GLM은 글에서 단어가 연속된 구간을 몇 군데 골라 지우고 그 자리에 표식을 남깁니다. 빈칸이 든 글이 접두사이고, 지운 구간들을 복원한 내용이 생성 대상입니다. 원문에서는 빈칸 앞뒤를 모두 읽을 수 있습니다. 빈칸을 채우는 동안에는 지금까지 주어진 복원 토큰까지만 읽습니다. GLM은 빈칸을 채우는 순서를 바꿔 학습하며, 원문에서 빈칸이 있던 위치와 그 안에서 몇 번째 토큰을 쓰는지를 따로 기록합니다. 이때 쓰는 위치 정보와 구간 표식은 위 번역 예제에 추가되는 요소입니다. [[1]](#ref-1)

<a id="2-palm의-병렬-하위-레이어는-별도-설계-축"></a>

### PaLM에서 병렬로 계산하는 부분

PaLM은 한 블록 안에서 어텐션과 피드포워드 분기를 병렬로 계산합니다. 이는 층 안의 연산을 어떻게 실행할지에 관한 선택입니다. 토큰끼리 어느 방향으로 정보를 주고받을 수 있는지는 어텐션 마스크가 정합니다. [[4]](#ref-4)

<a id="pytorch-implementation-prefix-mask"></a>

## PyTorch로 미래 토큰이 새어 들어오는지 확인하기

PyTorch의 스케일드 닷 프로덕트 어텐션(SDPA)에서 불리언 마스크의 `True` 는 해당 키를 읽어도 된다는 뜻입니다. 실수형 행렬에 1과 0을 넣어 넘기면 이 숫자는 어텐션 점수에 더해집니다. 이때 0을 더한 키도 소프트맥스 계산에 참여합니다. [[3]](#ref-3)

아래 코드는 CPU에서 패딩이 없는 문장 한 개, 헤드 하나, 위치마다 스칼라 값 하나로 마스크를 검사합니다. 길이가 다른 문장을 묶거나 여러 예제를 이어 붙인다면 유효한 키와 예제 사이의 경계도 마스크에 반영해야 합니다.

```python
import torch
from torch.nn.functional import scaled_dot_product_attention

prefix_len, length = 3, 7
position = torch.arange(length)
query_pos, key_pos = position[:, None], position[None, :]
allowed = (key_pos < prefix_len) | (key_pos <= query_pos)

# [batch, heads, positions, features]
q = k = torch.zeros(1, 1, length, 1)
values = torch.arange(1, length + 1, dtype=q.dtype).view_as(q)

def attend(v, mask):
    return scaled_dot_product_attention(q, k, v, attn_mask=mask, dropout_p=0.0).flatten()

output = attend(values, allowed)
torch.testing.assert_close(output, torch.tensor([2., 2., 2., 2.5, 3., 3.5, 4.]))

changed = values.clone()
changed[0, 0, 4, 0] += 100  # T2
new_output = attend(changed, allowed)
torch.testing.assert_close(new_output[:4], output[:4])
assert new_output[4] > output[4]
```

질의와 키를 모두 0으로 두면 볼 수 있는 위치들의 가중치가 같습니다. T1의 출력은 1, 2, 3, 4의 평균인 2.5입니다. T2의 값을 바꿔도 T1의 출력은 그대로입니다. 미래 값이 새는 문제를 재현하려면 `attend(values, allowed.float())` 와 `attend(changed, allowed.float())` 를 차례로 실행해 보세요. T1의 출력이 약 **3.257** 에서 **10.465** 로 뜁니다. 미래 토큰 하나를 바꾼 영향이 앞선 위치까지 번진 것입니다.

프롬프트 캐시를 재사용할 때도 같은 원리가 적용됩니다. 원문의 끝에 토큰을 추가하면 앞선 원문 위치에서도 새 토큰을 읽을 수 있습니다. 이 경우에는 영향을 받는 원문의 표현을 다시 계산해야 합니다. 번역문만 한 토큰 연장하면 앞선 행에서 볼 수 있는 범위는 그대로입니다.

*한 좌표는 원문에서 어느 빈칸인지를 가리키고, 다른 좌표는 그 구간에서 몇 번째 토큰을 복원하고 있는지를 나타냅니다.*
