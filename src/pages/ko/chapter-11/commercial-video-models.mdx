# 11.6 Commercial Video Models & Future Directions

상용 비디오 생성은 미인 대회가 아니라 통합 문제입니다. 팀은 시간적 일관성, 프롬프트와 참조 이미지 준수, 오디오 타이밍, 편집 가능성, 지연 시간, 가격, 콘텐츠 권리, 안전 제어, 서빙 인터페이스의 안정성을 함께 평가해야 합니다. 멋진 데모는 가능성을 보여 주지만 신뢰할 수 있는 운영 시스템을 증명하지는 않습니다.

아래 클립 생성 비교는 **2026-10-13 기준의 과거 스냅샷** 입니다. 11월 클립 생성 업데이트와 Genie 4 사례는 **2026-11-24 기준** 으로 확인했습니다. 이름, 한도, 가격, 가용성은 빠르게 바뀌므로 구매나 출시 전에 공식 문서를 다시 확인해야 합니다.

---

## 1. 공급자가 공개한 내용

### Google Veo 3.1

Google의 공개 제품 자료는 네이티브 오디오, 참조 기반 제어, 세로형 출력, 해상도 선택, 크리에이터·개발자 제품을 통한 배포를 강조합니다 [[1]](#ref-1). 이는 제품 기능입니다. 인코더의 상세 구조, 학습 데이터 혼합, 파라미터 수, 오디오와 비디오를 정렬하는 메커니즘은 인용한 제품 자료에 **공개되지 않았습니다**.

### OpenAI Sora 2

Sora 2 system card는 동기화된 음성·영상 생성과 안전 평가·완화를 설명합니다 [[2]](#ref-2). 공식 deprecation 일정은 Videos API와 Sora 2 별칭/스냅샷의 API 제거일을 2026-09-24로 명시합니다 [[3]](#ref-3). 따라서 이 스냅샷에서는 사용할 수 있는 API 후보가 아닌 과거 연구·안전 사례로 다룹니다. 연구적 의미·소비자 제품·API 수명 주기는 별도 사실이며 다른 일정으로 변할 수 있습니다.

### ByteDance Seedance 2.5

현재 공식 페이지는 음성·영상 공동 생성, 최대 30초 clip, reference 제어, 편집과 호스팅/API 접근 경로를 설명합니다 [[4]](#ref-4). 이는 시험할 수 있는 제품 주장입니다. 인용한 제품 페이지에는 파라미터 수·정확한 latent 모듈·데이터 혼합·전체 학습법이 **공개되지 않았습니다**. Seedance 2.0의 한도를 물려받는 대신 정확한 제품 리비전과 지역을 평가합니다.

| 질문 | Veo 3.1 | Sora 2 | Seedance 2.5 |
| :--- | :--- | :--- | :--- |
| 공개적으로 강조한 기능 | 네이티브 오디오와 크리에이터 제어 | 동기화된 오디오와 문서화된 안전 제어 | 음성·영상 공동 생성, reference 제어와 편집 |
| 인용 출처의 아키텍처 상세 | 제품 수준 설명 외에는 미공개 | 일부 연구 프레이밍만 공개, 운영 레시피는 미공개 | 통합 접근은 명시, 내부 모듈은 미공개 |
| 운영상 의미 | Google 제품과 quota를 정확히 검증 [[1]](#ref-1) | 2026-09-24 API 제거; 과거 사례 [[3]](#ref-3) | 호스팅/API 리비전·지역·약관 검증 [[4]](#ref-4) |

이 표는 보편적인 승자를 선언하지 않습니다. 공급자 데모의 프롬프트, 편집 도구, 평가자는 서로 호환되지 않습니다.

### 11월 클립 생성 업데이트: Gemini Omni 1.2 Flash

**2026-11-24 기준.** Google의 11월 5일 변경 기록은 `gemini-omni-1.2-flash`를 **출시됨/API 전용, 정식 제공** 으로 명시합니다. 문서화된 작업 흐름은 오디오가 포함된 고정 길이 영상을 생성하거나 대화로 편집합니다. 일반 출력은 3–15초이며, 첫·마지막 프레임 보간과 한 번의 연장은 3–10초입니다. 연장한 전체 영상의 한도는 30초입니다. 모드별 제약을 하나의 “최대 길이”로 뭉뚱그리면 안 됩니다. [[6]](#ref-6) [[10]](#ref-10)

편집 보존·참조 준수·연장 구간의 시간적 일관성은 실시간 제어와 따로 평가합니다. 같은 계열이라는 이유로 이 고정 클립 API와 아래 Genie 4 세션을 서로 바꿔 쓸 수는 없습니다.

## 2. 사내 비디오 평가셋 만들기

하이라이트 영상이 아니라 실제 워크플로의 작업에서 시작합니다. 프롬프트, 입력 자산, 지원되는 경우 seed, 생성 설정, 모델 버전, 원본 출력을 불변 평가 manifest에 기록합니다.

| slice | 측정 대상 | 대표 실패 |
| :--- | :--- | :--- |
| 인물·객체 | 컷 전환과 가림 이후의 참조 준수 | 얼굴, 의상, 글자, 객체의 변화 |
| 움직임·기하 | 시간적 일관성과 접촉의 개연성 | 팔다리 증가, 미끄러짐, 객체 소멸 |
| 오디오·대사 | 사건 타이밍, lip sync, 명료도 | 화면은 맞지만 소리가 늦거나 무관함 |
| 연출 가능성 | 카메라, 길이, 화면비, 편집 반응 | 지시 누락 또는 과도한 반영 |
| 운영 | queue 시간, 생성 시간, 재시도, 비용 | tail latency 급증 또는 조용한 작업 실패 |
| 안전·권리 | 정책 차단, 출처, 동의, 초상 | 위험한 출력 또는 불명확한 재사용 권리 |

좌우 위치를 무작위화한 blind pairwise review를 사용하고 동점과 판단 보류를 기록합니다. 하나의 종합 점수는 출시를 막아야 할 실패를 숨길 수 있으므로, 핵심 slice에는 최소 gate를 두고 신뢰구간을 보고합니다. 사람 평가는 일반 선호 평가자뿐 아니라 대상 편집 워크플로를 이해하는 담당자도 포함해야 합니다.

### Artifact와 rollback 계약

공급자·모델 식별자, API 버전, 요청 schema, 생성 설정, 안전 설정, 프롬프트 템플릿 버전, 입력 자산 hash, 평가 manifest를 고정합니다. 모델 변경은 전체 배포 전에 canary로 검증합니다. 핵심 안전·권리 사례가 실패하거나, 오류율이 관측 구간의 임계값을 넘거나, 지연 시간·비용이 제품 예산을 벗어나면 중단합니다. 공급자나 모델 업데이트를 애플리케이션 재작성 없이 되돌릴 수 있도록 last-known-good routing 설정을 유지합니다.

## 3. 시각적 개연성에서 물리 이해를 추론하지 않기

생성된 영상이 물리적으로 그럴듯해 보여도 개입 조건에서는 실패할 수 있습니다. 가림 일관성, 객체 영속성, 동기화된 소리는 관찰 가능한 행동이지, 명시적 3D scene graph, 물리 시뮬레이터, 공유 잠재 이벤트 모듈의 존재를 증명하지 않습니다.

대신 counterfactual을 시험합니다.

- 카메라 경로만 바꾸고 객체 정체성이 유지되는지 확인합니다.
- 행동을 반대로 바꾸고 인과 순서가 개연성을 유지하는지 확인합니다.
- 재질이나 충격 강도를 바꾸고 움직임과 소리가 함께 변하는지 검사합니다.
- 영상을 연장하고 정체성, 기하, 오디오 타이밍이 언제 무너지는지 측정합니다.
- 같은 뜻의 다른 프롬프트로 반복해 특정 표현에만 성공하는지 찾습니다.

이 테스트는 공개되지 않은 메커니즘을 단정하지 않고 행동을 측정합니다.

## 4. 영상에서 상호작용 환경으로: Genie 4

**2026-11-24 기준.** Genie 4는 10월 연구 프리뷰를 거쳐 11월 18일 이용 자격을 갖춘 Google AI Ultra 구독자에게 배포되기 시작했고, 11월 19일에는 유료 개발자 API로 제공됐습니다. API 변경 기록은 Interactions API(`v1beta`)를 통한 정식 제공을 명시합니다. 따라서 상태는 **출시됨/API 전용** 이며, 이 출처가 공개 가중치를 입증하지는 않습니다. 연구 모델 카드에는 프리뷰 표현이 남아 있지만, 이는 카드 발행 당시의 표현이며 이후 API 출시 사실을 뒤집지 않습니다. [[5]](#ref-5) [[6]](#ref-6) [[7]](#ref-7)

API는 텍스트·참조 이미지·실시간 제어를 받아 동기화된 오디오와 720p, 초당 24프레임 영상을 전송합니다. 문서의 세션 상한은 **120초** 이며, 시각적 일관성과 객체 영속성은 첫 **45–90초** 에 가장 강하다고 설명합니다. 그 구간 내 정확성을 보장한다는 뜻은 아닙니다. 모델 카드는 Gemini Omni Flash와 Gemini 추론을 이용하는 Transformer 기반 시스템이라고 공개하지만, 파라미터 수와 전체 학습 데이터 혼합은 공개하지 않습니다. 장면 변화, 불완전한 물리 상호작용, 글자·공간 오류도 보고합니다. [[7]](#ref-7) [[8]](#ref-8)

여러 경과 시점에서 반복적인 카메라 회전, 가림, 서로 모순되는 중간 지시를 시험합니다. 제어 입력 시각·수신 프레임·오디오 동기화·네트워크 지연·최초 상태 오류를 기록하세요. 120초 연결 한도는 검증된 계획 범위가 아닙니다. 통합 가이드는 연결을 끊어도 서버 생성이 즉시 멈추지는 않는다고 경고하므로, 세션 완료를 명시적으로 요청하고 종료를 확인해야 합니다. [[9]](#ref-9) [20.7절](/chapter-20/path-to-agi-and-world-models/)은 이러한 관찰 가능한 행동을 일반적인 세계 모델링이나 AGI 주장과 구분합니다.

<details>
<summary>Quiz 1: 제품 팀이 공급자 데모만으로 상용 비디오 모델의 순위를 정하면 안 되는 이유는 무엇인가요?</summary>
*프롬프트, 편집 도구, sampling 설정, 선별 과정이 다르기 때문입니다. 호환 가능한 조건에서 품질, 안전, 지연 시간, 비용, 권리를 비교하려면 실제 작업에 맞춘 사내 평가가 필요합니다.*
</details>

<details>
<summary>Quiz 2: 공급자가 모델이 동기화된 오디오를 생성한다고 말할 때 무엇을 결론 내릴 수 있나요?</summary>
*공개 기능은 시험할 수 있습니다. 하지만 그 사실만으로 통합 인코더, 물리 시뮬레이터, 학습 레시피 같은 공개되지 않은 내부 메커니즘을 알 수는 없습니다.*
</details>

<details>
<summary>Quiz 3: 하나의 평균 비디오 품질 점수보다 slice별 release gate가 나은 이유는 무엇인가요?</summary>
*높은 평균이 치명적인 정체성, 안전, 권리, 오디오 실패를 숨길 수 있기 때문입니다. slice 최소 기준은 일부의 중대한 실패가 평균에 묻히지 않게 합니다.*
</details>

<details>
<summary>Quiz 4: interactive world-model 평가는 one-shot 비디오 평가와 무엇이 다른가요?</summary>
*한 영상의 시각 품질뿐 아니라 행동에 따른 상태 변화, 지속성, 제어 가능성, 상호작용 시간이 늘어날 때의 오류 누적을 시험해야 합니다.*
</details>

<details>
<summary>Quiz 5: Genie 4의 120초 세션 한도가 120초 동안 신뢰할 수 있는 시뮬레이션을 뜻하지 않는 이유는 무엇인가요?</summary>
*서빙 한도는 연결 시간을 제한합니다. 상태 일관성은 더 일찍 무너질 수 있으므로 경과 시간에 따른 객체 지속성과 행동 조건부 전이를 시험해야 합니다. 사용을 마치면 서버 세션도 명시적으로 종료합니다.*
</details>
