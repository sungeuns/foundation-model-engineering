# 11.3 통합 멀티모달과 Any-to-Any

이미지를 읽는 모델이 이미지를 생성하는 것은 아닙니다. 음성을 이해해도 텍스트로만 답할 수 있습니다. 따라서 **any-to-any** 는 검사해야 할 역량 표이며, native라는 단어에서 도출할 아키텍처 결론이 아닙니다.

문제는 모달리티 사이의 표현·시간 정렬·목적함수·출력 경로를 조율하는 것입니다. 공동 학습한 시스템에도 전용 encoder·codec·projector·생성 모듈이 남을 수 있습니다.

## 1. 공통 표현이 모달리티 인터페이스를 없애지는 않는다

모달리티 $m$ 의 encoder가 $f_m\in\mathbb R^{B\times S_m\times d_m}$ 을 만든다고 합시다. 투영 $P_m$ 은 폭 $d_m$ 을 공통 폭 $D$ 로 바꾸어 $z_m\in\mathbb R^{B\times S_m\times D}$ 를 만듭니다. $B$ 는 배치 크기, $S_m$ 은 모달리티의 표현 길이입니다. 호환되는 폭은 공동 처리를 가능하게 하지만 backbone hidden dimension 확대나 모든 모달리티에 같은 토크나이저를 요구하지는 않습니다.

이미지 patch 위치·음성 시간·video frame·텍스트 순서는 투영 후에도 복원 가능해야 합니다. tensor 연결은 shape를 설명할 수 있지만 시간 정렬·interleaving·padding mask·교차 모달 학습을 구현하지는 않습니다. 투영 레이어만으로 완전한 멀티모달 모델이 되는 것은 아닙니다.

## 2. 공개된 사례: Qwen2.5-Omni

2025년 Qwen2.5-Omni 보고서는 텍스트·이미지·음성·동영상 입력과 streaming 텍스트·음성 출력을 설명합니다. **Thinker–Talker** 는 텍스트 생성과 자기회귀 audio-token 경로를 구분하며, 시간 정렬 위치 인코딩과 streaming 음성 decoder를 사용합니다 [[1]](#ref-1).

이는 native 통합이 구분 없는 단일 출력 head라는 주장에 대한 좋은 반례입니다. 보고서는 전용 구성 요소가 조율되는 시스템을 공개합니다. 입증한 출력 모드가 임의의 이미지·동영상 생성을 뜻하지는 않으며, 이 메커니즘을 다른 제공사의 미공개 모델에 적용해서도 안 됩니다.

## 3. 10월 업데이트: 세 가지 다른 출력 계약

**2026-10-13 기준.** 모달리티 지원과 생성 모델의 마케팅 분류를 구분합니다.

| 사례 | 입력 계약 | 출력 계약 | 근거의 경계 |
|---|---|---|---|
| Qwen2.5-Omni, 과거 기술 사례 | 텍스트·이미지·음성·동영상 | 텍스트·음성 | 공개된 Thinker–Talker이며 임의 출력 모달리티는 아님 [[1]](#ref-1) |
| DeepSeek V4.1 Flash, 가중치 공개 완료 | native 이미지·텍스트 | 자기회귀 텍스트 | 카드만으로 음성·동영상 생성이 입증되지는 않음 [[2]](#ref-2) |
| EmbeddingGemma 2, 10월 공개 | 공통 멀티모달 표현 | 임베딩 벡터 | 검색 표현과 생성된 미디어는 다름 [[3]](#ref-3) |

지원 조합·streaming·시간 정보·입력 한도·정확한 API/로컬 아티팩트도 표에 넣어야 합니다. 음성 지원은 인식·생성·임베딩 또는 이들의 조합일 수 있습니다. 필요한 경로를 각각 검사하고 누락된 기능은 미보고로 남깁니다.

## 4. 시간·서빙 계약

live 음성·동영상에는 사용 가능한 출력까지의 전체 지연, chunk 경계, 동기화 drift, buffering, 취소, 중단 후 복구를 측정합니다. 음성 처리 시간은 음성 응답 지연과 같지 않습니다. frame sampling은 짧은 사건을 놓칠 수 있고 겉보기 정렬이 맞아도 인과적으로 중요한 순서를 잃을 수 있습니다.

모달리티 encoder·표현 확장·backbone prefill/decode·실제로 공개된 codec/diffusion decoder·메모리 전송·도구 orchestration을 별도 계산합니다. 짧은 텍스트 요청에 긴 녹음이 붙으면 표현·처리 비용이 커질 수 있습니다. 공통 문맥이 모든 모달리티를 똑같이 저렴하게 만들지는 않습니다.

캐시 ID에는 전처리, encoder/토크나이저 리비전, sample rate/frame 정책, 위치 정렬, dtype/scale, 모델 리비전을 넣습니다. 음성 chunking·이미지 resizing 변경 후 같은 접두사를 재사용하면 호환되지 않는 상태가 복원될 수 있습니다. 처리량뿐 아니라 cold/복원 실행도 검증합니다.

## 5. 학습·평가·출시

입력 checkpoint, 각 토크나이저/encoder/codec, 고유 채팅 템플릿, 모달리티 목적·가중치, 데이터 manifest, 라이선스/동의, PII/비밀 처리, sample ID·shard hash를 고정합니다. 관련 녹음·clip·문서·대화·합성 변형을 묶어 분할하고 평가 자산·의미 이웃을 격리합니다.

학습률·모달리티 혼합·시퀀스/표현 길이·정밀도·sharding·재계산·응답 cap·reference ID 또는 명시적 미사용을 밝힙니다. 텍스트/도구 SFT에는 BOS/EOS·`add_generation_prompt`·잘림·padding·assistant 구간 mask·packing 격리를 확인합니다. 음성/동영상 target에는 자체 유효 frame/token mask와 정렬된 conditioning이 필요합니다. 입력 녹음을 assistant 텍스트 응답처럼 취급하지 않습니다.

파라미터·gradient·optimizer·activation·임시 버퍼·collective·checkpoint·평가 자원을 분리합니다. 토큰/frame 정규화 학습/검증 손실, 도메인·모달리티 구간, 정렬 drift, nonfinite/overflow, gradient/activation norm, 처리량, MFU, 데이터 대기, collective/straggler, 재구성 가능한 batch ID를 관측합니다. 수치 실패·drift·역량 유지·위험 출력·비용/지연 악화의 pause/abort 경계를 책임자·관측 구간과 함께 사전에 정합니다.

sharded 모델/optimizer·scheduler·scaler/FP8 상태·step/노출 수·RNG·sampler/정확한 데이터 커서·모든 구성 요소/config/data hash를 checkpoint합니다. checksum·완료 표식으로 원자적 게시를 수행하고 보존·원격 복제·world-size 제한·복원 훈련·학습 연속성 검사를 정합니다. 구성 요소/템플릿/도구/안전 불변 묶음은 도메인·기존 역량 유지·안전·형식/도구·지연·비용·오류 조건을 짝지은 불확실성이나 근거 있는 표본 수로 통과한 뒤 출시합니다. 일부만 출력한 미디어와 session 상태까지 rollback을 훈련합니다.

## 6. 실무적 결론

특정 아티팩트가 필요한 시간·품질 조건에서 어느 모달리티를 입력받고 출력할 수 있는지가 핵심입니다. 공동 학습은 전용 모듈을 유지하면서 조율을 개선할 수 있습니다. 전체 경로를 검증하고 공개되지 않은 아키텍처·데이터 혼합·학습 세부사항은 **미공개** 로 남깁니다.
