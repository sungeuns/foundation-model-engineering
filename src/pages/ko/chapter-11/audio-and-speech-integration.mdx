# 11.2 오디오와 음성 통합

음성에는 단어뿐 아니라 시간·화자 특성·운율·배경음이 담깁니다. 전사는 유용한 표현이지만 텍스트만 넘기는 인터페이스는 명시적으로 담지 않은 정보를 보통 잃습니다. 그렇다고 모든 cascade가 비언어적 정보를 전부 버려야 하는 것은 아닙니다. 타임스탬프·화자 라벨·별도 음향 특징을 보존할 수 있습니다.

엔지니어링 선택은 신호를 어디서 압축하고 시간 구조를 어디까지 유지할지에 관한 것입니다. Native 오디오 인터페이스는 일부 인계 비용을 줄이는 대신 스트리밍·정렬·중단 문제를 새로 만듭니다.

## 1. 파형·프레임·토큰 속도

16 kHz 단일 채널 파형에는 초당 16,000개의 샘플이 있습니다. 저장 dtype은 별도의 선택입니다. 인코더는 이를 더 낮은 속도의 프레임으로 바꾸고, 신경 코덱은 프레임을 이산 인덱스로 바꿀 수 있습니다. 음향 프레임 속도와 직렬화한 토큰 속도는 다릅니다.

초당 프레임 수 $F$, 코드북 수 $Q$에서 단순 직렬 예측은 초당 $FQ$번의 토큰 결정을 요구합니다. 인덱스마다 $N$개 후보가 있다면 고정 길이 인덱스의 이상적 payload는 초당 $FQ\log_2N$비트입니다. 프레이밍·엔트로피 코딩은 제외합니다. $F=50$, $Q=8$, $N=1024$이면 초당 인덱스 400개, 4,000비트입니다. 지연 배치나 병렬 코드북 예측은 이 명목 payload를 유지하면서 직렬 단계를 바꿀 수 있습니다.

## 2. 잔차 벡터 양자화

인코딩된 프레임 $x\in\mathbb R^d$에서 잔차를 $r_1=x$로 시작합니다. 단계 $q$의 코드북 $C_q$에는 $d$차원 벡터 $N$개가 있습니다.

$$
i_q=\arg\min_{i\in\{1,\ldots,N\}}\|r_q-C_q[i]\|_2^2,\qquad
r_{q+1}=r_q-C_q[i_q],\qquad
\hat x=\sum_{q=1}^{Q}C_q[i_q].
$$

$i_q$는 선택한 인덱스, $\hat x$는 복원한 특징 프레임입니다. 후속 단계는 잔차를 모델링하지만 특정 의미 범주를 맡는다고 보장되지는 않습니다. 잔차 norm이 줄어드는지도 코드북과 학습에 달려 있으며 임의의 무작위 코드북을 추가한다고 자동으로 성립하지는 않습니다.

> **교육용 순전파 예제:** 학습되지 않은 최근접 코드북 lookup이며, 학습된 음성 코덱이나 smoke test한 학습 파이프라인이 아닙니다. 파형 encoder/decoder, commitment loss, straight-through 또는 EMA 학습, 사용되지 않는 코드 관리, 가변 길이 마스크, 분산 동기화, 혼합 정밀도 안정성을 생략합니다. 무작위 특징의 출력은 텐서 모양만 설명하며 알아들을 수 있는 음성이나 복원 품질을 보여 주지 않습니다.

```python
import torch
import torch.nn as nn

class ResidualVectorQuantizer(nn.Module):
    def __init__(self, num_quantizers=8, codebook_size=1024, dim=128):
        """
        Args:
            num_quantizers: Number of cascaded codebooks (Q)
            codebook_size: Number of vectors per codebook (N)
            dim: Dimension of each vector (d)
        """
        super().__init__()
        self.num_quantizers = num_quantizers
        self.codebooks = nn.ParameterList([
            nn.Parameter(torch.randn(codebook_size, dim))
            for _ in range(num_quantizers)
        ])

    def forward(self, x):
        # x shape: [batch_size, seq_len, dim]
        residual = x
        quantized_out = torch.zeros_like(x)
        token_indices = []

        for i in range(self.num_quantizers):
            codebook = self.codebooks[i]

            # Compute squared L2 distance: x^2 + y^2 - 2xy
            # residual^2: [batch, seq, 1]
            # codebook^2: [codebook_size]
            # matmul: [batch, seq, codebook_size]
            dist = (
                residual.pow(2).sum(dim=-1, keepdim=True)
                + codebook.pow(2).sum(dim=-1)
                - 2 * torch.matmul(residual, codebook.t())
            )

            # Find index of the closest codebook vector
            indices = torch.argmin(dist, dim=-1) # [batch_size, seq_len]
            token_indices.append(indices)

            # Lookup quantized vectors and accumulate
            quantized = codebook[indices]
            quantized_out += quantized

            # Update residual for the next quantizer stage
            residual = residual - quantized

        # token_indices shape: [batch_size, num_quantizers, seq_len]
        return quantized_out, torch.stack(token_indices, dim=1)

# Example execution simulating a 50Hz audio frame rate
batch_size = 2
seq_len = 50 # 1 second of audio
dim = 128

dummy_audio_features = torch.randn(batch_size, seq_len, dim)
rvq = ResidualVectorQuantizer(num_quantizers=8, codebook_size=1024, dim=128)
reconstructed, indices = rvq(dummy_audio_features)

print(f"Original features: {dummy_audio_features.shape}")
print(f"Reconstructed features: {reconstructed.shape}")
print(f"Token indices shape: {indices.shape}")
# Output: -> 8 tokens per frame
```

## 3. 이산·연속 오디오 모델링

AudioLM은 의미·음향 표현을 계층적으로 분리합니다 [[1]](#ref-1). VALL-E는 텍스트와 화자 프롬프트를 조건으로 코덱 언어 모델링을 연구합니다 [[2]](#ref-2). AudioPaLM은 텍스트·음성 표현을 결합해 음성 과제를 지원합니다 [[3]](#ref-3). 메커니즘은 서로 다르며, 오디오 제품명만으로 제공사가 어느 구조를 쓰는지 알 수는 없습니다.

CALM은 consistency 기반 다음 프레임 생성기와 자기회귀 연속 오디오 잠재 표현을 연구합니다 [[4]](#ref-4). 이산 양자화를 없애도 VAE가 무손실이 되거나 모든 오류가 없어지지는 않습니다. 연속 모델이 항상 낫다고 단정하지 말고 과제·하드웨어 조건을 맞춰 충실도·명료도·시간적 안정성·지연·연산을 비교합니다.

텍스트 토큰화는 토크나이저와 전체 입력이 고정되면 결정적이지만, 한 단어도 공백이나 주변 텍스트에 따라 다르게 나뉠 수 있습니다. 음향 토큰의 변화 역시 파형과 인코더 문맥에 달려 있습니다. 어느 관찰만으로 한 표현은 문맥과 무관하다거나 이산 예측은 실패할 수밖에 없다고 할 수는 없습니다.

## 4. 10월 API 사례: 목소리와 행동 시점은 별도 계약이다

**2026-10-18 기준**, OpenAI의 10월 16일 API 업데이트는 GPT-Live에 설명으로 생성하는 목소리와 natural voice 9개를 추가합니다. 10월 15일에는 입력·출력 전사 delta가 도착하는 동안 판단할 수 있는 native Decisions 통합이 추가됐습니다 [[5]](#ref-5) [[6]](#ref-6). 문서화된 API 기능이며 코덱·파라미터 수·학습 데이터 혼합을 공개한 것은 아닙니다.

실무적으로는 목소리 식별자·오디오 세션·행동 정책을 따로 버전 관리해야 합니다. 전사 prefix는 수정·중단·취소될 수 있습니다. “오십—아니 십오를 이체해”에서 초기 판단이 금액과 권한 확정 전에 취소 불가능한 이체로 이어지면 안 됩니다. 잠정 판단, 취소 ID, 중복 억제, 독립 실행 검사를 사용합니다. 목소리가 바뀌어도 행동의 권한 경계는 달라지지 않아야 합니다.

## 5. 스트리밍 평가와 핵심 정리

처음 들리는 출력까지의 시간, 청크 간 공백, 전체 응답 지연, 중단 감지·정지 시간, 전사 수정 안정성, 도구 행동 정확성, 완료한 대화당 비용을 측정합니다. 잡음·억양·언어 전환·겹치는 화자·무음·연결 해제와 재연결을 평가합니다. 단어 오류율뿐 아니라 명료도와 사람의 청취 검사도 사용합니다. 전사가 맞아도 음성 상호작용은 나쁠 수 있습니다.

모델·endpoint 리비전, 공개된 코덱·전처리, 샘플링 주파수·채널 규약, voice ID, 템플릿, 생성 설정, 도구 스키마, 안전·행동 정책을 불변 묶음으로 유지합니다. 시험 오디오와 화자는 적응 학습 데이터에서 격리합니다. 새 목소리·스트리밍 설정은 같은 대화로 canary 평가하고, 중요 행동 오류와 지원 언어 slice를 출시 기준으로 삼으며, 세션 상태와 대기 중인 행동의 롤백을 연습합니다.

오디오 통합은 표현과 상태 관리의 결합 문제입니다. 다음 절은 하나의 공유 인코더나 제한 없는 출력을 가정하지 않고 이를 여러 모달리티로 확장합니다.
