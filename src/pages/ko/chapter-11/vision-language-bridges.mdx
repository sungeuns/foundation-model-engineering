# 11.1 비전–언어 모델: CLIP·프로젝터·교차 어텐션

**비전–언어 모델** 은 이미지 표현과 언어를 연결합니다. 연결 방식에 따라 출력도 달라집니다. CLIP은 이미지와 주어진 설명이 얼마나 잘 맞는지 점수를 계산하고, 생성 모델은 이미지 특징을 조건으로 언어 디코더가 답변을 만듭니다. 이때 서로 다른 표현을 연결하는 인터페이스가 **비전–언어 브리지** 입니다.

영수증 사진을 예로 들어 봅시다. “이 사진들에서 영수증을 찾아라”는 이미지와 텍스트의 유사도로 해결할 수 있습니다. “합계는 얼마이며 어느 줄에 쓰여 있는가?”에 답하려면 이미지 속 내용을 읽고 근거에 맞는 답변을 생성해야 합니다. CLIP 이미지 인코더를 재사용하는 것만으로 유사도 점수가 이런 답변으로 바뀌지는 않습니다.

| 인터페이스 | 구체적인 입력 → 출력 | 언어 모델에 전달되는 것 |
| :--- | :--- | :--- |
| CLIP 듀얼 인코더 | 이미지와 후보 설명 → 유사도 점수 | 생성용 디코더가 필요하지 않음 |
| 프로젝터 + 디코더 | 이미지 특징 시퀀스와 질문 → 답변 토큰 | 투영된 이미지 특징이 디코더 시퀀스의 자리를 차지 |
| 리샘플러 + 교차 어텐션 | 이미지 특징과 질문 → 답변 토큰 | 텍스트 상태가 별도의 시각 메모리를 조회 |

먼저 [시각 토큰 계산기](#visual-token-budget)에서 같은 224픽셀 이미지가 어디에 배치되는지 비교한 뒤, 아래의 원리를 따라가 보세요.

## 1. CLIP: 이미지와 설명의 짝을 학습하기

CLIP은 짝지어진 이미지와 텍스트로 두 인코더를 학습합니다. 각 인코더의 출력을 공통 차원으로 투영하고 길이가 1이 되도록 정규화하여, 비교에 사용할 임베딩 하나씩을 얻습니다. 원 논문은 양방향 대조 학습 손실을 사용하며 로짓의 크기도 학습합니다 [[1]](#ref-1).

배치에 $B$ 개의 이미지–텍스트 쌍이 있고 공통 임베딩 차원이 $d$ 라고 합시다. 이미지 $i$ 와 설명 $j$ 의 정규화된 임베딩을 $v_i,t_j\in\mathbb R^d$ 로 쓰겠습니다. 코사인 유사도 $C$ 와 온도로 조정한 로짓 $Z$ 를 구분하면 다음과 같습니다.

$$
C_{ij}=v_i^\top t_j,\qquad Z_{ij}=C_{ij}/\tau,\qquad \tau>0.
$$

두 임베딩 배열의 형태는 각각 $[B,d]$ 이고 비교 행렬은 $[B,B]$ 입니다. 두 배열의 짝 순서를 맞췄으므로 정답 쌍은 대각선에 놓입니다. 이미지별 행에서는 맞는 설명을, 설명별 열에서는 맞는 이미지를 분류합니다.

$$
\begin{aligned}
\mathcal L_{i\to t}&=-\frac1B\sum_{i=1}^{B}\log\frac{\exp Z_{ii}}{\sum_{j=1}^{B}\exp Z_{ij}},\\[0.5em]
\mathcal L_{t\to i}&=-\frac1B\sum_{j=1}^{B}\log\frac{\exp Z_{jj}}{\sum_{i=1}^{B}\exp Z_{ij}}.
\end{aligned}
$$

$$
\mathcal L_{\mathrm{CLIP}}=\tfrac12(\mathcal L_{i\to t}+\mathcal L_{t\to i}).
$$

대각선 밖의 항목은 **음성 예제로 가정한 쌍** 이지, 반드시 틀린 설명은 아닙니다. 두 사진이 같은 장면을 담을 수도 있고, 두 설명이 한 이미지에 모두 맞을 수도 있습니다. 중복이나 복수의 정답 설명을 다루려면 샘플링 정책이나 여러 양성 쌍을 허용하는 손실을 설계해야 합니다. 온도를 낮추면 softmax 분포가 뾰족해지지만, 고정된 임베딩의 최근접 이웃 순위는 바뀌지 않습니다.

### PyTorch로 손실만 구현하기

> **교육용 손실 구현:** 입력은 형태 $[B,d]$, dtype, 기기, 짝 순서가 서로 맞는 0이 아닌 이미지·텍스트 임베딩입니다. 정규화, 양수인 학습 가능 스케일, 양방향 손실을 보여줍니다. 인코더, 분산 환경의 음성 예제 수집, 복수 양성 타깃, 혼합 정밀도 안정화, 학습·체크포인트 루프는 생략했습니다. 완전한 CLIP 학습기는 아닙니다.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class CLIPLoss(nn.Module):
    def __init__(self, init_temperature=0.07):
        super().__init__()
        if init_temperature <= 0:
            raise ValueError("Temperature must be positive")
        self.logit_scale = nn.Parameter(torch.tensor(1.0 / init_temperature).log())

    def forward(self, image_embeddings, text_embeddings):
        # Inputs: [batch_size, embed_dim]; paired rows have equal indices.
        image_embeddings = F.normalize(image_embeddings, p=2, dim=-1)
        text_embeddings = F.normalize(text_embeddings, p=2, dim=-1)
        batch_size = image_embeddings.size(0)
        logits = torch.matmul(image_embeddings, text_embeddings.t()) * self.logit_scale.exp()
        labels = torch.arange(batch_size, device=image_embeddings.device)
        loss_i = F.cross_entropy(logits, labels)
        loss_t = F.cross_entropy(logits.t(), labels)
        return (loss_i + loss_t) / 2
```

### 모델 다운로드 없이 실행하는 짝 맞추기 실험

> **예제의 범위:** 다음 코드는 Python 3 표준 라이브러리와 직접 만든 단위 벡터 세 개만 사용합니다. CPU에서 Python 실수로 순위와 손실을 계산하며, 픽셀을 읽거나 인코더를 학습하지 않습니다. 온도는 $0.2$ 로 고정합니다. 두 번째 경우에는 일부러 정답이 대각선에 있다는 가정을 깨뜨려 데이터의 짝이 어긋나는 버그를 드러냅니다.

```python
from math import exp, isclose, log

def contrastive_logits(images, texts, temperature=0.2):
    # This exercise supplies unit vectors; no encoder or normalization here.
    return [[sum(a * b for a, b in zip(image, text)) / temperature
             for text in texts] for image in images]

def diagonal_cross_entropy(rows):
    losses = []
    for target, row in enumerate(rows):
        peak = max(row)
        log_partition = peak + log(sum(exp(x - peak) for x in row))
        losses.append(log_partition - row[target])
    return sum(losses) / len(losses)

def symmetric_loss(logits):
    columns = list(zip(*logits))
    return (diagonal_cross_entropy(logits)
            + diagonal_cross_entropy(columns)) / 2

def top_matches(rows):
    return [max(range(len(row)), key=row.__getitem__) for row in rows]

images = [(1., 0., 0.), (0., 1., 0.), (0., 0., 1.)]
paired = images.copy()
shuffled = [paired[2], paired[0], paired[1]]
good = contrastive_logits(images, paired)
bad = contrastive_logits(images, shuffled)

print("paired image-to-text:", top_matches(good))
print("shuffled image-to-text:", top_matches(bad))
print("shuffled text-to-image:", top_matches(list(zip(*bad))))
print(f"paired loss: {symmetric_loss(good):.6f}")
print(f"shuffled diagonal-target loss: {symmetric_loss(bad):.6f}")

assert top_matches(good) == [0, 1, 2]
assert top_matches(bad) == [1, 2, 0]
assert top_matches(list(zip(*bad))) == [2, 0, 1]
assert isclose(symmetric_loss(good), log(1 + 2 * exp(-5)))
assert isclose(symmetric_loss(bad) - symmetric_loss(good), 5.0)
```

예상 손실은 각각 `0.013386`, `5.013386`입니다. 설명의 위치가 바뀌었다고 임베딩이 나빠진 것이 아닙니다. 정답 위치가 틀려진 것입니다. 인코더를 의심하기 전에 짝 순서를 복원하거나 양방향 정답 인덱스를 다시 지정해야 합니다. 무작위 임베딩의 손실 값만 출력해서는 이런 데이터 파이프라인 오류를 발견하기 어렵습니다.

## 2. 프로젝터: 이미지 특징을 디코더 시퀀스에 넣기

답변을 생성하려면 CLIP 검색에 쓰는 전역 임베딩 하나와 구분하여 **공간 특징의 시퀀스** 를 유지합니다. 원래 LLaVA 아키텍처는 CLIP ViT의 격자 특징을 선형 투영으로 언어 모델의 임베딩 차원에 맞춥니다 [[3]](#ref-3).

이미지 특징 수를 $P$, 비전 인코더의 특징 차원을 $d_v$, 언어 모델의 특징 차원을 $d_\ell$ 이라고 합시다. 배치 크기가 $B$ 이고 텍스트 위치가 $T$ 개일 때 선형 프로젝터의 입출력 형태는 다음과 같습니다.

$$
\begin{aligned}
H_v&\in\mathbb R^{B\times P\times d_v},\\
W&\in\mathbb R^{d_v\times d_\ell},\\
X_v&=H_vW\in\mathbb R^{B\times P\times d_\ell}.
\end{aligned}
$$

$$
X_{\mathrm{input}}=[X_v;X_{\mathrm{text}}]
\in\mathbb R^{B\times(P+T)\times d_\ell}.
$$

대괄호는 시퀀스 축으로 이어 붙인다는 뜻입니다. 여기서는 이미지 뒤에 텍스트가 오는 순서로 그렸지만, 구현에 따라 지정된 이미지 표시 위치에 특징을 삽입할 수도 있습니다. 선형 변환을 MLP로 바꾸어도 이 입출력 구조는 유지할 수 있습니다. 시각 벡터는 연속적인 입력이며, 텍스트 토크나이저가 출력하는 어휘 ID가 아닙니다.

가상의 형태 예제를 계산해 보겠습니다. $[1,256,768]$ 이미지 특징을 4,096차원으로 투영하면 $[1,256,4096]$ 이 됩니다. 여기에 텍스트 32자리를 더하면 $[1,288,4096]$ 입니다. 프로젝터가 바꾼 것은 **특징의 개수가 아니라 차원** 입니다. 연결 모듈 자체가 작아도 디코더 입력이 길어져 연산 비용이 커질 수 있습니다.

어느 가중치를 고정할지는 별도의 선택입니다. 원래 LLaVA는 특징 정렬 단계에서 프로젝터만 학습하고, 인스트럭션 튜닝 단계에서는 비전 인코더를 고정한 채 프로젝터와 언어 모델을 함께 학습합니다 [[3]](#ref-3). 프로젝터를 사용한다고 해서 프로젝터만 학습하는 것은 아닙니다.

## 3. 교차 어텐션: 텍스트 옆에 시각 메모리 두기

Flamingo는 고정된 비전·언어 백본을 학습 가능한 Perceiver Resampler와 게이트 교차 어텐션 블록으로 연결합니다. 원래 비전 인코더는 ViT 패치 인코더가 아니라 NFNet입니다. 리샘플러는 학습 가능한 쿼리로 공간·시공간 특징을 이미지 또는 비디오당 시각 잠재 벡터 64개로 바꾸고, 언어 모델에 추가된 블록이 이를 조회합니다 [[2]](#ref-2).

이미지 한 장의 인터페이스를 $[B,P,d_v]\to[B,K,d_m]$ 으로 나타낼 수 있습니다. $K$ 는 리샘플링한 메모리 길이이고 $d_m$ 은 특징 차원입니다. 텍스트 쿼리의 위치 수는 여전히 $T$ 입니다. 교차 어텐션은 텍스트와 메모리를 호환되는 query/key/value 차원으로 투영하고, 텍스트 상태와 같은 형태의 갱신 값을 만듭니다. 메모리 슬롯 $K$ 개를 **디코더의 자기 어텐션 시퀀스 뒤에 붙이는 것이 아닙니다**.

게이트가 적용되는 어텐션 분기 하나를 단순화하면 다음과 같습니다.

$$
y=x+\tanh(\alpha)\,\mathrm{CrossAttend}(x,M).
$$

$x$ 와 $y$ 는 텍스트 상태, $M$ 은 시각 메모리, $\alpha$ 는 0으로 초기화하는 학습 가능한 스칼라입니다. 이 식에는 블록의 피드포워드 분기를 생략했습니다. 초기에는 추가 분기의 기여가 0이지만, 게이트와 다른 학습 모듈이 바뀐 뒤에도 언어 능력이 유지된다는 보장은 없습니다. Flamingo는 각 텍스트 위치가 직접 교차 어텐션으로 읽을 수 있는 대상을 가장 최근의 앞선 이미지·비디오로 제한합니다. 이전 이미지의 정보는 텍스트 자기 어텐션을 통해 남아 있을 수 있습니다 [[2]](#ref-2).

두 설계 모두 여러 이미지를 다루는 방식은 이미지 순서, 표시 토큰, 마스크, 위치 인코딩, 학습 데이터에 달려 있습니다. 이어 붙이기를 쓴다고 이미지 한 장으로 제한되지는 않으며, 교차 어텐션을 쓴다고 이미지 간 비교가 정확해지는 것도 아닙니다.

## 4. 시각 토큰 예산 직접 계산하기

두 방식을 같은 조건에서 계산해 봅시다. $14\times14$ 픽셀 패치 하나가 특징 하나를 만들고, 추가 분류 토큰·크롭·패치 병합은 없다고 가정합니다. 정사각형 이미지 한 변의 픽셀 수를 $s$, 이미지 수를 $m$ 이라고 하겠습니다. 이미지 표시 토큰까지 포함한 텍스트 위치 수는 $T=32$ 입니다.

$$
P=(s/14)^2,\qquad S_{\mathrm{projector}}=T+mP.
$$

$224\times224$ 이미지 한 장이면 $P=16^2=256$ 이므로 디코더 시퀀스는 288자리입니다. 가로·세로를 모두 두 배로 늘리면 $P=32^2=1024$, 시퀀스는 1,056자리가 됩니다. 헤드 하나의 밀집 어텐션 점수 행렬은 $288^2=82{,}944$ 항목에서 $1056^2=1{,}115{,}136$ 항목으로 약 $13.4\times$ 커집니다. 이는 인과 마스크를 적용하기 전 전체 행렬의 항목 수입니다. 실측 지연 시간이나 GPU 메모리 비율이 아니며, 효율적인 커널은 이 행렬 전체를 메모리에 만들지 않을 수 있습니다.

다른 경로에서는 이미지당 메모리 슬롯을 $K=64$ 개로 리샘플링합니다. 디코더 시퀀스는 32자리를 유지하고, 별도 메모리가 $64m$ 슬롯을 담습니다. 모든 슬롯을 대상으로 하는 텍스트–메모리 어텐션 행렬은 헤드당 $T(mK)$ 항목이며, 이미지별 마스크로 실제 참조 대상을 제한할 수 있습니다. 인코더와 리샘플러는 여전히 입력 특징을 처리하고, 교차 어텐션에도 별도의 투영·층·캐시 비용이 듭니다. 메모리 길이가 고정되어도 고해상도 입력 처리 비용이 사라지지는 않습니다.

아래에서 해상도와 이미지 수를 바꾸어 보세요. 특징이 어디에 배치되는지 비교하기 위해 같은 예제 패치 격자를 두 경로에 적용했습니다. Flamingo의 NFNet을 재현하거나 출시 모델의 성능을 비교하는 실험은 아닙니다.

영수증을 읽는 모델이라면 시각 예산을 줄이기 전에 작은 글씨의 합계와 세부 항목을 검사해야 합니다. “영수증이다”라는 큰 범주는 보존하면서 정답에 필요한 숫자는 잃을 수 있기 때문입니다. 이 관계를 측정할 때 이미지 전처리, 크롭 수, 프롬프트, 디코딩, 채점 기준을 고정하세요. 시각 토큰을 이어 붙이는 방식에서는 늘어난 위치를 [KV 캐시 예산](../../chapter-12/kv-cache-management/)에 포함해야 합니다. 별도의 교차 어텐션 메모리는 따로 계산합니다.

## 5. 브리지가 어떤 정보를 보존하는지 검사하기

연결 모듈이나 시각 예산을 바꾸기 전에 작은 영수증 테스트를 만들어 봅시다. 직접 만든 영수증 A에는 `Total 31.50`, B에는 `Total 42.00`이라는 줄을 넣습니다. 원본 이미지, 이미지 ID, 프롬프트, 전처리 설정, 정답 줄을 함께 보관합니다. 이는 제안하는 진단 실험이며, 실제 모델의 측정 결과가 아닙니다.

두 작업을 따로 실행하세요. 이미지–텍스트 유사도로 “영수증 사진”이라는 설명과 고정된 다른 문서 설명들의 순위를 비교하고, 생성 모델에는 인쇄된 합계와 그 근거 줄을 답하게 합니다. 큰 범주를 올바르게 검색했다는 사실만으로 시각 인터페이스가 숫자까지 보존했다고 볼 수는 없습니다.

| 통제해서 바꿀 입력 | 확인할 동작 |
| :--- | :--- |
| 원본 영수증 A | 영수증 설명을 검색하고 `31.50`과 근거 줄 `Total 31.50`을 답하는지 확인 |
| 합계 줄을 흐리게 만들거나 잘라내기 | 큰 범주 검색이 유지되는지 기록하고, 보이는 근거를 지어내지 않고 줄을 읽을 수 없거나 줄이 없다고 답하는지 확인 |
| 질문은 그대로 두고 A를 B로 교체 | 답이 `42.00`으로 바뀌고 B의 합계 줄을 근거로 드는지 확인 |
| A·B 표시를 붙여 두 장을 주고 순서를 뒤집기 | 영수증 A를 묻는 질문에는 계속 A를 인용하는지 확인. 표시와 실제 첨부 이미지의 대응은 유지 |

이 입력과 디코딩 설정을 고정하고 시각 예산만 바꾸어 봅니다. 검색 정확도와 정확한 금액 응답률, 올바른 근거 줄 인용률, 적절한 답변 보류 비율을 구분해 보고하세요. 첫 토큰 지연과 최대 메모리도 측정합니다. 이 작은 진단에서는 근거 줄을 하나라도 지어내면 더 큰 평가에 앞서 조사할 실패로 봅니다. 몇 개의 예제를 통과했다고 출시 기준을 만족한 것은 아닙니다.

적응 학습이 필요하면 [SFT 절차](../../chapter-9/sft-fundamentals/)의 학습 계약을 적용하세요. 멀티모달에서 특히 확인할 것은 이미지 프로세서와 특징을 뽑는 층, 모델 고유 채팅 템플릿의 이미지 표시자, 잘라내기 이후 이미지–답변 대응, 답변 손실에서 시각 위치를 제외하는 처리입니다. LM 가중치를 고정하면 그래디언트·옵티마이저 상태가 줄지만, 앞단 프로젝터를 학습하려면 LM을 거쳐 역전파하고 활성값을 보관해야 할 수 있습니다. 이 평가용 영수증은 학습에 넣지 말고, 더 큰 규모의 배포 판단에는 [평가와 출시 기준](../../chapter-17/production-evaluation-and-release-gates/)을 사용하세요.

## 연구 점검: 시각 인코더의 어떤 부분이 도움이 될까?

**As of 2026-11-25.** *Unbundling Multimodal Vision Encoding*은 선행 시각 사전 학습, 시각 전용 용량, 그 용량이 백본에 들어가는 위치를 분리합니다. 전체 생애 연산량을 맞춘 통제 실험에서 공동 학습한 시각 용량은 사전 학습 인코더에 필적할 수 있었고, 전용 용량 자체를 없애면 시각 이해가 떨어졌습니다 [[4]](#ref-4). 실험한 조건에 대한 근거이지, 모든 규모와 데이터 예산에서 사전 학습 인코더가 불필요하다는 증거는 아닙니다.

이 결과를 조사하려면 같은 데이터에서 사전 학습 인코더, 같은 크기의 공동 학습 인코더, 용량을 맞춘 인코더 없는 모델을 비교합니다. 한 예산에는 선행 사전 학습 비용을 포함하고 인코더를 재사용하는 경우는 따로 보고하세요. 시각 토큰화와 평가 조건을 명시하고, 시각 질의응답뿐 아니라 언어 능력 보존과 첫 토큰 지연도 측정합니다. 서로 다른 출시 모델을 비교하는 것만으로는 이 요인을 분리할 수 없습니다.

필요한 출력에 따라 인터페이스를 고르고, 그 인터페이스가 추가하는 특징 수를 계산한 뒤 어떤 세부 정보가 보존되는지 검사하세요. 검색 점수, 디코더 위치, 교차 어텐션 메모리 슬롯은 모두 “이미지 임베딩”이라고 불리더라도 서로 다른 역할을 합니다.

## Quizzes

<details>
<summary>Quiz 1: 내적이 대칭인데도 CLIP에 양방향 손실이 필요한 이유는 무엇인가요?</summary>
*두 벡터의 순서를 바꾸어도 내적 하나는 같지만, 이미지–텍스트 행과 텍스트–이미지 열은 서로 다른 후보 집합으로 정규화합니다. 양방향 모두 올바른 짝의 정답 인덱스가 필요합니다. 어느 손실도 그 자체로 텍스트 생성기를 만들지는 않습니다.*
</details>

<details>
<summary>Quiz 2: 예제에서 설명 순서를 섞으면 왜 손실이 정확히 5 늘어나나요?</summary>
*온도가 0.2일 때 각 행·열에는 로짓 5 하나와 0 두 개가 있습니다. 순서를 바꾸어도 로그 정규화 항은 같지만, 모든 대각선 타깃의 로짓이 5에서 0으로 바뀝니다. 임베딩끼리의 대응은 그대로인데 각 크로스 엔트로피가 5씩 커지는 것입니다.*
</details>

<details>
<summary>Quiz 3: 특징 256개의 차원을 768에서 4,096으로 투영하면 시각 토큰 예산이 줄어드나요?</summary>
*아닙니다. 위치별 투영은 특징 차원을 바꾸며 256자리 자체는 유지합니다. 예제에서는 텍스트 32자리와 합쳐 디코더 시퀀스가 288자리가 됩니다. 풀링, 병합, 리샘플링은 별도 연산입니다.*
</details>

<details>
<summary>Quiz 4: 한 변이 448픽셀인 이미지 두 장에서 예제의 두 경로는 어떻게 다른가요?</summary>
*이미지마다 패치가 1,024개입니다. 이어 붙이면 디코더 위치는 $32+2\times1024=2080$ 개입니다. 이미지당 64슬롯으로 리샘플링하면 별도 메모리는 128슬롯이고 텍스트 시퀀스는 32자리를 유지합니다. 이 수만으로 지연 비율이나 같은 정확도를 주장할 수는 없습니다.*
</details>

<details>
<summary>Quiz 5: 고정된 LM과 0으로 초기화한 시각 게이트가 능력 보존을 보장하나요?</summary>
*아닙니다. 0인 게이트는 초기에 추가 분기의 기여를 없애지만, 학습한 게이트와 시각 조건은 베이스 가중치가 고정되어 있어도 출력을 바꿀 수 있습니다. 적응 후 언어 능력과 시각적 근거에 맞는 응답을 평가해야 합니다. 가중치 고정이 역전파에 필요한 활성값 메모리까지 모두 없애는 것도 아닙니다.*
</details>
