# 14.2 벡터 인덱싱과 데이터베이스 솔루션

임베딩을 정했다면 지연·메모리 예산 안에서 유용한 이웃을 찾는 방법을 골라야 합니다. 정확 검색은 품질 기준선이며 배칭이나 선택성이 높은 필터 아래 실용적일 수 있습니다. 근사 최근접 이웃(ANN) 인덱스는 작업 부하에 따른 재현율 절충으로 검색량을 줄입니다. 인덱스 이름만으로 밀리초 미만 지연이나 무시할 만한 재현율 손실이 보장되지는 않습니다.

## 1. 정확 검색 기준선부터

차원 $d$ 의 벡터 $N$ 개를 순회하면 좌표 계산량은 $O(Nd)$ 입니다. 실제 지연은 메모리 트래픽·거리 척도·배칭·하드웨어·동시성에도 달려 있습니다. 차원 768인 FP32 벡터 10억 개는 벡터만 $N d\times4=3.072$ TB이며 식별자·복제본·메타데이터·임시 버퍼는 별도입니다.

접근이 허용된 표본 코퍼스에서 정확한 top-k를 구해 ANN 재현율을 정의하고, 임베딩 이웃이 유용한지는 사람의 관련성 레이블로 평가하세요. 높은 ANN 재현율은 정확한 거리 검색과의 일치일 뿐 임베딩·근거 최신성·답변 품질의 검증은 아닙니다.

## 2. HNSW: 계층과 후보 예산

HNSW는 최하단에 모든 벡터를 두고 위로 갈수록 벡터 수가 줄어드는 중첩 근접 그래프를 만듭니다 [[1]](#ref-1). 최하단도 완전 연결 밀집 그래프가 아니라 희소 연결입니다. 상위 계층으로 유망한 영역에 접근한 뒤 하단에서 후보 집합을 제한해 탐색합니다.

구축과 질의 파라미터를 구분하세요. `M`은 연결도·그래프 메모리, `efConstruction`은 구축량·그래프 품질, `efSearch`는 질의 탐색 예산에 영향을 줍니다. 예산을 높이면 재현율이 좋아질 수 있지만 거리 계산·지연도 늘어납니다. 삭제·필터·데이터 군집·삽입 순서·차원이 곡선을 바꿉니다. 관측된 로그 규모 확장은 모든 데이터·설정의 최악 복잡도 보장이 아닙니다.

아래 실험은 실제 그려진 이웃 간선을 따라가며 마지막 노드를 전수 검색의 최근접 노드와 비교합니다. 고정 장난감 그래프와 greedy 탐색을 사용하고 HNSW 삽입·이웃 선택 휴리스틱·efSearch 큐는 생략합니다. 계층 하강·국소 탐색의 이해를 위한 것이며 데이터베이스 벤치마크가 아닙니다.

## 3. 양자화·IVF·ScaNN

인덱스 메커니즘은 조합할 수 있습니다. 그래프와 양자화는 상호 배타적인 범주가 아닙니다.

| 메커니즘 | 바꾸는 것 | 측정할 엔지니어링 비용 |
|---|---|---|
| Flat 정확 순회 | 모든 적격 벡터 평가 | 벡터 트래픽·배칭·후보 규모 |
| HNSW 그래프 | 연결된 후보 이웃 방문 | 그래프 간선·구축·탐색·갱신 동작 |
| IVF 분할 | 선택한 거친 군집 검색 | 학습·군집 불균형·probe 수·군집 누락 |
| Product quantization(PQ) | 전체 벡터 대신 코드북 인덱스 저장 | 코드북·근사 거리·선택적 정확 재평가 |
| ScaNN 계열 | 점수에 맞춘 양자화와 검색 단계 결합 | 학습·점수/재평가 예산·하드웨어·거리 척도 |

Guo 등의 비등방성 양자화는 큰 내적 점수를 더 잘 보존하도록 재구성 오차의 성분에 다른 페널티를 줍니다 [[2]](#ref-2). 벡터 방향을 보존하면 항상 순위가 유지된다는 설명보다 구체적입니다. 정규화하지 않은 최대 내적 검색에서는 크기도 중요합니다. 적절히 정규화할 때 코사인과 내적이 동등해집니다. 어느 알고리즘이 항상 빠르다고 선언하지 말고 같은 재현율·처리량 조건의 전체 시스템을 비교하세요.

저장 예제로 PQ가 부분 공간 $M=96$ 개와 중심 256개를 쓰면 부분 공간당 8비트, 벡터당 코드 96바이트입니다. 100만 벡터의 코드는 96 MB입니다. 차원 768·FP32 코드북이면 중심은 $96\times256\times8\times4=786{,}432$ 바이트를 더 씁니다. 식별자·거친 중심·그래프 간선·정렬·메타데이터·복제본·원본 벡터 재평가는 별도입니다. 코드 크기의 감소율과 서비스 전체 메모리 감소율은 다릅니다.

## 4. 필터는 검색과 권한의 일부

관련성 높은 인사 문서도 권한 없는 사용자에게 전달하면 안 됩니다. 테넌트·ACL 버전·보존/삭제 상태를 원본과 모든 파생 표현에 연결하세요. 메타데이터 필드만으로 권한이 강제되지는 않습니다. 검색 서비스는 콘텐츠·발췌·캐시·로그가 보이기 전에 정책을 검사·적용해야 합니다.

고정 ANN 후보 목록을 나중에 필터링하면 적격 결과가 부족해질 수 있습니다. 적격 노드로만 이동하게 하면 그래프 경로가 끊길 수 있습니다. 구현은 콘텐츠를 반환하지 않고 비적격 노드를 경유하거나 필터 인지 간선·필터링한 정확 순회·적응 검색 계획을 사용할 수 있습니다. Qdrant의 논의는 특정 구현의 방법을 보여 줄 뿐 모든 데이터베이스가 같은 필터 알고리즘을 쓴다는 근거는 아닙니다 [[4]](#ref-4).

낮고 높은 선택성의 필터에서 **적격 집합 안의 재현율**, 결과 충족도·지연·정보 누출을 평가하세요. 권한 거부·오래된 ACL 캐시·테넌트 격리·삭제·복제본·복원 스냅샷을 시험합니다. 정확한 top-k여도 권한 없는 근거를 포함하면 실패한 검색 시스템입니다.

## 5. 인덱스에서 서비스로

**2026-10-25 기준**, FAISS 유지관리자의 선택 가이드는 학습·저장·검색량 같은 제약으로 정확·그래프·분할·압축 방식을 구분합니다 [[3]](#ref-3). 라이브러리는 알고리즘을 제공하며 관리형/자체 운영 서비스에는 내구성·동시 갱신·필터·백업/복원·관측성이 추가로 필요합니다. 제품명만으로 이런 보장이 성립하지 않습니다.

목표 코퍼스·질의 분포·차원·거리·배치·동시 부하·하드웨어·필터·갱신량을 기준으로 벤치마크하세요. 인덱스 버전·구축 시드/순서·임베딩/토크나이저·거리 설정·검색 파라미터를 기록합니다. 재현율–지연 곡선, p50/p95/p99, 구축 시간, 복제본을 포함한 메모리·저장, 수집 지연, 삭제 문서 노출, 오류율을 보고합니다. 가능하면 필터링한 정확 검색도 기준선에 포함하세요.

새 인덱스는 shadow 경로와 버전이 있는 전환으로 승격합니다. 대응 품질 근거·핵심 권한/삭제 게이트·명시적 중단 임계값을 가진 담당자가 필요합니다. 정상 경로를 남기고 삭제 tombstone을 유지하는 복원·롤백을 연습하세요. 14.3절에서는 검색 신호를 결합하고 후보에 재순위화 계산을 사용합니다.
