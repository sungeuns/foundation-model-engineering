# 14.1 어휘 검색에서 시맨틱 검색으로

고객센터에 문의가 두 건 들어왔습니다. 첫 고객은 *타이어 펑크*라고 썼는데 정비 매뉴얼의 제목은 *바퀴 구멍 수선*입니다. 두 번째 고객은 제품 등록 코드 `XJ-992-B`만 보냈습니다. 첫 문의에서는 표현이 달라도 같은 문제를 찾는 능력이, 두 번째에서는 코드 한 글자까지 보존하는 능력이 중요합니다. 검색 증강 생성(RAG)에서는 이 단계에서 골라낸 문단이 답변에 인용할 수 있는 근거가 됩니다.

## 1. 키워드 검색의 한계

### A. 동의어 문제 (Vocabulary Mismatch)

어휘 색인은 어떤 단어가 어느 문서에 나오는지 기록합니다. *타이어*, *펑크*, *바퀴*, *구멍*을 각각 다른 단어로 취급하면 질의와 제목에 겹치는 단어가 없어 BM25 점수는 0입니다. 동의어 사전으로 해결할 수도 있습니다. 그러려면 독자가 실제로 쓰는 표현이 사전에 들어 있어야 합니다.

### B. 다의어 (Context Blindness)

*은행*이라는 질의만으로는 금융 기관을 찾는지 열매를 찾는지 알기 어렵습니다. *대출*을 덧붙이면 어휘 검색에서도 벡터 검색에서도 순위가 달라질 수 있습니다. 질문 자체가 모호하면 표현 방식만 바꿔도 모호함은 남습니다.

### C. 교차 언어(Cross-Lingual)의 한계

한국어 문의와 영문 설명서에 겹치는 단어가 하나도 없을 수 있습니다. 번역이나 다국어 인코더가 둘을 이어 줍니다. 한편 제품 번호는 색인을 만들 때 온전한 검색 단위로 보관하면 언어가 달라도 바로 일치합니다.

### D. 해결책: Vector Embeddings

밀집 검색기는 질의와 문단을 벡터로 바꾸는 방법을 학습합니다. Karpukhin 등의 연구에서는 질의 인코더와 문단 인코더를 따로 두고, 답을 담은 문단과의 내적이 경쟁 문단과의 내적보다 커지도록 학습했습니다 [[3]](#ref-3). 처음 보는 표현 두 개가 실제로 가까워지는지는 평가 데이터로 확인해야 합니다.

## 2. 인터랙티브 개념: Lexical vs. Semantic Search

고객센터 문서 제목 네 개에 두 가지 점수를 매겨 봅시다. **BM25** 는 제목에 등장한 검색어를 기준으로 계산합니다. **코사인 유사도** 에 쓰는 벡터는 바퀴·등록·학습과 관련된 단어가 각각 몇 번 나오는지 센 값입니다. 실습의 단어 목록을 펼치면 어떤 단어가 어느 좌표에 들어가는지 볼 수 있습니다. 학습된 검색기는 데이터에서 표현을 익힙니다. 여기서는 손으로 검산할 수 있도록 단어 목록을 직접 정했습니다.

*등록 XJ-992-B*를 검색하면 어느 제목이 앞설까요? A와 B는 모두 등록을 다루지만 제품 코드가 들어 있는 제목은 B뿐입니다. 아래 표에서 두 점수를 비교해 보세요. 예제 링크를 복사하면 같은 검색을 다시 열 수 있고, 언어를 바꿔도 해당 예제로 이어집니다. 직접 입력한 검색어는 현재 탭에만 남습니다.

### 키워드의 보루: 특정 정보에 대한 정밀도

[제품 코드 예제](#lexical-product-code)에서 두 제목에 공통으로 나오는 *등록*보다 BM25 점수를 더 크게 올리는 단어는 드물게 등장하는 코드입니다. 실습에서 쓰는 역문서 빈도는 제목 $N$개 중 검색어가 $f$개에 나올 때 $\mathrm{IDF}(f)=\ln(1+(N-f+0.5)/(f+0.5))$입니다 [[4]](#ref-4). BM25의 $k_1=1.2$는 단어 반복에 따른 점수 증가 폭을, $b=0.75$는 문서 길이 보정의 강도를 정합니다. 질의에서 중복된 단어는 한 번만 반영합니다. 제목 길이를 $L$, 평균 제목 길이를 $\overline L$, 제목 안에서의 해당 단어 빈도를 $\mathrm{tf}$라고 합시다. 이 예제는 제목이 모두 세 단어이고 같은 단어가 반복되지 않아, 일치하는 단어의 빈도·길이 보정 계수 $(k_1+1)\,\mathrm{tf}/(\mathrm{tf}+k_1(1-b+bL/\overline L))$가 1입니다.

A의 점수는 $\mathrm{IDF}(2)=0.693$입니다. B는 여기에 $\mathrm{IDF}(1)=1.204$를 더해 **1.897** 점을 얻습니다(소수 셋째 자리로 반올림). 두 문서의 주제 벡터는 같아 코사인은 모두 1입니다. 코드만 검색하면 어휘 검색에서는 여전히 B가 나옵니다. 주제 사전에는 코드가 없어 질의 벡터의 길이가 0이 되고 코사인을 계산할 수 없습니다. 표에서 ‘—’가 바로 이 경우입니다. 실습은 영문을 소문자로 통일하고 단어 안의 하이픈은 보존합니다. 어간 추출이나 형태소 분석은 하지 않습니다.

[*타이어 펑크* 예제](#lexical-paraphrase)에서는 상황이 달라집니다. 두 단어 모두 제목에 없어 BM25 점수는 네 문서 모두 0입니다. 하지만 질의와 C의 제목 *바퀴 구멍 수선*은 벡터의 방향이 같아 코사인은 1입니다. *타이어 등록*을 직접 입력하면 두 좌표 중 바퀴 좌표만 겹쳐 C와의 코사인이 $2/(\sqrt{2}\times 2)\approx0.707$로 낮아집니다.

**파이썬으로 검산하기.** 위의 네 제목에서 센 단어 빈도와 표준 라이브러리만 있으면 점수를 재현할 수 있습니다.

```python
from math import hypot, isclose, log1p

# Four three-token titles. Each matched term occurs once, so its BM25
# contribution here is its inverse document frequency.
def idf(df):
    return log1p((4 - df + 0.5) / (df + 0.5))

def cosine(q, d):
    norm = hypot(*q) * hypot(*d)
    return sum(a * b for a, b in zip(q, d)) / norm if norm else None

general = idf(2)
specific = idf(2) + idf(1)
print(round(general, 3), round(specific, 3))  # 0.693 1.897
assert isclose(cosine([1, 1, 0], [2, 0, 0]), 2**-0.5)
assert cosine([0, 0, 0], [0, 1, 0]) is None
```

고객센터 검색을 평가할 때는 같은 뜻을 바꿔 쓴 문의와 코드만 들어온 문의를 따로 모으고, 답을 담은 문단을 표시해 두세요. 같은 수의 후보를 뽑았을 때 각 검색기가 그 문단을 몇 번이나 포함하는지 비교합니다. [14.3절의 순위 결합 실습](../advanced-retrieval/#rrf-candidate-cutoff)에서는 두 검색기가 모두 후보에서 뺀 문단을 재순위화 단계에서도 되살릴 수 없는 이유를 살펴봅니다.

## 3. 고급 청킹(Chunking) 전략

### A. 단순 (Fixed-Size) Chunking

매뉴얼의 한 문단 끝에 *XJ-992-B*가 나오고 초기화 절차는 다음 문단에 적혀 있다고 해 봅시다. 256토큰 단위로 자르면 코드와 절차 사이가 갈라질 수 있습니다. 청크를 20토큰씩 겹쳐도 필요한 내용이 경계에 걸쳐 있으면 놓칩니다. 실제로 반환된 구간을 확인하세요.

### B. 계층적 (Hierarchical) Chunking

절마다 요약을 색인하고, 요약으로 먼저 고른 절 안에서 문단을 찾을 수 있습니다. 올바른 절을 고르면 문단을 일일이 검색하는 비용을 아낍니다. 반대로 요약에서 빠진 세부 사항 때문에 처음부터 다른 절을 고르면 해당 문단에는 점수도 매겨지지 않습니다.

### C. 부모-자식 (Parent-Child / Small-to-Large) Chunking

코드가 나오는 짧은 문단을 색인한 뒤, 검색된 문단의 원문 ID로 상위 절을 찾아 생성기에 전달할 수 있습니다. 이때 일치한 구간, 문서 버전, 열람 권한을 함께 보존하세요. 관련 문단을 찾은 비율과 최종 문맥에 절차가 끝까지 들어간 비율을 따로 측정하면, 검색에는 성공했는데 답변에 필요한 내용이 잘린 사례를 포착할 수 있습니다.

## 4. 의미 공간의 수학 (InfoNCE 및 Matryoshka)

### 대조 학습과 InfoNCE 손실

질의와 문단을 짝지어 $N$개 모은 배치를 생각해 봅시다. 질의 $q_i$의 정답 문단을 $d_i$로 표시했다면 배치 안의 다른 문단 $d_j$와 비교할 수 있습니다. 유사도 함수가 $s$이고 온도 $\tau$가 양수일 때 대조 손실을 다음과 같이 정의할 수 있습니다.

$$
\mathcal L=-\frac1N\sum_{i=1}^N\log\frac{\exp(s(q_i,d_i)/\tau)}{\sum_{j=1}^N\exp(s(q_i,d_j)/\tau)}.
$$

소프트맥스는 질의 하나를 기준으로 배치 안 문단들의 점수를 정규화합니다. 다른 문단에도 답이 들어 있는데 이를 오답으로 취급하면 학습 신호가 어긋납니다. 배치를 만들 때 레이블과 유사 문단의 중복을 확인하세요. Dense Passage Retrieval 연구는 같은 배치에서 뽑은 오답과 어휘 검색기가 찾은 까다로운 오답 문단을 실험했습니다 [[3]](#ref-3).

### Matryoshka Representation Learning (MRL)

Matryoshka 학습은 벡터의 맨 앞에서부터 여러 길이로 자른 표현 각각에 학습 목표를 부여합니다 [[1]](#ref-1). 정밀도가 같을 때 768개 좌표 중 앞의 128개만 남기면 좌표 저장 공간이 6분의 1로 줄어듭니다. 아무 임베딩이나 자르면 중요한 좌표가 잘릴 수 있습니다. 여러 길이로 학습한 모델도 지원하는 차원별로 검색 품질을 측정하고, 자른 뒤에는 모델이 요구하는 정규화를 적용하세요.
