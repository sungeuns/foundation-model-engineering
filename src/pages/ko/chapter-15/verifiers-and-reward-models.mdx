# 15.4 검증기와 보상 모델

여러 후보를 만드는 것이 유용하려면 올바른 작업과 그럴듯한 실수를 구분할 수 있어야 합니다. 검증기는 측정 도구와 비슷합니다. 출력 점수만큼 오류, 확률 보정과 적용 범위가 중요합니다. 탐색은 약한 검증기를 공략할 수 있으므로 생성기와 선택기를 함께 평가해야 합니다.

## 1. 결과 감독과 과정 감독

**결과 보상 모델(ORM)** 은 완성된 결과에 대한 감독을 받습니다. 입력에는 최종 답뿐 아니라 풀이 전체가 포함될 수 있으며 점수도 반드시 이진 값이나 $[0,1]$ 범위일 필요는 없습니다. 최종 레이블 하나로는 앞선 어떤 단계가 실패를 일으켰는지 알기 어렵습니다.

**과정 보상 모델(PRM)** 은 중간 단계에 붙은 레이블을 사용합니다. *Let's Verify Step by Step*은 이 구분을 연구하고 단계별 주석을 제공합니다. [[1]](#ref-1) 낮은 과정 점수로 가지를 제거할 수 있지만 점수도 틀릴 수 있습니다. 과도한 가지치기는 낯설지만 올바른 풀이를 버릴 수 있습니다. 구분자의 토큰화와 주석 정책이 한 단계의 범위를 정합니다.

### 단계 마스크를 사용하는 채점 예제

> **완전한 학습기가 아닌 교육용 모듈입니다.** 호출자는 호환되는 인과적 백본, 모델 고유 채팅 템플릿의 토큰, 어텐션 마스크, 응답 단계 경계를 같은 장치에 제공해야 합니다. 프롬프트·패딩·레이블 없는 단계는 `step_mask`에서 false여야 합니다. 인덱스는 BOS/EOS와 길이 제한을 처리한 토큰 시퀀스를 가리킵니다. 패킹한 대화에는 분리된 어텐션과 대화 내부의 유효 경계가 필요합니다. 이 이진 손실은 3분류 주석, 분산 전역 정규화나 확률 보정을 구현하지 않습니다.

```python
import torch
from torch import nn

class ProcessRewardModel(nn.Module):
    def __init__(self, base_llm, hidden_size):
        super().__init__()
        self.base_llm = base_llm
        self.score_head = nn.Linear(hidden_size, 1)

    def forward(self, input_ids, attention_mask, step_end_indices, step_mask):
        # [B,S], [B,S], [B,K], [B,K]. Invalid step indices may be -1.
        B, S = input_ids.shape
        if S == 0 or attention_mask.shape != input_ids.shape:
            raise ValueError("nonempty sequences and matching attention mask required")
        if step_end_indices.shape != step_mask.shape or step_mask.shape[0] != B:
            raise ValueError("step boundary/mask shape mismatch")
        valid = step_mask.bool()
        if ((step_end_indices[valid] < 0) | (step_end_indices[valid] >= S)).any():
            raise ValueError("valid step boundary outside sequence")
        indices = step_end_indices.clamp(0, S-1)
        rows = torch.arange(B, device=input_ids.device)[:, None]
        if not attention_mask[rows, indices][valid].bool().all():
            raise ValueError("step boundary points to padding")
        outputs = self.base_llm(input_ids=input_ids, attention_mask=attention_mask,
                                output_hidden_states=True, use_cache=False)
        hidden = outputs.hidden_states[-1][rows, indices]
        # Co-locate the head and base model before use; respect head dtype.
        logits = self.score_head(hidden.to(self.score_head.weight.dtype)).squeeze(-1).float()
        return logits, valid

def masked_step_loss(logits, labels, valid):
    if not valid.any():
        raise ValueError("batch has no labeled response steps")
    if labels.shape != logits.shape:
        raise ValueError("labels/logits shape mismatch")
    targets = labels[valid].float()
    if not torch.isfinite(targets).all() or ((targets < 0) | (targets > 1)).any():
        raise ValueError("this binary example requires targets in [0,1]")
    return nn.functional.binary_cross_entropy_with_logits(logits[valid], targets)
```

헤드는 로짓을 반환합니다. Sigmoid를 적용하면 $[0,1]$ 이 되지만 정확성에 대해 보정된 확률이 되지는 않습니다. 미노출 데이터에서 신뢰도를 검사하고 잘못된 승인과 거절의 비용에 맞춰 임계값을 정합니다.

## 2. 생성형 검증

GenRM은 토큰 예측으로 검증을 표현하며, 판정 전에 추론을 생성하는 변형도 연구합니다. [[2]](#ref-2) 근거 생성은 순차 연산을 추가할 뿐 판정의 정확성을 증명하지 않습니다. 직접 분류하는 모델도 은닉 상태에서 계산합니다.

같은 토큰·시간 예산에서 판별 점수, 직접 생성한 판정, 근거를 먼저 생성한 검증을 비교합니다. 정답 누출, 위치·장황함 편향, 판정의 오류 상관관계, 설득력 있게 작성된 오답을 검사합니다. 근거를 여러 번 샘플링해도 같은 실수를 반복할 수 있습니다. 아래 인터랙션은 학습된 검증기의 평가가 아니라 미리 작성한 예제입니다.

## 3. SCoRe: 모델 자신의 궤적으로 수정 행동 학습하기

SCoRe는 두 학습 단계를 사용합니다. 1단계에서는 첫 시도의 분포가 참조 모델 근처에 머물도록 강한 KL 벌점을 주면서 두 번째 시도를 개선합니다. 2단계에서는 두 시도를 모두 최적화하며 두 번째 보상에 정답 여부의 변화에 따른 보너스를 더합니다. [[3]](#ref-3) 시도 $i$ 의 이진 정답 여부를 $r_i$ 라 하면 보너스는 $b_2=\alpha(r_2-r_1)$ 이고 $\alpha>0$ 입니다. 이는 **전체 목적함수는 아닙니다.** 기본 보상과 참조 정규화가 남습니다.

이 논문은 분포 불일치와 교정 행동의 붕괴를 연구합니다. 모든 SFT가 실패하거나 모든 수정 작업에 RL이 필요함을 증명하지는 않습니다. 오답→정답, 정답→오답 전이를 첫 시도 품질과 전체 비용과 함께 따로 측정합니다.

## 4. 데이터와 학습 계약

결정적 검사기는 제한된 작업의 결과를 채점할 수 있지만 모든 중간 문장을 검증하지는 않습니다. 교사의 비평도 정답이 아닌 주석 후보입니다. 작업 ID, 출처·라이선스, 교사·판정 모델 버전, 프롬프트, 생성 설정, 시드, 거절 이유와 사람의 감사 결과를 보존합니다. 관련 문제와 합성 변형은 군집화한 뒤 분할하고 평가 프롬프트·채점 기준·변형을 격리합니다.

학습 시 베이스 모델, 토크나이저·템플릿, 헤드, 레이블, 참조 체크포인트 또는 참조 없음, 최대 응답 길이, 단계 정책, 손실 집계, 옵티마이저, 학습률과 클래스 가중치를 고정합니다. 학습·서빙 템플릿 일치와 길이 제한을 확인하고 단계 수·도메인·레이블 출처별 성능을 보고합니다. 정밀도·샤딩·재계산 설정에 맞춰 파라미터, 기울기, 옵티마이저 상태, 활성값, 임시 버퍼, 집단 통신, 체크포인트와 평가 비용을 구분합니다.

보조 LM 손실을 사용한다면 토큰 정규화 손실을, 그 밖에 레이블 단계 손실, 확률 보정, 오승인·오거절, 비유한 값 수, 기울기·활성값 norm, 처리량, MFU, 데이터 대기와 느린 작업자를 재구성 가능한 배치 ID와 함께 관측합니다. 수치·품질 중단 기준은 학습 전에 정합니다. 모델·헤드, 옵티마이저, 스케줄러·스케일러, RNG, 샘플러·데이터 커서, 데이터·설정 해시를 체크섬과 완료 표시로 원자적으로 저장하고 복원·롤백을 연습합니다.

독립적인 도메인, 능력 유지, 안전성, 형식·도구, 지연 시간, 비용과 오류율 기준을 불확실성 추정과 함께 통과해야 릴리스합니다. 마지막 정상 아티팩트 묶음과 측정 가능한 롤백 기준을 유지합니다. 탐색이 검증기 점수에 따라 후보를 선택하기 시작한 뒤에도 다시 평가해야 합니다. 선택이 검증기가 만나는 오류의 분포를 바꾸기 때문입니다.

## 5. 실무적 정리

탐지할 실패에 맞춰 감독의 세밀함과 채점 방식을 선택합니다. 결과 레이블, 과정 판정과 생성된 설명은 구분해서 다룹니다. 다음 장에서는 행동과 도구의 부수 효과가 추가되므로 신뢰할 수 있는 평가와 복구가 더 중요해집니다.

<details>
<summary>Quiz 5: 쌍별 보상 손실의 기울기는 무엇인가요?</summary>
*$d=r_\theta(x,y_w)-r_\theta(x,y_l)$, $\mathcal L=-\log\sigma(d)$ 라고 하고 $y_w$ 를 선호 비교의 승자라고 합시다. 그러면 $\nabla_\theta\mathcal L=(\sigma(d)-1)(\nabla_\theta r_\theta(x,y_w)-\nabla_\theta r_\theta(x,y_l))$ 입니다. 이 선호 순위 목적함수는 위 코드의 단계 레이블 BCE와 다릅니다.*
</details>
