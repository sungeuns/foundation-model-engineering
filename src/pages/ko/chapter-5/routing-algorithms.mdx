# 5.2 Routing Algorithms (라우팅 알고리즘)

라우터는 제한된 전문가 연산 예산을 배분합니다. 작업을 한 사람에게만 보내면 다른 사람은 쉬게 되지만, 작업 수를 똑같이 맞춘다고 전체 지연 시간이 최소가 되는 것도 아닙니다. 토큰 친화도, 전문가 용량, 통신량, 인과성을 함께 고려해야 합니다.

## 토큰 선택과 부하 균형

토큰 표현 $x$ 와 라우터 행렬 $W$ 에 대해 기본 토큰 선택 방식은 $p(x)=\operatorname{softmax}(xW)$ 에서 $k$ 개 전문가를 선택합니다. 출력 결합 전에 선택된 가중치를 다시 정규화할 수 있습니다. 라우팅 붕괴는 적게 선택된 전문가가 더 적은 업데이트를 받는 피드백 현상이며, 정해진 스텝 뒤에 반드시 발생하는 사건은 아닙니다.

Noisy top-$k$ 는 탐색을 유도하고, 균형 손실은 목적 함수를 $L=L_{LM}+\alpha L_{bal}$ 로 바꿉니다. 계수 $\alpha$ 는 모델의 학습과 부하 사이의 절충을 조절합니다. 검증 손실과 전문가 부하를 함께 측정해야 하며, 전문가가 반드시 수학·문학처럼 명확한 주제로 전문화되는 것은 아닙니다. [[1]](#ref-1)

## 전문가 선택: 전문가별 고정 용량

Expert Choice는 선택 축을 뒤집어 각 전문가가 라우팅 그룹에서 일정 수의 토큰을 고르게 합니다. 용량 계수는 배수이고, 계산된 정수 용량은 토큰 수입니다. 개수가 같아도 실제 처리 시간이 같지는 않을 수 있습니다. 한 토큰은 여러 전문가의 출력을 받거나 아무것도 받지 않을 수 있습니다. $y=x+\operatorname{MoE}(x)$ 에서는 전문가 출력을 받지 못해도 잔차 표현이 유지됩니다. [[2]](#ref-2)

인과성의 핵심 문제는 그룹 내부의 경쟁입니다. 미래 토큰이 선택에 참여하면 뒤쪽 문장을 바꾸는 것만으로 앞쪽 토큰의 라우팅도 달라질 수 있습니다. 인과적 디코더에는 이를 방지하는 그룹 구성이나 라우팅 설계가 필요하며, KV 캐시를 유지하는 것만으로는 해결되지 않습니다.

> **교육용 선택 예제.** CPU 텐서로 인덱스와 가중치만 반환합니다. 전문가 연산, 잔차 및 scatter 결합, 인과적 그룹 구성, 분산 전송과 학습은 생략합니다. 용량은 사용 가능한 토큰 수 이내로 제한합니다.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class ExpertChoiceRouting(nn.Module):
    def __init__(self, d_model, num_experts, capacity_factor):
        super().__init__()
        if num_experts < 1 or capacity_factor <= 0:
            raise ValueError("positive expert count and capacity factor required")
        self.num_experts = num_experts
        self.capacity_factor = capacity_factor

        # Router network
        self.router = nn.Linear(d_model, num_experts, bias=False)

    def forward(self, x):
        """
        x shape: [batch_size, seq_len, d_model]
        """
        batch_size, seq_len, d_model = x.shape
        num_tokens = batch_size * seq_len

        # Calculate fixed capacity per expert
        # E.g., if capacity_factor=2.0, an expert processes twice the average token share
        if num_tokens == 0:
            raise ValueError("empty routing group")
        expert_capacity = min(num_tokens, max(1, int(
            (num_tokens / self.num_experts) * self.capacity_factor)))

        x_flat = x.reshape(-1, d_model) # [num_tokens, d_model]

        # 1. Compute affinity logits: [num_tokens, num_experts]
        logits = self.router(x_flat)

        # 2. Convert to routing weights (Softmax over experts)
        weights = F.softmax(logits, dim=-1)

        # 3. TRANSPOSE: Let experts view all tokens -> [num_experts, num_tokens]
        weights_t = weights.t()

        # 4. Expert Choice: Each expert picks its top `expert_capacity` tokens
        # top_weights, top_indices shape: [num_experts, expert_capacity]
        top_weights, top_indices = torch.topk(weights_t, expert_capacity, dim=-1)

        # (In a full implementation, tokens would now be gathered using top_indices,
        # processed by their respective experts, and scattered back)

        return top_indices, top_weights

# Example usage
layer = ExpertChoiceRouting(d_model=1024, num_experts=8, capacity_factor=1.5)
dummy_input = torch.randn(2, 128, 1024) # 256 total tokens
indices, weights = layer(dummy_input)

# Each of the 8 experts exactly selected 48 tokens (256 / 8 * 1.5)
print(f"Indices shape: {indices.shape}") # Expected: [8, 48]
```

## Soft MoE: 미분 가능한 슬롯

Soft MoE는 토큰의 가중 혼합으로 전문가 입력 슬롯을 만들고, 전문가 출력을 다시 토큰 표현으로 결합합니다. 이 혼합 슬롯에 희소 연산을 수행합니다. 원 논문은 비전 모델을 평가했습니다. 인과적 생성에 그대로 적용할 때의 핵심 문제는 미래 위치의 혼합이며, 소프트 할당이 모든 연산 절감 효과를 없앤다는 뜻은 아닙니다. [[3]](#ref-3)

## DeepSeek-V3의 동적 선택 편향

DeepSeek-V3는 전문가 선택과 출력 가중치를 구분합니다. 토큰 $t$, 전문가 벡터 $e_i$, 친화도 $s_{i,t}$, 부하 제어 편향 $b_i$ 를 사용하면 단순화한 선택 규칙은 다음과 같습니다.

$$
s_{i,t}=\sigma(x_t^\top e_i),\qquad
I_t=\operatorname{TopK}_i(s_{i,t}+b_i),\qquad
g_{i,t}=\frac{\mathbf{1}[i\in I_t]s_{i,t}}{\sum_{j\in I_t}s_{j,t}}.
$$

편향은 **sigmoid 이후** 의 선택 점수를 바꾸고, 선택된 출력 가중치는 편향 없는 친화도로 계산합니다. 부하 제어기는 과부하 전문가의 편향을 낮추고 저부하 전문가의 편향을 높입니다. “보조 손실 없음”은 이 부하 제어 방식의 이름입니다. 보고서에는 작은 시퀀스 단위 균형 손실도 남아 있습니다. 위 식은 노드 제한, 라우팅 출력 배율과 공유 전문가를 생략합니다. [[4]](#ref-4)

이는 문서화된 설계 사례이지 모든 모델에서 보조 손실을 없애야 한다는 증거가 아닙니다. 데이터·연산·전문가 수·용량을 고정한 절제 실험에서 홀드아웃 품질과 불균형을 함께 평가해야 합니다.
