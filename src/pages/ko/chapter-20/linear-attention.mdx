# 20.3 선형 어텐션

디코더가 2, 8, 20이라는 값을 차례로 읽었습니다. 첫 번째 값과 세 번째 값의 키가 같다면 나중에 첫 번째 값만 다시 꺼낼 수 있을까요? 세 번째 토큰을 처리한 뒤 상태에 무엇이 남는지 보면 답을 알 수 있습니다. 덧셈으로 상태를 갱신하는 선형 어텐션을 예로 들어, 값을 어떻게 쓰고 읽는지 확인하고 필요한 메모리까지 계산해 봅시다.

---

## 1. 핵심 아이디어

쿼리 $Q$, 키 $K$, 값 $V$ 와 키의 폭 $d$ 가 주어지면 밀집 softmax 어텐션은 보이는 토큰 쌍마다 점수를 구합니다. 융합 커널은 전체 점수 행렬을 저장하지 않고 아래 식을 계산할 수 있습니다.

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d}}\right)V
$$

두 특징 벡터의 내적 $\phi(q)^T\phi(k)$ 으로 점수를 구하는 커널을 택하면, 정규화 전의 분자는 곱하는 순서를 다음과 같이 바꿔 쓸 수 있습니다.

$$
\phi(Q)\left(\phi(K)^T V\right)
$$

디코더에서 각 쿼리가 볼 수 있는 토큰은 합산 범위로 결정됩니다. 시점 $t$ 의 쿼리가 볼 수 있는 범위로 두 합을 제한합니다.

$$ S_t=\sum_{i=1}^t \phi(k_i)v_i^T,\qquad z_t=\sum_{i=1}^t \phi(k_i),\qquad y_t^T=\frac{\phi(q_t)^T S_t}{\phi(q_t)^T z_t}. $$

$q_i$, $k_i$, $v_i$ 는 위치 $i$ 의 쿼리, 키, 값입니다. $\phi$ 는 폭이 $m$ 인 비음수 특징 맵입니다. 새 토큰마다 $m\times d_v$ 행렬 $S_t$ 에 외적을 더하고 길이가 $m$ 인 벡터 $z_t$ 에 키 특징을 더합니다. 분모는 이 쿼리에서 보이는 커널 가중치의 합입니다. 위 식은 합이 양수인 경우에 성립합니다. 구현할 때는 합이 0이거나 아주 작은 경우를 어떻게 처리할지도 정해야 합니다. [[1]](#ref-1)

## 2. 왜 이 아이디어가 계속 매력적인가

특징 폭과 값의 폭을 고정하면 디코딩 한 단계마다 $m d_v$ 개 원소를 갱신하고 같은 크기의 상태에서 값을 읽습니다. 접두사 길이가 늘어나도 행렬 크기는 그대로입니다. 순환 계산을 구조화된 행렬 곱으로 다루는 관점은 상태 공간 쌍대성에서도 볼 수 있습니다. [[3]](#ref-3) 한편 밀집 어텐션은 보이는 위치마다 키와 값을 보관하므로 각 키의 점수를 따로 계산할 수 있습니다. 짧은 문맥에서는 고정 크기의 행렬이 오히려 공간을 더 차지할 수 있습니다. [계산기](#context-state-memory)에서 역전되는 길이를 찾아보세요.

## 3. 초기 변형들이 왜 고전했는가

값 2와 20의 키 특징이 모두 $(1,0)$ 이고, 값 8의 키 특징이 $(0,1)$ 이라고 합시다. 마지막 상태에는 합 $(22,8)$ 과 횟수 $(2,1)$ 가 남습니다. 특징이 $(1,0)$ 인 쿼리는 $22/2=11$ 을 읽습니다. 2와 20의 순서를 바꿔도 이 상태는 같으므로, 마지막 상태만 받은 쪽은 어느 값이 먼저 나왔는지 알아낼 수 없습니다. 위치 정보를 특징에 넣거나 문맥에 따라 키가 달라지거나 상태 갱신 규칙을 바꾸면 결과도 달라질 수 있습니다.

## 4. 최근 연구가 고치려는 것

### 떠오르는 Hybrid Pattern

Yang 등은 델타 규칙을 쓰는 층에 슬라이딩 윈도 또는 전역 어텐션을 섞어 실험했습니다. 이들의 검색 실험은 언어 모델의 평균 손실 외에 앞서 등장한 값을 정확하게 꺼낼 수 있는지도 따로 측정할 이유를 보여 줍니다. 밀집 어텐션 층은 이전 키를 개별적으로 보관할 수 있고, 순환 층은 고정 크기 상태를 유지합니다. 두 방식을 섞은 모델을 서빙할 때는 양쪽 메모리를 모두 계산해야 합니다. [[2]](#ref-2)

### 덧셈 메모리와 delta rule의 차이

단순한 gate-plus-write는 상태를 감쇠한 뒤 새 정보를 더합니다. Delta rule은 현재 key 방향에 이미 저장된 예측을 빼는 **상태 의존적 교정** 을 수행합니다. [[2]](#ref-2)

$$ S_t=(I-\beta_t k_tk_t^T)S_{t-1}+\beta_t k_tv_t^T. $$

여기서 $S_t\in\mathbb R^{d_k\times d_v}$, $k_t\in\mathbb R^{d_k}$, $v_t\in\mathbb R^{d_v}$ 이고 $\beta_t$ 는 쓰기 강도입니다. 단위 norm key를 쓰면 $k_tk_t^T$ 는 그 key 방향의 투영입니다. 교정은 한 키의 방향으로 작용하고, 그 키에 수직인 성분은 그대로 보존할 수 있습니다. Gated DeltaNet은 망각도 결합하며 구현의 정규화·게이트 순서를 확인해야 합니다. [[4]](#ref-4)

## 5. 교육용 PyTorch 예제

<a id="causal-linear-scan"></a>

### 마지막 값을 바꾸면 앞의 두 출력은 어떻게 될까?

첫 쿼리가 읽을 수 있는 값은 2 하나입니다. 두 번째 쿼리의 특징은 $(1,1)$ 이므로 보이는 두 키에 똑같이 가중치 1을 주고 $(2+8)/2=5$ 를 읽습니다. 세 번째 값을 20에서 100으로 바꾸면 이 두 출력은 어떻게 될까요? Python 3.10 이상과 PyTorch가 설치된 CPU에서 확인할 수 있습니다.

**예제의 범위.** 헤드 하나가 패딩 없는 float32 시퀀스 하나를 처리합니다. 쿼리와 키는 특징 변환을 마친 값으로 주어집니다. 반복문에서 각 토큰이 기록된 직후의 상태를 볼 수 있습니다. 배치 디코더에는 투영, 마스크, 요청별 상태 관리와 하드웨어에 맞는 커널도 필요합니다.

```python
import torch

# 한 헤드의 쿼리 특징과 키 특징을 토큰마다 한 행씩 넣습니다.
queries = torch.tensor([[1., 0.], [1., 1.], [1., 0.]])
keys = torch.tensor([[1., 0.], [0., 1.], [1., 0.]])
values = torch.tensor([[2.], [8.], [20.]])

def scan(queries, keys, values, state=None):
    if state is None:
        memory = values.new_zeros(keys.shape[1], values.shape[1])
        counts = keys.new_zeros(keys.shape[1])
    else:
        memory, counts = state

    outputs = []
    for query, key, value in zip(queries, keys, values, strict=True):
        memory = memory + torch.outer(key, value)
        counts = counts + key
        normalizer = query @ counts
        if normalizer <= 0:
            raise ValueError("query has no overlap with the visible keys")
        outputs.append((query @ memory) / normalizer)
    return torch.stack(outputs), (memory, counts)

stream, _ = scan(queries, keys, values)
weights = (queries @ keys.T).tril()
reference = (weights @ values) / weights.sum(dim=1, keepdim=True)
torch.testing.assert_close(stream, reference)
print(stream.flatten().tolist())

_, prefix_state = scan(queries[:2], keys[:2], values[:2])
suffix, _ = scan(queries[2:], keys[2:], values[2:], prefix_state)
torch.testing.assert_close(suffix, stream[2:])

changed_values = values.clone()
changed_values[2] = 100.
changed, _ = scan(queries, keys, changed_values)
torch.testing.assert_close(changed[:2], stream[:2])
print(changed.flatten().tolist())
```

처음에는 `[2.0, 5.0, 11.0]`, 값을 바꾼 뒤에는 `[2.0, 5.0, 51.0]` 이 출력됩니다. 삼각 행렬로 구한 참조값은 같은 커널로 모든 토큰 쌍의 가중치를 직접 구한 결과입니다. 저장한 $(S_2,z_2)$ 에서 이어서 계산해도 마지막 출력이 같습니다. 매 단계의 누적 합 대신 시퀀스 전체의 합을 한 번만 구하면 첫 쿼리도 세 번째 값을 읽게 됩니다.

## 6. 문맥 상태 메모리 계산기

<a id="context-state-memory"></a>

32층, KV 헤드 8개, 헤드 폭 128, KV 원소당 2바이트이면 토큰 하나를 보관하는 데 128 KiB가 듭니다. 비교할 순환 모델은 층마다 헤드가 32개입니다. 특징 폭과 값의 폭이 모두 128일 때 FP32 상태는 요청당 64.5 MiB입니다. KV 캐시는 차례로 16 MiB, 64.5 MiB, 512 MiB가 됩니다. 순환 상태를 BF16으로 저장하면 두 크기가 같아지는 지점은 어디일까요?

## 7. 모델을 고를 때 확인할 것

같은 프롬프트로 두 가지를 측정하세요. 먼저 같은 키가 반복되거나 문서 중간에서 값이 수정됐을 때 나중의 쿼리가 원하는 값을 꺼내는지 봅니다. 다음으로, 접두사 길이마다 실행 중인 요청 하나를 위해 실제로 보관하는 바이트 수를 잽니다. 긴 문맥에서 메모리를 절약하는 모델도 과제에 꼭 필요한 수정 사항을 놓칠 수 있습니다.

## 최근 연구: gating·delta update·상태를 가진 서빙

**2026-10-13 기준.** Gated DeltaNet은 선택적 망각과 delta-rule의 목표 지향 update를 결합하고 하이브리드 어텐션 stack을 연구합니다 [[4]](#ref-4). 새 값을 쓰기 전에 기존 상태의 일부를 지울 수 있어 이후의 읽기 결과도 달라집니다.

효율적인 레이어도 정확한 상태 계약이 필요합니다. 접두사 재사용에서는 recurrent 상태와 어텐션 KV를 같은 위치에서 복원해야 합니다. 분기형 speculation은 토큰 버퍼를 줄이는 것만으로 되돌릴 수 없는 상태를 격리해야 합니다. [12.1절](/ko/chapter-12/kv-cache-management)과 [12.4절](/ko/chapter-12/speculative-decoding)의 최근 통합 근거가 아키텍처의 메모리 절감에도 scheduler·복구 검증이 필요한 이유를 설명합니다. 처리량과 함께 연상 회상·위치 민감도·장문 품질·cold/복원 continuation을 평가합니다.


### 10월 배포 사례: 계층마다 다른 상태

**2026-11-25 기준**, Ling 3.1 Flash 공개 카드는 KDA 63계층·gated-MLA 9계층의 7:1 하이브리드를 명시합니다 [[5]](#ref-5). 공개된 구체적 스택이며 모든 “선형” 모델이 같은 순환식을 쓴다는 근거는 아닙니다. 순환 상태와 어텐션 KV를 따로 계산하고 실제 런타임에서 정확한 회상·접두사 재사용·분기·롤백을 시험하세요. 호스팅 1019 프로필과 공개 가중치 리비전의 동등성은 확인되지 않았습니다. 출처 범위 안의 비교는 17.6절을 보세요.

## Muir: 고정 상태의 용량과 읽기·쓰기 동역학

**2026-11-25 기준 — 초기 연구.** Muir는 채널별 게이트를 가진 delta 메모리를 분석합니다. 민감도에 따라 저랭크 게이트 용량을 배분하고 시간 척도별 읽기를 조절하며, 경계를 기준으로 계산하는 청크 커널을 제안합니다. 정적 읽기와 동적 읽기는 단일 지연의 기억 유지와 여러 지연에 대한 적응 사이에서 절충합니다. TPU 중심 커널과 제한된 회상 과제의 결과를 모든 하드웨어의 우위로 일반화할 수는 없습니다. [[6]](#ref-6)

단일 사실 검색, 서로 의존하는 여러 사실, 연속 텍스트 모델링을 나누어 평가하세요. 동일 파라미터·연산 예산의 품질, 수치 조건과 실제 처리량은 선형 복잡도만으로 결정되지 않습니다.
