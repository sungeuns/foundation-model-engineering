# 13.2 Quantization Methods

80억 개 가중치를 4비트로 저장하면 가중치 자체는 4 GB입니다. 그렇다고 4 GB 메모리에서 전체 모델을 서빙할 수 있다는 뜻은 아닙니다. 스케일, 양자화하지 않은 텐서, 활성화, KV 캐시도 공간이 필요합니다. 같은 4비트 모델 두 개가 같은 답을 내는 것도 아닙니다. 반올림 오차의 크기뿐 아니라 오차가 생기는 위치가 중요합니다.

이 절에서는 두 질문을 따라갑니다. **어떤 오차가 레이어 출력에 크게 영향을 주며, 런타임은 어떤 표현을 실제로 실행할 수 있을까요?** GPTQ와 AWQ는 보정 데이터를 이용해 첫 질문을 다루고, GGUF 같은 형식은 텐서와 메타데이터의 저장 방식을 기술합니다. 배포 과정의 서로 다른 요소입니다.

## 1. GPTQ: 레이어 출력 오차 보상

GPTQ 논문은 평가한 175B 모델을 GPU에서 몇 시간에 걸쳐 3비트 또는 4비트로 압축하고 작은 perplexity 변화를 얻었다고 보고합니다 [[1]](#ref-1). 해당 모델·보정 데이터·양자화 설정·평가의 결과이며, 모든 모델에서 안전한 비트 수를 정한 것은 아닙니다.

### 헤시안이 측정하는 것

선형 레이어의 가중치를 $W\in\mathbb{R}^{d_{out}\times d_{in}}$, 보정 입력 벡터 $n$ 개를 열로 모은 행렬을 $X\in\mathbb{R}^{d_{in}\times n}$ 이라 하겠습니다. GPTQ가 근사적으로 푸는 문제는 양자화 제약이 있는 레이어 출력 복원입니다.

$$
\underset{\hat W\in\mathcal Q}{\operatorname{minimize}}\;
\frac{1}{n}\lVert WX-\hat WX\rVert_F^2,
\qquad H=\frac{2}{n}XX^\top.
$$

$\mathcal Q$ 는 허용된 양자화 표현이고 $\lVert\cdot\rVert_F$ 는 Frobenius 노름입니다. $H$ 는 출력 한 행의 복원 손실을 가중치에 대해 두 번 미분한 헤시안입니다. 평균을 빼지 않은 이차 모멘트로 입력 특징 간 상호작용을 담습니다. 전체 모델의 언어 모델링 손실에 대한 헤시안은 아닙니다.

가중치 하나를 반올림하면 레이어 출력이 달라집니다. GPTQ는 아직 양자화하지 않은 가중치를 조정하여 보정 입력에서 이 변화를 보상합니다. 각 행이 같은 입력 이차 모멘트 행렬을 공유하므로 여러 행의 같은 열을 함께 처리할 수 있습니다. 입력끼리 상관관계가 있으면 보상의 여지가 생기지만, $H$ 가 대각행렬이면 특징 간 보정은 없습니다. 감쇠항은 거의 특이한 추정 행렬을 안정화합니다.

### 작은 오차 보상 루프

> **의도적으로 단순화한 단일 레이어 구현.** CPU FP32이며 $W$ 는 `[out_features, in_features]`, $H$ 는 `[in_features, in_features]` 형상입니다. 보정 데이터 준비, 그룹별 스케일 탐색, 활성화 순서 재배치, 비트 패킹, 융합 커널, 분산 실행, 모델 수준 품질 기준을 생략합니다. 출력은 밀집 FP32 텐서이므로 이 코드 자체로 저장량이 줄지는 않습니다.

```python
import torch

@torch.no_grad()
def gptq_core_loop(W, H, bits=4, damping=0.01):
    """Educational FP32, per-output-row symmetric quantization; no packing."""
    if W.ndim != 2 or H.shape != (W.shape[1], W.shape[1]):
        raise ValueError("incompatible W/H shapes")
    if not 2 <= bits <= 8 or damping <= 0:
        raise ValueError("invalid quantization settings")
    work = W.detach().float().clone()
    hessian = H.detach().to(device=W.device, dtype=torch.float32).clone()
    ridge = damping * hessian.diag().mean().clamp_min(1e-6)
    hessian.diagonal().add_(ridge)
    # U.T @ U = inverse(H); not the unchanged raw inverse Hessian.
    chol = torch.linalg.cholesky(hessian)
    inverse = torch.cholesky_inverse(chol)
    U = torch.linalg.cholesky(inverse, upper=True)
    qmax = 2 ** (bits - 1) - 1
    scales = (work.abs().amax(dim=1) / qmax).clamp_min(1e-8)
    quantized = torch.zeros_like(work)
    for i in range(work.shape[1]):
        column = work[:, i]
        q = (column / scales).round().clamp(-qmax, qmax) * scales
        quantized[:, i] = q
        error = (column - q) / U[i, i]
        work[:, i+1:] -= error[:, None] * U[i, i+1:][None, :]
    return quantized

torch.manual_seed(7)
W = torch.randn(16, 32)
X = torch.randn(32, 64)  # calibration features x samples
H = 2 * X @ X.T / X.shape[1]
W_q = gptq_core_loop(W, H)
print("Calibration reconstruction MSE:", ((W - W_q) @ X).square().mean().item())
```

이 예제는 $H$ 를 만든 데이터에서 복원 오차를 측정합니다. 선택을 신뢰하기 전에 별도로 남긴 보정 검증 구간에서도 측정해야 합니다. 레이어 오차가 작아져도 생성 품질·도구 출력 형식·드문 도메인 능력이 보존된다는 보장은 없습니다. 평가 예제와 의미적으로 가까운 예제는 보정 데이터에서 격리하세요.

## 2. AWQ: 재스케일링으로 민감한 채널 보호

AWQ는 활성화에 따른 민감도를 살피고 가중치를 양자화하기 전에 채널별 스케일을 탐색합니다 [[2]](#ref-2). 1%를 포함한 소수의 중요한 가중치를 보호했을 때의 관찰은 논문이 실험한 조건에서 얻은 결과입니다. 모든 모델에 같은 비율의 고정된 필수 가중치 집합이 있다는 뜻은 아닙니다.

### 가중치 오차만 보면 놓치는 것

출력 하나의 가중치가 $w=[0.1,1]$, 입력이 $x=[100,1]$ 이라고 해봅시다. 정확한 출력은 $11$ 입니다. 양의 최대 코드가 7이고 스케일이 $1/7$ 인 대칭 4비트 격자에서는 가중치가 $[1/7,1]$ 로 반올림되어 출력이 약 $15.286$ 이 됩니다. 가중치 오차는 $0.04286$ 에 불과하지만 입력 100과 곱해져 출력 오차가 약 $4.286$ 이 됩니다. 설명을 위해 만든 두 특징 예제이며 모델 벤치마크가 아닙니다.

활성화 통계는 이런 민감도를 찾는 데 도움이 됩니다. 다만 보정 분포에 의존하는 대리 지표이며, 가중치의 인과적 중요도를 완전히 측정하는 것은 아닙니다.

### 역수 스케일링이 보존하는 것

양수인 입력 채널 스케일 벡터를 $s$, 이를 대각 원소로 갖는 행렬을 $D(s)$ 라 하면 반올림 전에는 다음이 성립합니다.

$$
WX=(W D(s))(D(s)^{-1}X).
$$

스케일링한 가중치에 양자화 함수 $Q$ 를 적용한 뒤 실제 출력 오차는 다음과 같습니다.

$$
\Delta Y=\bigl[Q(WD(s))-WD(s)\bigr]D(s)^{-1}X.
$$

스케일링은 반올림 격자와 입력의 배율을 함께 바꿉니다. 양자화 그룹을 공유하면 이웃 가중치도 영향을 받습니다. 한 채널의 범위를 키울수록 다른 채널의 정밀도가 떨어질 수 있습니다. AWQ는 이 상충관계를 고려해 스케일을 탐색합니다. 역수 관계가 성립한다고 해서 **양자화한 뒤의 출력까지 원본과 같아지는 것은 아닙니다**.

> **의도적으로 단순화한 스케일링 예제.** CPU FP32에서 양자화 전의 역수 스케일링 동치만 확인합니다. AWQ의 스케일 탐색·클리핑, 양자화 자체, 인접 연산에 스케일을 합치는 처리, 비트 패킹, 런타임 커널, 별도 검증 데이터의 품질 평가는 생략합니다.

```python
import torch

@torch.no_grad()
def awq_scale_weights(W, X, s_x=0.5):
    """Illustrate reciprocal channel scaling, not the AWQ scale search."""
    if W.ndim != 2 or X.ndim != 3 or W.shape[1] != X.shape[-1]:
        raise ValueError("incompatible calibration shape")
    if not 0 <= s_x <= 1:
        raise ValueError("s_x must be in [0,1]")
    magnitudes = X.float().abs().mean(dim=(0, 1)).clamp_min(1e-6)
    scales = magnitudes.pow(s_x)
    scales = scales / torch.sqrt(scales.max() * scales.min())
    return W.float() * scales[None, :], scales

W = torch.randn(16, 32)
X = torch.randn(2, 8, 32)
X[..., 0] = 0  # inactive channels must not cause division by zero
scaled_W, scales = awq_scale_weights(W, X)
assert torch.allclose(X @ W.T, (X / scales) @ scaled_W.T, atol=1e-5)
```

AWQ와 GPTQ는 서로 다른 보정 연산에 비용을 씁니다. 같은 체크포인트·보정 데이터·양자화 설정·대상 런타임에서 구현을 비교해야 합니다. 방법의 이름만으로 속도나 품질 순위를 보장할 수 없습니다.

## 3. TurboQuant: 회전과 잔차 보정

TurboQuant는 온라인 벡터 양자화의 평균제곱 오차와 내적 오차를 연구합니다. 회전 후 분포에 맞춘 스칼라 양자화를 사용하며, 내적 추정에는 잔차의 QJL 보정을 결합합니다. Hadamard 회전 뒤 균일 반올림만 적용한 것은 전체 알고리즘이 아닙니다 [[3]](#ref-3).

직교 회전은 양자화 전 내적을 보존하지만 양자화 오차까지 없애지는 않습니다. 논문의 KV 품질 결과는 평가한 모델과 작업에 한정됩니다. 동시 처리량은 가중치·KV·임시 버퍼·메타데이터·커널 비용을 함께 고려해야 하므로 비트 수만으로 두 배가 된다고 결론 내릴 수 없습니다. 자세한 구분은 13.5절에서 다룹니다.

## 4. GGUF: 실제 저장된 텐서 확인

GGUF는 텐서와 메타데이터를 저장하는 컨테이너이지 하나의 양자화 알고리즘이 아닙니다 [[5]](#ref-5). 텐서 타입에 따라 블록 크기·스케일·오프셋·코드 표현이 다르며 모든 블록이 제로 포인트를 저장하지는 않습니다.

**2026-11-18 기준** 공식 명세는 타입별 텐서 데이터와 키·값 메타데이터를 기술합니다. 블록 형식과 변환기의 혼합 텐서 정책을 구분하세요. `Q4_K_M` 같은 이름만으로 모든 층의 정밀도를 알 수는 없습니다. 실제 텐서 타입과 크기, 변환기 커밋·설정·가중치 해시를 기록하고 대상 백엔드에서 품질과 성능을 검증해야 합니다.

## 5. FP8과 정수 격자

균일 정수 양자화는 *하나의 스케일 안에서* 복원 값의 간격이 같습니다. 부동소수점은 지수부와 가수부를 사용하여 값의 크기에 따라 간격이 달라집니다. 이 구분이 모든 LLM 텐서가 정규 분포를 따르거나 어느 표현의 오차가 언제나 더 작다는 뜻은 아닙니다.

2022년 FP8 제안은 E4M3와 E5M2를 정의합니다 [[4]](#ref-4). E4M3는 E5M2보다 가수 비트가 많고 표현 범위가 좁습니다. 논문은 이러한 특성을 학습 방식의 순전파 텐서와 기울기에 활용합니다. 구체적인 포맷 변형·스케일링 규칙·커널 지원은 선택한 구현에서 확인해야 합니다. E5M2가 IEEE 방식의 특수 값을 사용한다는 사실이 이 제안을 “IEEE FP8 표준”으로 만들지는 않습니다.

FP8에도 유한한 표현 범위가 있습니다. 스케일링·클리핑·오버플로·누산 정밀도·입력 분포가 오차에 영향을 줍니다. 16비트 텐서를 8비트로 바꾸면 해당 텐서의 원시 저장량은 절반이지만 전체 VRAM이나 실행 시간이 절반이 되지는 않을 수 있습니다.

## 6. 메타데이터와 런타임 상태를 따로 계산하기

가중치 $P$ 개를 $b$ 비트로 저장하면 이상적인 저장량은 $Pb/8$ 바이트입니다. 80억 개 가중치를 모두 4비트로 저장하고 128개마다 FP16 스케일 하나를 두는 **가상 형식** 을 생각해봅시다. 그룹은 6,250만 개이므로 스케일에 125 MB가 추가됩니다. 헤더·패딩·비양자화 텐서·런타임 상태를 넣기 전부터 가중치와 스케일의 합은 **4.125 GB** 입니다.

아래 계산은 그룹이 끊기지 않고 이어진다고 가정합니다. 실제 형식은 각 행이나 텐서에서 그룹을 새로 시작할 수 있습니다. GGUF 파일 크기 예측기는 아닙니다.

```python
parameters = 8_000_000_000
bits, group_size, scale_bytes = 4, 128, 2
weight_bytes = parameters * bits // 8
groups = (parameters + group_size - 1) // group_size
metadata_bytes = groups * scale_bytes
assert weight_bytes == 4_000_000_000
assert metadata_bytes == 125_000_000
print((weight_bytes + metadata_bytes) / 1e9)  # 4.125 decimal GB
```

그룹마다 2바이트 제로 포인트도 저장한다면 125 MB가 더 필요합니다. 그룹 크기나 메타데이터 타입을 바꾸면 부가 비용도 바뀝니다. 목표 배치와 문맥 길이에 맞춰 KV·순환 상태, 활성화, 작업 공간, allocator 여유를 별도로 계산하세요. `W4A16` 표기는 가중치·활성화 정밀도를 설명할 뿐 KV 정밀도나 모든 연산의 처리 방식을 정하지는 않습니다.

배포 파일을 바꾸기 전에 기본 체크포인트·토크나이저와 템플릿·보정 데이터 명세·변환기와 런타임 버전·해시를 보존합니다. 별도 평가 구간에서 도메인과 기본 능력 유지, 안전성, 형식·도구 정확성, 최대 메모리와 지연 시간을 비교하세요. 미리 정한 품질 또는 서비스 기준을 넘으면 배포를 거부하거나 롤백합니다. 파일이 작아졌다는 사실만으로 배포를 결정해서는 안 됩니다.

## 7. 양자화 범위와 출력 오차 살펴보기

범위와 비트 수를 바꾸며 반올림·클리핑·활성화에 따른 출력 오차를 비교하세요. 균일 양자화 계산이며 GPTQ·AWQ 벤치마크는 아닙니다.

*아닙니다. 국소 목적함수는 보정 입력에 대한 선형 레이어 출력을 복원하며, 입력 이차 모멘트로 반올림 오차를 보상합니다. 국소 복원 오차가 줄어도 모든 후속 능력이 보존된다는 보장은 없으므로 별도 데이터로 모델 수준 평가를 해야 합니다.*
</details>

<details>
<summary>Quiz 3: 4비트 체크포인트의 저장량이 파라미터당 0.5바이트보다 커질 수 있는 이유는 무엇인가요?</summary>
*스케일·제로 포인트·패킹·혼합 정밀도 텐서가 추가되기 때문입니다. 가상의 128개 가중치 그룹에서 FP16 스케일 하나는 다른 비용을 빼고도 가중치당 $2/128=0.015625$ 바이트를 더합니다. 런타임에는 활성화·KV 상태·작업 공간도 필요합니다.*
</details>

<details>
<summary>Quiz 4: 역수 스케일링 동치가 AWQ 양자화 이후에도 같은 출력을 보장하나요?</summary>
*아닙니다. 동치는 반올림 전 성립합니다. 양자화 후에는 $[Q(WD(s))-WD(s)]D(s)^{-1}X$ 가 남으며, 스케일 탐색·그룹 격자·입력에 따라 달라집니다. 같은 그룹의 다른 채널이 정밀도를 잃을 수도 있습니다.*
</details>

<details>
<summary>Quiz 5: 대칭 INT8의 텐서별 스케일과 토큰별 스케일은 어떻게 다른가요?</summary>
*$T$ 개 토큰과 $D$ 개 채널인 $X\in\mathbb R^{T\times D}$ 에서 대칭 코드 범위를 $[-127,127]$ 로 택합니다. 텐서별로는 $s_{tensor}=\max_{t,d}|X_{t,d}|/127$, 토큰별로는 $s_t=\max_d|X_{t,d}|/127$ 입니다. 모두 0인 행에는 양수 대체 스케일을 사용합니다. 토큰별 스케일은 한 행의 범위가 다른 행의 격자까지 결정하지 않게 하지만 계산·메타데이터 비용이 추가되며 종단 간 작업 정확도의 향상을 보장하지는 않습니다.*
</details>
