# 13.4 지식 증류

고객 문의를 *결제* 또는 *반품* 담당자에게 보내는 작은 분류기를 만든다고 해 봅시다. 한 교사 모델은 “결제”라고 답하고, 다른 교사는 두 항목의 확률까지 보여 줍니다. 고른 담당자는 같아도 두 선택지가 얼마나 경합했는지는 두 번째 답에서만 알 수 있습니다. **지식 증류** 는 교사 모델에서 얻은 신호로 학생 모델을 학습하는 방법입니다. 어떤 손실을 쓸 수 있는지는 관찰할 수 있는 신호에 달렸습니다.

<a id="1-로짓-매칭에서-추론-과정으로의-진화"></a>

## 1. 교사가 무엇을 제공할 수 있을까요?

같은 입력과 같은 클래스 집합에 대해 교사와 학생의 로짓을 각각 $z_t$, $z_s$라고 합시다. 온도 $T>0$에서 두 분포는 $p_T=\operatorname{softmax}(z_t/T)$와 $q_T=\operatorname{softmax}(z_s/T)$입니다. Hinton 등은 교사의 출력 확률을 부드럽게 바꿔 학습 목표로 삼았습니다. $T$를 1보다 높이면 확률이 한 클래스에 덜 쏠려서 낮은 확률을 받은 클래스 사이의 차이도 드러납니다. 흔히 다음처럼 손실의 크기를 조정합니다. [[1]](#ref-1)

$$
\mathcal L_{\mathrm{KD}}=T^2\sum_i p_T(i)\log\frac{p_T(i)}{q_T(i)}.
$$

$i$는 클래스 번호입니다. 자연로그를 쓰므로 $T^2$을 곱하기 전 순방향 KL 발산의 단위는 nat입니다. 교사가 1등 레이블만 알려 주면 그 입력에서 나머지 클래스에 얼마씩 확률을 배분했는지 복원할 수 없습니다.

### 관찰할 수 있는 신호에 맞춰 학습 목표 고르기

| 교사에게 받은 신호 | 학생이 학습할 수 있는 목표 |
| --- | --- |
| 답변이나 생성된 설명문 | 문장을 모아 학생이 그 토큰을 예측하도록 학습합니다. Hsieh 등은 교사가 생성한 풀이를 추가 텍스트 목표로 썼습니다. 설명문은 관찰할 수 있지만, 그것이 답을 낸 내부 계산을 충실히 반영하는지는 별도로 확인해야 합니다. [[2]](#ref-2) |
| 전체 로짓 또는 확률 | 두 모델이 같은 결과 집합에 확률을 매길 때 분포를 맞출 수 있습니다. 다음 토큰의 KL을 계산하려면 토큰 ID와 순서, 앞에 주어진 토큰열까지 맞춰야 합니다. 상위 토큰 몇 개만 받으면 남은 확률이 어떻게 나뉘었는지 알 수 없습니다. [[1]](#ref-1) |
| 중간 특징 | 지정한 층과 위치에서 활성화 텐서를 읽습니다. 2014년 12월에 처음 공개된 FitNets는 학생의 중간 특징을 교사 특징에 맞추는 투영을 학습했습니다. 그러려면 해당 텐서에 접근할 수 있어야 합니다. [[6]](#ref-6) |

텍스트·확률·특징은 서로 보완할 수 있습니다. [은닉 좌표와 출력층을 따로 바꾸는 실습](#distillation-readout)에서 특징을 맞추는 손실이 어떤 제약을 더하는지 확인해 보세요.

## 2. 생성 모델을 위한 분포 교정: Forward KL vs Reverse KL

토큰을 순차적으로 생성하는 자기회귀(Auto-regressive) 모델의 지식 증류에서 가장 중요한 수학적 결정 중 하나는 발산(Divergence) 함수의 방향입니다. 전통적인 지식 증류는 교사 분포 $P$ 와 학생 분포 $Q$ 사이의 **Forward KL Divergence** $\mathcal{D}_{KL}(P || Q)$ 를 최소화합니다.

* **Forward KL (Mean-seeking)**: 전통적인 선택입니다. 교사 분포가 확률을 두는 영역을 학생도 넓게 덮도록 유도합니다. coverage가 중요할 때는 장점이 있지만, 학생이 훨씬 작을 경우 확률 질량을 너무 넓게 퍼뜨리는 부작용이 생길 수 있습니다.
* **Reverse KL (Mode-seeking)**: MiniLLM 같은 연구는 자기회귀 생성에서는 **Reverse KL Divergence** $\mathcal{D}_{KL}(Q || P)$ 가 더 잘 맞을 수 있다고 봅니다 [[3]](#ref-3). 학생이 교사가 선호하는 모드에 더 강하게 집중하게 만들기 때문에, 일부 설정에서는 더 또렷하고 유창한 출력을 만들 수 있습니다.

핵심은 어느 한쪽이 항상 우월하다는 이야기가 아닙니다. divergence 방향이 학생의 성격을 바꾸기 때문에, 생성형 증류에서는 이것을 기본값이 아니라 설계 선택으로 봐야 한다는 점이 중요합니다.

## 3. On-Policy 증류: 학생의 실수로부터 배우기

고정된 교사 궤적과 학생이 생성하는 궤적 사이에는 분포 차이가 생길 수 있습니다. 교사 출력도 오류를 포함하며, 학생이 한 토큰을 다르게 쓴다고 반드시 실패하는 것은 아닙니다. 중요한 것은 실제 학생 상태에서의 오류를 평가하고 학습 분포가 이를 다루도록 설계하는 것입니다.

이에 대한 대응이 **On-Policy Distillation** 입니다. 일반화된 지식 증류(GKD) 같은 방법은 교사가 만든 이상적인 경로만 보여주는 대신, 학생이 실제로 생성한 시퀀스를 교사가 다시 채점하게 만듭니다 [[4]](#ref-4). 즉, 학생이 자주 빠지는 나쁜 상태에서 다음 토큰을 어떻게 골라야 하는지까지 배우게 하는 방식입니다.

실무적으로 중요한 이유는 분명합니다. 배포된 모델은 깨끗한 예제에서 실패하기보다, 한 번 살짝 틀어진 뒤 그 상태를 회복하지 못해서 실패하는 경우가 많기 때문입니다.

## 4. 아키텍처 비동질성과 특징 정렬

두 모델이 다음 토큰을 같은 확률로 예측해도 은닉 차원의 수나 좌표계는 다를 수 있습니다. 중간 특징으로 학습하려면 어느 층의 어느 토큰 위치를 비교할지 먼저 정합니다. 학습 가능한 투영을 두면 학생의 은닉 상태를 교사 특징과 비교할 수 있는 좌표계로 옮길 수 있습니다. FitNets는 이 방식으로 폭이 넓은 교사에서 더 좁은 학생을 학습했습니다. [[6]](#ref-6)

### PyTorch 구현: 특징 기반 지식 증류

아래 예제는 다음 토큰의 교차 엔트로피, 온도를 적용한 출력 분포 사이의 순방향 KL, 투영한 학생 은닉 상태와 교사 은닉 상태 사이의 MSE를 하나의 손실로 결합합니다.

> **교육용 loss 예제.** 같은 토크나이저·어휘 순서·채팅 템플릿을 사용하는 정렬된 교사/학생 출력을 가정합니다. 실제 교사는 고정된 체크포인트로 `eval()` 및 `inference_mode()`에서 실행해야 합니다. 아래 합성 마스크는 실제 템플릿의 assistant span 마스크로 대체하세요. BOS/EOS 중복을 피하고 EOS 포함 정책·절단·패딩을 일치시키며, 패킹 시 샘플 간 attention을 차단해야 합니다. 전체 모델 학습, 다른 토크나이저의 분포 매핑, 전역 토큰 수를 사용하는 분산 loss 정규화는 구현하지 않습니다.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class ModernKDLoss(nn.Module):
    def __init__(self, student_dim, teacher_dim, temp=2.0, alpha=0.5, beta=0.1):
        super().__init__()
        if temp <= 0 or not 0 <= alpha <= 1 or beta < 0:
            raise ValueError("invalid loss settings")
        self.temp, self.alpha, self.beta = temp, alpha, beta
        self.feature_projector = nn.Linear(student_dim, teacher_dim, bias=False)

    def forward(self, student_logits, teacher_logits, student_hidden,
                teacher_hidden, labels, assistant_mask):
        # Same tokenizer, vocabulary ordering and [B,S,V] positions required.
        if student_logits.shape != teacher_logits.shape or student_logits.ndim != 3:
            raise ValueError("teacher/student logit alignment mismatch")
        if labels.shape != student_logits.shape[:2] or assistant_mask.shape != labels.shape:
            raise ValueError("label/mask shape mismatch")
        if labels.shape[1] < 2:
            raise ValueError("at least one next-token target required")
        # Position t predicts token t+1; padding uses -100, prompts use mask=False.
        valid = assistant_mask[:, 1:].bool() & labels[:, 1:].ne(-100)
        if not valid.any():
            raise ValueError("no supervised assistant tokens")
        s = student_logits[:, :-1].float()[valid]
        t = teacher_logits[:, :-1].detach().float()[valid]
        targets = labels[:, 1:][valid]
        ce = F.cross_entropy(s, targets)
        log_s = F.log_softmax(s / self.temp, dim=-1)
        log_t = F.log_softmax(t / self.temp, dim=-1)
        kd = F.kl_div(log_s, log_t, log_target=True, reduction="none").sum(-1).mean()
        # Align the predictive hidden states at the same selected positions.
        projected = self.feature_projector(student_hidden[:, :-1][valid])
        target_hidden = teacher_hidden[:, :-1].detach()[valid].float()
        feature = F.mse_loss(projected.float(), target_hidden)
        return (1-self.alpha)*ce + self.alpha*self.temp**2*kd + self.beta*feature

# Small CPU smoke example. Teacher outputs are frozen and already aligned.
torch.manual_seed(0)
B, S, V, Ds, Dt = 2, 6, 32, 8, 12
s_logits = torch.randn(B, S, V, requires_grad=True)
t_logits = torch.randn(B, S, V)
s_hidden = torch.randn(B, S, Ds, requires_grad=True)
t_hidden = torch.randn(B, S, Dt)
labels = torch.randint(V, (B, S))
labels[1, -2:] = -100
assistant_mask = torch.zeros(B, S, dtype=torch.bool)
assistant_mask[:, 3:] = True  # template-derived in a real pipeline
criterion = ModernKDLoss(Ds, Dt)
loss = criterion(s_logits, t_logits, s_hidden, t_hidden, labels, assistant_mask)
loss.backward()
print("KD loss:", loss.item())
```

## 5. 실무 증류 설계의 질문

실제 제품의 증류 파이프라인을 설계할 때는 다음 운영상의 질문이 중요합니다.

1. **어떤 행동이 가장 중요한가요?** 정확도, 지연 시간, 형식 준수, 도구 사용, 안전성에 따라 적합한 교사 신호가 달라집니다.
2. **적합한 교사인가요?** 전문 작업에서는 파라미터 수보다 도메인 적합성이 중요할 수 있습니다.
3. **어떤 실패를 평가하나요?** 정제된 벤치마크 성적이 좋아도 응답 길이, 확률 보정, 거절 행동이 달라질 수 있습니다.
4. **어디에 예산이 쓰이나요?** 추론 과정 생성이나 on-policy 채점을 위한 교사 추론이 전체 증류 비용의 큰 부분을 차지할 수 있습니다.

따라서 실무 증류에는 교사 출력으로 학생을 학습하는 것 외에도 데이터 선별, 교사 품질 검사, 학생 궤적 평가와 릴리스 기준이 필요합니다.

## 6. 표현 정렬의 기하학적 제약

은닉 상태가 $h=[1,3]^\top$이고, 출력층의 행벡터가 클래스 A에는 $[2,-1]$, B에는 $[1,1]$이라고 합시다. 로짓 $Wh$는 $[-1,4]^\top$입니다. 온도 $T=1$에서 교사가 B에 주는 확률은 0.993307입니다. 두 체크 상자가 비어 있으면 학생의 좌표와 출력층은 교사와 같습니다. 학생의 은닉 좌표만 교환하면 어떻게 될지 먼저 예상해 보고, 이어서 출력층의 두 열도 교환해 보세요.

<KDVisualizer lang="ko" />

은닉 좌표만 바꾸면 로짓이 $[5,4]^\top$가 됩니다. B의 확률은 0.268941로 낮아지고 순방향 KL은 1.266389 nat으로 커집니다. 두 상자를 모두 선택하면 로짓은 $[-1,4]^\top$, KL은 0으로 돌아옵니다. 두 경우 모두 원래 좌표에서 계산한 은닉 상태의 평균제곱오차(MSE)는 $((3-1)^2+(1-3)^2)/2=4$입니다.

출력층에서 같은 순열을 되돌리면 어느 은닉 상태에서도 이 관계가 성립합니다. 순열 행렬을 $P$라고 하면 $h_s=Ph$, $W_s=WP^\top$일 때 $P^\top P=I$이므로 $W_sh_s=Wh$입니다. 특징을 비교할 때도 학생 좌표를 $P^\top$로 투영하면 교사의 원래 좌표와 일치해 투영 후 MSE는 0이 됩니다. 이 예제에서는 학습 없이도 식으로 결과를 확인할 수 있습니다.

**파이썬 표준 라이브러리로 검산하기.** 각 줄에는 학생이 B에 준 확률, 순방향 KL(nat), 원래 좌표의 은닉 상태 MSE가 나옵니다. 순서대로 원본, 출력층의 열만 교환, 은닉 좌표만 교환, 둘 다 교환한 경우입니다.

```python
from math import exp, log

h = [1, 3]
W = [[2, -1], [1, 1]]

def probabilities(state, rows):
    logits = [sum(a * b for a, b in zip(row, state)) for row in rows]
    terms = [exp(z - max(logits)) for z in logits]
    return [v / sum(terms) for v in terms]

p = probabilities(h, W)
for state in (h, h[::-1]):
    for rows in (W, [row[::-1] for row in W]):
        q = probabilities(state, rows)
        kl = sum(a * log(a / b) for a, b in zip(p, q))
        mse = sum((a - b)**2 for a, b in zip(h, state)) / len(h)
        print(f"{q[1]:.6f} {kl:.6f} {mse:.0f}")
```

## SteerDistill: 국소적으로 교정한 행동에서 배우기

**2026-11-15 기준 — 초기 연구.** SteerDistill은 행동이 어긋난 지점 부근의 환경을 복원한 뒤, 교사의 지침으로 양자화 학생이 스스로 수정하도록 유도합니다. 국소 검증을 통과한 수정은 지침 없는 학생에 증류합니다. 교정 턴에는 순방향 KL, 다른 턴에는 원 정밀도 교사에 대한 역방향 KL을 씁니다. 실험 범위는 모델 3개와 에이전트 벤치마크 5개입니다. 성공한 교사 궤적·복원 가능한 상태·신뢰할 국소 검증이 필요하며, 국소 수정이 전체 성공을 보장하지는 않습니다. [[5]](#ref-5)

검증기 오류와 최종 성공을 따로 측정하세요. 버전·마스크·환경 스냅샷을 보존하고 평가 과제와 변형은 격리해야 합니다.

## 증류 실행 계약

입력 manifest에 데이터 출처·권한·필터·중복 제거·평가 격리와 교사/학생·토크나이저·템플릿 hash를 기록합니다. 증류 대상은 assistant의 유효 다음 토큰이며 교사 checkpoint, 생성 설정·길이 정책, projection 레이어와 loss 가중치를 함께 고정합니다. 예제는 CPU FP32 텐서 계산이며 실제 예산에는 두 모델의 가중치, 학생 그래디언트·옵티마이저·활성화, 교사 추론 버퍼, 로짓 저장, collective·평가 비용이 추가됩니다.

토큰 정규화 CE/KL과 도메인별 검증 지표, nonfinite/overflow·norm, 처리량·MFU·데이터 대기·collective와 batch ID를 관측합니다. 비유한 값, 마스크 불일치나 중요 슬라이스 악화 시 중단하세요. 체크포인트는 학생·projection·옵티마이저·스케줄러·정밀도 상태, step·토큰 수·RNG·sampler·데이터 cursor·hash를 포함해야 합니다. 격리된 도메인·기본 능력 유지·안전·형식/도구·지연·비용·오류율 평가를 짝지은 불확실성과 함께 통과하고 이전 정상 번들 복귀를 시험한 뒤에만 승격합니다.

## Quizzes

<details>
<summary>Quiz 1: 1등 레이블 하나만 알면 여러 클래스를 예측하는 학생의 순방향 KL을 계산할 수 있을까요?</summary>
*계산할 수 없습니다. 확률 분포가 달라도 같은 레이블이 1등일 수 있습니다. 전체 분포에 대한 KL을 구하려면 비교하는 각 클래스에 교사가 준 확률이 필요합니다.*
</details>

<details>
<summary>Quiz 2: 생성형 증류에서 Reverse KL이 항상은 아니지만 종종 매력적인 선택이 되는 이유는 무엇입니까?</summary>
*Forward KL은 교사 분포를 넓게 덮도록 유도하기 때문에, 작은 학생에게는 확률 질량이 너무 퍼질 수 있습니다. Reverse KL은 더 mode-seeking해서 교사가 선호하는 연속에 학생이 더 강하게 집중하게 만들 수 있습니다. 그래서 일부 생성 설정에서는 더 또렷하고 유창한 출력을 만들 수 있습니다.*
</details>

<details>
<summary>Quiz 3: On-Policy Distillation이 해결하려는 문제는 무엇입니까?</summary>
*훈련 때 본 깨끗한 teacher trajectory와, 실제 추론에서 학생이 만들어 내는 imperfect trajectory 사이의 간극을 줄이려는 것입니다. 학생이 직접 만든 시퀀스를 교사가 다시 채점하게 하면, 학생은 이상적인 경로뿐 아니라 자신이 실제로 빠지는 나쁜 상태에서 어떻게 회복할지도 배울 수 있습니다.*
</details>

<details>
<summary>Quiz 4: 학생의 은닉 좌표 두 개와 출력층의 두 열을 함께 맞바꾸면 출력만 보는 손실로 어떤 차이를 찾을 수 있을까요?</summary>
*어떤 은닉 상태에서도 로짓이 같아 순방향 KL은 0입니다. 실습의 입력에서는 원래 좌표의 은닉 상태 MSE가 4입니다. 특징을 비교하기 전에 투영으로 순열을 되돌리면 좌표도 다시 일치합니다.*
</details>

<details>
<summary>Quiz 5: 실제 distillation pipeline에서 teacher의 파라미터 수보다 teacher 선택 자체가 더 중요한 이유는 무엇입니까?</summary>
*학생은 teacher가 주는 신호만 배울 수 있기 때문입니다. 도메인에 잘 맞는 teacher는 target task에 더 적합한 출력, rationale, hidden-state structure를 제공합니다. 반대로 훨씬 더 큰 일반 모델이라도 배포 목표와 신호가 어긋나면 좋은 teacher가 아닐 수 있습니다.*
</details>
