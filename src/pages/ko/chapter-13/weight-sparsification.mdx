# 13.3 Weight Sparsification

가중치 행렬의 절반을 0으로 바꿔 저장했는데 파일 크기가 그대로입니다. 같은 밀집 행렬 곱셈을 실행해도 시간은 거의 줄지 않습니다. 빠진 단계는 표현 방식입니다. 밀집 텐서는 0도 그대로 저장하며, 밀집 커널은 여전히 전체 연산을 수행합니다.

희소화에는 두 작업이 있습니다. 먼저 필요한 동작을 유지하면서 무엇을 제거할지 정합니다. 그런 다음 남은 계산을 효율적으로 저장하고 실행해야 합니다. 가지치기 점수는 첫 번째 문제를, 희소 형식이나 실제로 작아진 밀집 행렬은 두 번째 문제를 다룹니다. 어느 하나만으로 종단 간 가속을 입증할 수는 없습니다.

## 1. 패턴은 커널과의 약속이다

| 패턴 | 입력 열 여덟 개의 예 | 실행에 필요한 조건 |
|---|---|---|
| 비구조적 | `[0, 0, 0, 4, 5, 6, 0, 8]` | 전체에서 네 값을 남기지만 위치가 불규칙하므로 알맞은 희소 표현과 커널이 필요합니다. |
| 2:4 반구조적 | `[1, 0, 3, 0] [0, 6, 0, 8]` | 연속된 네 원소마다 두 위치를 남겨 제약된 레이아웃에 맞춥니다. |
| 구조적 | 입력 채널 하나와 대응 열 전체를 제거 | 연결된 행렬들이 새 차원에 맞아야 하며 작은 밀집 커널을 사용할 수 있습니다. |

첫 행은 50% 희소하지만 **2:4는 아닙니다**. 두 그룹에 각각 한 개와 세 개가 남습니다. 비구조적이라는 말은 제거 위치에 제약이 없다는 뜻이지 알고리즘이 무작위로 선택한다는 뜻이 아닙니다. 밀집 커널은 각 값이 0인지 검사해 곱셈을 동적으로 생략하지 않습니다. 희소 커널에는 이해할 수 있는 메타데이터와 레이아웃이 필요합니다.

**2026-11-18 기준** PyTorch 2.15 문서는 반구조적 표현의 dtype·형상·CUDA 조건을 명시합니다 [[4]](#ref-4). 네 원소 패턴이 맞더라도 모든 형상·전치·장치·연산자가 지원되는 것은 아닙니다. 실제 런타임을 기록하고 실행된 커널을 확인하세요.

### 값이 절반이어도 저장량은 절반보다 크다

네 원소 묶음마다 FP16 값 두 개와 인덱스 4비트를 저장하는 표현을 생각해봅시다. 원래 네 값은 8바이트입니다. 남긴 값에는 4바이트, 메타데이터에는 0.5바이트가 듭니다. 각각의 가중치 저장량을 $M_{sparse}$ 와 $M_{dense}$ 라 하면

$$
\frac{M_{sparse}}{M_{dense}}=\frac{4+0.5}{8}=0.5625.
$$

원래 FP16 가중치가 10억 개라면 정렬이나 다른 텐서를 제외해도 2 GB가 1.125 GB가 됩니다. 절감률은 50%가 아닌 43.75%입니다. 이 예제는 보존한 원소당 인덱스 2비트를 쓰는 문서의 표현과 일치합니다 [[4]](#ref-4). 다른 형식은 메타데이터 비용이 달라질 수 있습니다.

희소 행렬 커널이 두 배 빨라도 애플리케이션 처리량이 두 배가 되는 것은 아닙니다. 해당 커널이 기존 지연 시간의 60%이고 나머지는 그대로라면 상대 지연 시간은 $0.6/2+0.4=0.7$, 속도 향상은 약 $1.43\times$ 입니다. 명시한 가정에서 계산한 설명용 상한이며 하드웨어 측정값은 아닙니다.

## 2. SparseGPT: 제거한 가중치의 오차 보상

SparseGPT는 OPT-175B와 BLOOM-176B에 한 번의 가지치기를 적용해 상당한 비구조적 희소성을 얻고, 실험에서 작은 perplexity 변화를 보고했습니다 [[1]](#ref-1). 해당 모델과 작업의 결과입니다. 같은 희소성이나 재학습 생략이 모든 능력의 보존을 보장하지는 않습니다.

$W\in\mathbb R^{d_{out}\times d_{in}}$ 와 보정 입력 열을 모은 $X\in\mathbb R^{d_{in}\times n}$ 에 대한 국소 목적함수는 다음과 같습니다.

$$
\underset{\hat W}{\operatorname{minimize}}\;
\frac{1}{n}\lVert WX-\hat WX\rVert_F^2
\quad\text{subject to}\quad\lVert\hat W\rVert_0\le\kappa.
$$

$\lVert\cdot\rVert_F$ 는 Frobenius 노름, $\lVert\hat W\rVert_0$ 는 남긴 0이 아닌 원소의 수, $\kappa$ 는 그 예산입니다. N:M 레이아웃은 각 그룹 안에 제약을 더합니다. GPTQ와 마찬가지로 $H=2XX^\top/n$ 은 한 행의 국소 복원 손실에 대한 헤시안이며 전체 언어 모델링 손실의 헤시안이 아닙니다.

SparseGPT는 이러한 입력 상관관계로 가지치기 과정에서 아직 고정하지 않은 가중치를 조정합니다. 국소 출력 오차를 일부 회복할 수 있지만, 이차 모멘트 추정·감쇠·행렬 분해에도 압축 시점의 메모리와 연산 비용이 듭니다. 결과 파일이 쓸 만한지는 별도 도메인 평가에서 확인해야 합니다.

## 3. Wanda: 더 저렴한 중요도 대리 지표

Wanda는 가중치 크기와 보정 활성화의 노름을 함께 사용합니다 [[2]](#ref-2).

$$
S_{ij}=|W_{ij}|\,\lVert X_j\rVert_2,
$$

$X_j$ 는 보정 토큰들에서 관찰한 입력 특징 $j$ 의 값입니다. 출력 한 행 안에서 점수를 비교하며 SparseGPT식 보상 갱신 없이 낮은 점수의 원소를 제거합니다. 보정 연산을 줄이는 방법이지 실제 “추론 경로”를 식별하는 방법은 아닙니다.

가중치가 $[0.01,0.2,0.3,2]$, 입력 하나가 $[100,1,1,1]$ 이라고 해봅시다. 크기 기준 가지치기는 앞의 두 가중치를 제거하지만, Wanda 점수는 $[1,0.2,0.3,2]$ 이므로 가운데 두 값을 제거합니다. 원래 출력은 3.5이고 두 방식의 출력은 각각 2.3과 3.0입니다. 이 예제에서는 활성화로 가중한 점수가 출력 오차를 줄입니다. 입력 분포가 바뀌면 결론도 바뀔 수 있습니다.

보정 토큰은 목표 트래픽을 대표해야 하며 패딩은 통계에서 제외합니다. 비공개 배포 평가 예제와 관련 문서는 보정 데이터에서 격리하고, 샘플 ID·토크나이저 버전·필터·정확한 마스크 생성 설정을 기록하세요.

## 4. 2:4 마스크를 만들고 확인하기

> **의도적으로 단순화한 마스크 구현.** CPU FP32에서 `W[out_features, in_features]` 와 `X[valid_tokens, in_features]` 를 받아 레이어 하나의 점수와 결정적인 마스크를 만듭니다. 모델 전체 보정·출력 보상·희소 패킹·GPU 커널 변환·품질 평가·성능 측정을 생략합니다. 마스크가 보존하는 위치는 정확히 두 곳이지만 기존 0 때문에 실제로 0이 아닌 값은 두 개보다 적을 수 있습니다.

```python
import torch

@torch.no_grad()
def wanda_2_4_mask(W: torch.Tensor, X: torch.Tensor):
    """CPU FP32 teaching example; X contains valid calibration tokens only."""
    if W.device.type != "cpu" or X.device.type != "cpu":
        raise ValueError("this teaching example is CPU-only")
    if W.dtype != torch.float32 or X.dtype != torch.float32:
        raise ValueError("use FP32 weights and activations")
    if W.ndim != 2 or X.ndim != 2 or X.shape[1] != W.shape[1]:
        raise ValueError("expected W[out,in], X[tokens,in]")
    if X.shape[0] == 0 or W.shape[0] == 0 or W.shape[1] == 0 or W.shape[1] % 4:
        raise ValueError("need nonempty tensors and input width divisible by four")
    if not torch.isfinite(W).all() or not torch.isfinite(X).all():
        raise ValueError("nonfinite calibration data")
    scores = W.abs() * X.norm(p=2, dim=0)[None, :]
    blocks = scores.reshape(W.shape[0], -1, 4)
    # Stable ordering defines what happens when scores tie.
    pruned = blocks.argsort(dim=-1, stable=True)[..., :2]
    keep = torch.ones_like(blocks, dtype=torch.bool)
    keep.scatter_(dim=-1, index=pruned, value=False)
    keep = keep.reshape_as(W)
    return W * keep, keep

torch.manual_seed(7)
W = torch.randn(128, 256)
X = torch.randn(1024, 256)  # 1,024 valid calibration tokens
W_pruned, keep = wanda_2_4_mask(W, X)
assert torch.all(keep.reshape(128, -1, 4).sum(-1) == 2)
assert torch.all((W_pruned.reshape(128, -1, 4) != 0).sum(-1) <= 2)
# Zeros do not change the allocation of a dense tensor.
assert W_pruned.numel() * W_pruned.element_size() == W.numel() * W.element_size()

# Authored one-row counterexample: compare the same input, not a model score.
w = torch.tensor([[0.01, 0.2, 0.3, 2.0]])
x = torch.tensor([[100.0, 1.0, 1.0, 1.0]])
w_wanda, _ = wanda_2_4_mask(w, x)
w_magnitude = w.clone()
w_magnitude[:, :2] = 0
original = x @ w.T
print(original.item(), (x @ w_magnitude.T).item(), (x @ w_wanda.T).item())
# Approximately 3.5, 2.3, 3.0. These figures concern this input only.
```

밀집 저장량이 같다는 검사는 의도적입니다. 압축이나 가속을 얻으려면 지원되는 희소 표현으로 내보내고 메타데이터와 커널 경로를 검증해야 합니다. 이 Python 마스크 생성 시간을 서빙 커널의 성능처럼 측정하지 마세요.

## 5. SliceGPT: 밀집 행렬의 차원 줄이기

SliceGPT는 계산의 불변성을 이용해 표현의 기저를 바꾼 뒤, 보정 데이터의 주성분 방향으로 유지할 차원을 선택합니다 [[3]](#ref-3). 연결된 모든 연산을 일관되게 변환하면 전체 직교 기저 변환은 계산을 보존할 수 있습니다. **정보를 잃는 단계는 차원을 제거할 때입니다.** 활성화 분산이 낮다고 해서 해당 방향에 잡음만 있거나 드문 작업에 쓸모없다는 뜻은 아닙니다.

결과 행렬은 더 작은 밀집 행렬이므로 일반 밀집 커널에서 실행하기 쉬워질 수 있습니다. 타일 정렬·변환 지원·중간 차원의 변화·워크로드가 실제 실행 시간을 결정합니다. 내보낸 모델을 원본과 같은 품질·문맥·동시 요청 조건에서 비교하세요.

## 7. 희소성 비율을 넘어 배포 조건 선택하기

| 방법 | 가중치를 선택하거나 조정하는 기준 | 런타임 이득에 필요한 조건 |
|---|---|---|
| Magnitude | 가중치 크기로 제거할 원소 선택 | 내보낸 패턴과 커널이 남은 계산의 비용을 줄여야 합니다. |
| SparseGPT | 희소성 제약 아래 국소 복원과 보상 | 지원 희소 레이아웃·호환 연산 형상·실측 워크로드 이득이 필요합니다. |
| Wanda | 가중치 크기와 활성화 노름의 곱, 보상 갱신 없음 | 같은 레이아웃·커널 검사가 필요합니다. 보정 비용이 작다고 서빙도 빠른 것은 아닙니다. |
| SliceGPT | 일관된 기저 변환과 차원 제거 | 작아진 밀집 연산이 효율적이어야 하며 요구 품질을 유지해야 합니다. |

기본 체크포인트·가지치기와 보정 데이터 명세·마스크 또는 변환한 차원·토크나이저와 템플릿·런타임 버전·해시를 하나의 아티팩트 묶음으로 보존합니다. 기본·도메인 능력, 안전성, 형식·도구 동작, 최대 메모리, 지연 시간, 처리량을 미리 정한 기준과 비교하세요. 롤백할 수 있도록 원본도 보관합니다. 이러한 방법으로 품질과 자원 예산을 동시에 맞출 수 없다면, 다음 절에서 별도로 학습한 작은 모델로 지식을 옮기는 증류를 살펴봅니다.
