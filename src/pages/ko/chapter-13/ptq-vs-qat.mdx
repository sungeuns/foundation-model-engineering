# 13.1 학습 후 양자화(PTQ)와 양자화 인식 학습(QAT)

700억 개의 BF16 가중치는 토큰을 하나도 처리하지 않아도 140 GB를 차지합니다. 가중치당 4비트를 쓴다면 가중치 자체는 35 GB입니다. 여기에 스케일과 양자화하지 않은 레이어, KV 캐시, 실행용 버퍼가 더해집니다. 그만큼 줄인 뒤에도 모델이 중요한 입력에 올바른 답을 내는지 확인해야 합니다.

**학습 후 양자화(PTQ)** 는 이미 학습한 체크포인트를 변환합니다. **양자화 인식 학습(QAT)** 은 목표 정밀도로 계산한 결과를 순전파에서 모사하면서 가중치를 조정합니다. [가중치 여덟 개로 만든 실습](#quantization-grid-example)에서 두 방식의 순전파와 역전파를 비교할 수 있습니다.

---

## 1. 선형 양자화의 수학적 이해 (Linear Quantization)

아핀 양자화(affine quantization)는 양수인 스케일 $S$, 정수 제로 포인트 $Z$, 그리고 $q_{\min}$ 에서 $q_{\max}$ 까지의 정수 구간을 사용합니다. 실수 $x$ 에 해당하는 코드 $q$ 를 구한 뒤 이 구간으로 제한합니다 [[2]](#ref-2).

$$
q = \operatorname{clip}\left(\operatorname{round}(x/S) + Z, q_{\min}, q_{\max}\right).
$$

정수 커널은 곱의 합을 정수로 누적한 뒤 스케일을 적용할 수 있습니다. 가중치만 양자화하는 커널 중에는 값을 복원한 다음 곱하는 방식도 있습니다. 스칼라 하나의 복원식은 다음과 같습니다.

$$
x_{\text{approx}} = S \times (q - Z)
$$

이 절에서는 $Z=0$ 인 대칭 격자를 사용합니다. $b$ 비트에서 $K=2^{b-1}-1$ 로 두고 $-K$ 부터 $K$ 까지의 코드를 씁니다. 저장 형식에서 가장 작은 음수 코드 하나는 쓰지 않습니다. 양수 $a$ 를 복원 범위의 상한으로 정하면 간격은 $S=a/K$ 입니다. 0은 정확히 0으로 복원하고, 두 코드의 한가운데에 있는 값은 PyTorch와 같이 짝수 쪽으로 반올림합니다 [[3]](#ref-3).

## 2. Post-Training Quantization (PTQ)

PTQ는 사전 학습된 체크포인트를 낮은 정밀도 표현으로 변환합니다. 단순 반올림부터 데이터 기반 오차 보정과 재구성까지 여러 방법이 있으며, 모든 방법이 가중치를 그대로 동결하거나 활성값 캘리브레이션을 요구하는 것은 아닙니다. 가중치만 양자화하거나 데이터 없이 변환하는 방법도 있습니다.

### 캘리브레이션의 범위

정적 활성값 양자화에서는 대표 입력으로 범위를 추정합니다. 표본 수, 도메인·길이·언어 분포, 클리핑 목표를 기록해야 합니다. 분포 변화는 포화와 오차를 늘릴 수 있지만 반드시 치명적인 붕괴를 일으키는 것은 아닙니다. 활성값 분포, 포화율, 미노출 평가와 실제 커널의 출력을 함께 검사합니다.

### PyTorch를 이용한 캘리브레이션 루프 엔지니어링

정적 INT8에서 텐서당 스케일을 하나 쓰려면 **지금까지 본 모든 보정 배치** 의 최댓값을 기억해야 합니다. 첫 배치에서 절댓값 2.0을 봤고 마지막 배치는 0.25까지만 나왔다고 해 봅시다. 마지막 배치로 스케일을 덮어쓰면 1.0만 입력해도 0.25에서 포화됩니다. 누적 min/max 관측기는 배치가 바뀌어도 앞서 본 극값을 보존합니다 [[4]](#ref-4).

> **CPU FP32 예제.** 가중치가 고정된 선형 레이어 하나에서 입력과 가중치의 양자화를 모사합니다. 스케일 버퍼를 체크포인트에 함께 저장합니다. 비트 패킹, 정수 커널, 채널별 스케일, 전체 모델 평가는 생략했습니다.

```python
import torch
from torch import nn

class PTQLinear(nn.Module):
    def __init__(self, in_features, out_features):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(out_features, in_features))
        self.bias = nn.Parameter(torch.zeros(out_features))
        self.register_buffer("act_scale", torch.tensor(0.0))
        self.register_buffer("weight_scale", torch.tensor(0.0))

    @torch.no_grad()
    def calibrate(self, x):
        # Keep extrema across batches of the same frozen checkpoint.
        if x.ndim < 1 or x.shape[-1] != self.weight.shape[1] or x.numel() == 0:
            raise ValueError("expected a nonempty batch with the layer's input width")
        peaks = torch.stack((x.abs().amax(), self.weight.abs().amax()))
        if not torch.isfinite(peaks).all():
            raise ValueError("nonfinite calibration data or weights")
        scales = (peaks / 127).clamp_min(torch.finfo(self.weight.dtype).tiny)
        self.act_scale.copy_(torch.maximum(self.act_scale, scales[0]))
        self.weight_scale.copy_(scales[1])

    def forward(self, x):
        if self.act_scale.item() == 0:
            raise RuntimeError("calibrate the layer or load its calibrated state")
        weight_codes = (self.weight / self.weight_scale).round().clamp(-127, 127)
        input_codes = (x / self.act_scale).round().clamp(-127, 127)
        accumulated = nn.functional.linear(input_codes, weight_codes)
        return accumulated * self.act_scale * self.weight_scale + self.bias

layer = PTQLinear(1, 1).eval()
with torch.no_grad():
    layer.weight.fill_(1)
    layer.calibrate(torch.tensor([[2.0]]))
    layer.calibrate(torch.tensor([[0.25]]))
    probes = torch.tensor([[1.0], [3.0]])
    restored = PTQLinear(1, 1).eval()
    restored.load_state_dict(layer.state_dict())
    torch.testing.assert_close(restored(probes), torch.tensor([[128 / 127], [2.0]]))
```

보존한 활성값 스케일은 $2/127$ 입니다. 복원한 레이어에 1.0을 넣으면 $128/127$, 3.0을 넣으면 2.0이 나옵니다. 가중치와 편향만 저장하면 이 동작을 재현할 수 없습니다. 포화율과 과업 품질은 보정에 쓰지 않은 입력으로 평가하세요.

## 3. Quantization-Aware Training (QAT): 능동적 접근

QAT에서는 학습할 가중치를 부동소수점으로 보관하고 순전파에서는 양자화한 값을 모사해 손실을 구합니다. 옵티마이저가 가중치를 움직여 반올림 경계를 넘게 할 수 있습니다. 그만큼 추가 학습 데이터와 연산이 드니, 같은 평가와 서빙 커널에서 변환한 모델이 잃었던 성능을 회복했는지 확인해야 합니다.

### Straight-Through Estimator (STE)의 수학적 속임수

같은 반올림 구간 안에서는 입력을 조금 움직여도 복원 값이 그대로입니다. 실제 도함수는 그 구간에서 0이고 출력이 뛰는 경계에서는 정의되지 않습니다. STE(straight-through estimator)는 학습에 쓸 대리 기울기를 정하는 방법입니다 [[1]](#ref-1). 이 예제에서는 스케일을 고정하고 $r=\operatorname{round}(x/S)$ 를 먼저 계산합니다. $-K\leq r\leq K$ 이면 상위 기울기를 그대로 전달하고 그 밖에서는 0을 전달합니다. **반올림한 코드** 에 적용하는 규칙이므로, 최대 복원 값보다 조금 큰 입력에도 기울기가 흐를 수 있습니다.

### STE를 활용한 Fake Quantization 엔지니어링

> **CPU FP32 예제.** 가중치 양자화 연산 하나의 순전파와 역전파를 확인합니다. 레이어의 스케일은 기울기 계산에서 분리한 가중치로 구합니다. 여덟 값을 쓰는 테스트에서는 경계 동작이 드러나게 스케일을 고정합니다. 전체 학습 루프, 비트 패킹, 스케일 학습, 서빙 커널은 생략했습니다.

```python
import torch
from torch import nn

class RoundClampSTE(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, limit):
        rounded = torch.round(x)
        ctx.save_for_backward(rounded.abs() <= limit)
        return rounded.clamp(-limit, limit)

    @staticmethod
    def backward(ctx, grad_output):
        (in_range,) = ctx.saved_tensors
        return grad_output * in_range, None

def fake_quantize(tensor, scale, bits=4):
    limit = 2 ** (bits - 1) - 1
    return RoundClampSTE.apply(tensor / scale, limit) * scale

class QATLinear(nn.Module):
    def __init__(self, in_features, out_features, bits=4):
        super().__init__()
        if not 2 <= bits <= 8:
            raise ValueError("this example supports 2 to 8 bits")
        self.weight = nn.Parameter(torch.randn(out_features, in_features) * 0.02)
        self.bias = nn.Parameter(torch.zeros(out_features))
        self.bits = bits

    def forward(self, x):
        limit = 2 ** (self.bits - 1) - 1
        scale = (self.weight.detach().abs().amax() / limit).clamp_min(torch.finfo(self.weight.dtype).tiny)
        return nn.functional.linear(x, fake_quantize(self.weight, scale, self.bits), self.bias)

# A fixed calibration scale makes rounding and clamping visible separately.
w = torch.tensor([-2, -1.25, -0.75, 0, 0.25, 1.25, 1.6, 2.0], requires_grad=True)
reconstructed = fake_quantize(w, scale=0.5, bits=3)
reconstructed.sum().backward()
torch.testing.assert_close(reconstructed, torch.tensor([-1.5, -1, -1, 0, 0, 1, 1.5, 1.5]))
torch.testing.assert_close(w.grad, torch.tensor([0., 1., 1., 1., 1., 1., 1., 0.]))
```

복원 값을 모두 더하면 각 입력에 도달하는 상위 기울기는 1입니다. 복원 값이 같아도 어떤 기울기를 통과시켰는지 구별할 수 있습니다. 아래 실습에서도 같은 여덟 값을 사용합니다.

## 4. 메모리와 혼합 정밀도 설계

학습 담당자는 먼저 어떤 가중치를 업데이트할지와 원본 가중치를 어떤 정밀도로 유지할지 정합니다. 그런 다음 파라미터, 기울기, 옵티마이저 상태, 활성값, 임시 버퍼, 분산 통신, 체크포인트와 평가에 드는 자원을 따로 계산합니다. 양자화를 모사한 중간 텐서를 메모리에 저장하는지, 연산을 한 커널로 합치는지에 따라서도 비용이 달라집니다. 비교할 때는 정밀도와 시퀀스 길이, 상태를 장치에 나누는 방식, 활성값 재계산 여부를 함께 기록하세요. QAT가 일반 학습이나 LoRA에 비해 얼마나 더 많은 메모리를 쓸지는 이 조건에 달려 있습니다.

혼합 정밀도를 설계할 때는 텐서나 레이어의 정밀도를 하나씩 바꾸고 품질이 얼마나 달라지는지 측정합니다. 첫 레이어와 마지막 레이어도 이렇게 확인할 후보입니다. 스케일을 학습하면 격자 간격이 바뀌지만 비트 수는 별도로 정해야 합니다. 서빙 담당자는 실제 장비와 커널이 지원하는 저장 형식에서 품질과 실행 시간을 비교합니다. 가중치 정밀도와 KV 캐시 정밀도도 구분해서 기록합니다.

실험을 재현하려면 기반 체크포인트, 토크나이저와 대화 템플릿, 보정·학습 데이터 목록, 학습 목적, 양자화 단위, 옵티마이저와 학습률, 학습할 모듈, 최대 응답 길이, 배포에 쓸 커널을 고정하세요. 참조 모델을 쓰면 버전을, 쓰지 않으면 그 사실을 남깁니다. 지도 미세조정(SFT)에는 토크나이저의 대화 템플릿을 사용합니다. 어시스턴트 응답에만 손실이 적용되는지, 시작·종료 토큰(BOS/EOS), 잘림과 패딩 처리가 의도와 맞는지 확인하세요. 길이가 다른 응답의 손실을 어떤 분모로 평균 내는지, 여러 샘플을 한 시퀀스로 묶어도 서로의 토큰을 볼 수 없는지도 검사합니다. 평가 자료는 보정·학습에서 격리하고 데이터의 출처, 라이선스, 필터 버전, 샘플 식별자와 샤드별 해시를 보관합니다.

학습 중에는 배치 식별자와 함께 토큰당 손실을 기록하고 도메인별 성능과 기반 모델의 역량 유지 여부를 추적합니다. 수치 이상은 NaN·무한대와 오버플로 발생 횟수, 기울기와 활성값의 노름, 포화율과 양자화 오차로 확인합니다. 학습이 느려지면 처리량과 연산 장치 활용률(MFU), 데이터를 기다린 시간, 집합 통신에 걸린 시간, 뒤처지는 작업자를 함께 살펴봅니다. 미리 정한 수치 안정성 또는 품질 기준을 벗어나면 학습을 중단합니다.

복구 담당자는 분산 저장한 모델·옵티마이저 상태, 학습률 스케줄러와 손실 스케일러, 난수 생성기, 데이터 샘플러와 다음에 읽을 위치, 아티팩트 해시를 체크포인트에 보관합니다. 배포용 가중치, 스케일, 비트 패킹 정보, 커널 요구 사항에는 체크섬을 붙이고 전체가 준비된 뒤 한꺼번에 공개합니다. 복원과 직전 버전으로의 롤백을 실제로 연습하세요. 출시 전에는 내보낸 모델을 배포 커널로 실행해 같은 입력에 대한 품질, 안전성, 출력 형식과 도구 호출, 지연 시간, 비용, 오류율을 기존 버전과 짝지어 비교합니다. 학습 단계에서 양자화를 모사한 결과만으로는 이 검사를 대신할 수 없습니다.

### FP4 전문가 가중치의 헤더에 I8이 적힌 이유는?

2026-11-25 기준, 바이두는 **ERNIE 5.5 Flash Preview** 의 가중치를 세 가지 형식으로 공개했습니다. Preview 가중치의 라이선스는 Apache 2.0입니다. 기본판은 블록 단위 FP8과 MXFP4 전문가 가중치를 함께 씁니다. 각 체크포인트의 safetensors 인덱스에서 같은 전문가 가중치인 `model.layers.1.block_sparse_moe.experts.0.w1.weight`를 찾아 해당 샤드의 헤더를 읽으면 다음과 같습니다. [[5]](#ref-5)

| Preview 체크포인트 | 헤더의 저장 자료형 | 저장된 텐서의 모양 | 가중치만 차지하는 용량 |
| --- | --- | --- | --- |
| 기본판 [[6]](#ref-6) | `I8` | 2048 × 1024 | 2 MiB |
| FP8 [[7]](#ref-7) | `F8_E4M3` | 2048 × 2048 | 4 MiB |
| BF16 [[8]](#ref-8) | `BF16` | 2048 × 2048 | 8 MiB |

기본판은 1바이트에 4비트 가중치 두 개를 담으므로 한 행의 길이가 절반입니다. 여기에 스케일도 더해야 합니다. 같은 샤드에 든 `w1.weight_scale_inv`는 2048 × 64개의 `F8_E8M0` 값으로 128 KiB를 차지합니다. 파이썬 표준 라이브러리로 기본판 샤드의 처음 256 KiB만 요청해 헤더를 확인할 수 있습니다. [[5]](#ref-5) [[6]](#ref-6)

```python
import json

url = ("https://huggingface.co/baidu/ERNIE-5.5-Flash-Preview/resolve/"
       "ace1100dcde7bf4eb06add6ae11ce4f43a11ddfe/model-00002-of-00128.safetensors")
with urlopen(Request(url, headers={"Range": "bytes=0-262143"}), timeout=30) as response:
    header_bytes = int.from_bytes(response.read(8), "little")
    header = json.loads(response.read(header_bytes))
key = "model.layers.1.block_sparse_moe.experts.0.w1.weight"
print(header[key]["dtype"], header[key]["shape"])  # I8 [2048, 1024]
```

헤더로 확인한 것은 가중치의 저장 방식입니다. 학습 과정은 바이두의 모델 카드에 따로 나옵니다. 바이두는 사후 학습 중 라우터가 선택하는 전문가에 W4A8 QAT를 적용해 서빙 형식에 맞춰 양자화를 모사했다고 설명합니다. FP4 커널이 없는 환경에는 FP8판이나 BF16판을 안내합니다. 어느 쪽이 더 빨리 응답하는지 판단하려면 같은 프롬프트와 배치 크기로 실제 장비에서 측정해야 합니다. [[5]](#ref-5)

## 5. 인터랙티브 시각화: 양자화 오차 시뮬레이터

**3비트** 에서 복원 범위의 상한을 **1.5** 로 두면 코드는 −3부터 3까지 일곱 개이고 간격은 0.5입니다. 1.25를 스케일로 나누면 2.5이므로 짝수 코드 2를 택하고 1.0으로 복원합니다. 이제 1.6과 2.0을 비교해 보세요. 둘 다 1.5로 복원되는데, QAT에서 기울기가 흐르는 쪽은 어느 쪽일까요?

QAT를 누르면 1.6은 코드 3으로 반올림돼 기울기 1을 전달합니다. 2.0은 코드 4로 반올림된 뒤 3으로 잘리므로 기울기가 0입니다. 모드를 바꿔도 여덟 값의 순전파 결과는 그대로입니다. 이 설정에서는 반올림한 코드 두 개가 잘리고, 가중치 평균제곱오차는 0.095입니다. 비트 수나 복원 범위를 바꾸면 표의 모든 값이 다시 계산됩니다. 표에서는 입력한 소수를 정확한 값으로 취급합니다. 실제 커널에서 이진 부동소수점 근사로 중간값의 어느 한쪽에 놓이면 반올림 결과가 달라질 수 있습니다.

## 6. 요약 및 비교

| 특징 | Post-Training Quantization (PTQ) | Quantization-Aware Training (QAT) |
| :--- | :--- | :--- |
| **복잡도** | 보정·변환, 작업 부하에 따라 다름 | 추가 학습·적응 |
| **필요 데이터** | 알고리즘에 따라 대표성 있는 보정셋 또는 data-free 방식 | 목적에 맞는 대표성 있는 적응 데이터 |
| **정확도 유지력** | format·보정·모델·과업에 따라 다름 | 일부 저비트 품질을 회복할 수 있으나 보장은 아님 |
| **메모리 오버헤드** | 보정 통계·임시 텐서·방법에 따라 다름 | 학습 상태·커널 구현에 따라 다름 |
| **최적 사용 사례** | 제한된 적응 예산의 압축 | PTQ가 품질 기준을 통과하지 못할 때 적응 |

13.2절에서는 GPTQ와 AWQ가 반올림 오차를 어떻게 다루는지, 그리고 저장된 텐서의 형식을 GGUF 같은 컨테이너가 어떻게 기술하는지 살펴봅니다.

## Quizzes

<details>
<summary>Quiz 1: 캘리브레이션 데이터에서의 좋은 결과만으로 배포 품질을 판단하면 안 되는 이유는 무엇인가요?</summary>
*정적 활성값 범위는 미노출 분포에서 포화나 정밀도 손실을 일으킬 수 있습니다. 독립적인 도메인·길이별 평가와 내보낸 커널의 출력을 확인해야 합니다. 모든 PTQ 방식이 정적 활성값 캘리브레이션을 쓰는 것은 아닙니다.*
</details>

<details>
<summary>Quiz 2: 반올림 연산의 실제 도함수만 쓰면 가중치 업데이트는 어떻게 될까요?</summary>
*평평한 구간에서는 도함수가 0이므로 이 경로로 가중치를 움직일 수 없습니다. STE는 대리 기울기를 써서 가중치가 격자 경계를 넘어갈 수 있게 합니다. 다른 기울기 추정 방법도 있습니다.*
</details>

<details>
<summary>Quiz 3: 혼합 정밀도를 선택할 때 어떤 검증이 필요한가요?</summary>
*층별 민감도, 실제 포맷의 메타데이터·커널 지원, 정확도와 지연 시간을 측정해야 합니다. 첫 층과 마지막 층이 항상 가장 민감한 것은 아니며 균일한 정밀도가 구현과 실행 효율에서 유리할 수도 있습니다.*
</details>

<details>
<summary>Quiz 4: QAT는 PTQ와 무엇이 다르며 왜 항상 더 좋지는 않나요?</summary>
*QAT는 학습 중 양자화 오차를 모사해 가중치를 적응시키지만, PTQ는 이미 학습된 가중치를 변환합니다. 이점은 데이터·예산·정밀도·커널에 달려 있으며 실제 export 아티팩트의 품질과 비용을 평가해야 합니다.*
</details>

<details>
<summary>Quiz 5: 1.6과 2.0의 복원 값이 같은데 기울기는 왜 다를까요?</summary>
*스케일이 0.5이면 반올림한 코드는 각각 3과 4입니다. 두 번째만 최대 코드 3을 넘어서므로 이 대리 기울기 규칙에서는 두 번째 기울기만 막힙니다. 역전파에서 스케일은 고정합니다.*
</details>
