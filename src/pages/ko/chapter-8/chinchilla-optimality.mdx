# 8.2 Chinchilla 최적성

고정 학습 예산에서 큰 모델을 짧게 학습할까요, 작은 모델에 더 많은 토큰을 보여 줄까요? Chinchilla는 이 배분 문제를 명시합니다. Hoffmann 등은 모델 400개 이상을 학습하고 해당 실험 설정에서 모델 크기와 토큰 수를 대략 함께 늘리는 배분을 찾습니다 [[1]](#ref-1). 경험적 스케일링 결과이며 물리 법칙이나 모든 모델의 파라미터당 토큰 의무량은 아닙니다.

## 1. 목적에 따라 달라지는 최적점

파라미터 수를 $N$, 학습 토큰을 $D$, dense 학습의 근사 FLOPs를 $C$ 라고 합시다. 흔히 쓰는 $C\approx6ND$ 는 시퀀스 길이·아키텍처·시스템 오버헤드의 중요한 부분을 생략합니다. 적합한 손실 모형은 다음 형태일 수 있습니다.

$$
L(N,D)=E+\frac{A}{N^\alpha}+\frac{B}{D^\beta}.
$$

$E$ 는 적합한 불가약 항, $A,B>0$ 은 규모 계수, $\alpha,\beta>0$ 는 측정한 감소율입니다. 코퍼스·토크나이저·모델군·최적화·적합 구간에 따라 달라집니다. $D=C/(6N)$ 을 대입해 모형의 손실을 최소화하면 다음과 같습니다.

$$
N^*\propto C^{\beta/(\alpha+\beta)},\qquad D^*\propto C^{\alpha/(\alpha+\beta)}.
$$

두 지수가 비슷하면 두 배분은 대략 계산량의 제곱근에 비례합니다. 비율에는 적합 계수도 영향을 줍니다. 지수가 같다고 모든 모델군에서 하나의 비율이 성립하지는 않습니다.

논문의 Chinchilla 사례는 70B 파라미터·약 1.4T 토큰을 사용하고 비슷한 학습 예산에서 더 큰 Gopher보다 좋은 결과를 보고합니다 [[1]](#ref-1). 그 구간에서 파라미터당 약 20토큰이 유용한 역사적 경험칙입니다. 100B 토큰에 적용하면 5B 파라미터라는 **배분 예시** 가 나오지만 새 코퍼스·제품의 최적 모델을 보장하지 않습니다.

## 2. 가정을 명시한 계산기

인터랙티브는 계산량·모델 크기·토큰의 관계를 보이기 위해서만 $D=20N$ 을 고정합니다. $N_B,D_B$ 를 십억 개 단위, $C_Z$ 를 $10^{21}$ FLOPs 단위로 두면 다음과 같습니다.

$$
C_Z\approx0.006N_BD_B=0.12N_B^2.
$$

단위 변환이 중요합니다. FLOPs는 연산량이고 FLOP/s는 처리량입니다. 하드웨어 시간에는 실효 활용률·통신·오버헤드가 추가로 작용합니다. MoE 활성 계산·전체 저장 파라미터·어텐션 계산·상태 메모리는 따로 계산해야 합니다.

## 3. 배분을 검증하는 방법

다음은 실행 가능한 학습 레시피가 아닌 실험 계약입니다.

| 계약 | 기록할 근거 |
|---|---|
| 입력 | 출처·라이선스/동의·PII/삭제 계보·필터 버전·혼합 가중치·샤드/표본 ID가 있는 불변 데이터 manifest, 토크나이저·코드/설정 해시 |
| 목적 | 토큰 정규화 다음 토큰 교차 엔트로피와 도메인 슬라이스, 손실 마스크·BOS/EOS·잘림·패딩·packing 경계·가변 길이 집계 |
| 결정적 하이퍼파라미터 | 모델 폭/깊이·총 토큰·시퀀스 길이·토큰 배치·optimizer/학습률·warmup/decay·시드·정밀도, 실험 예산별 스케줄 조정 |
| 계산·메모리 | 파라미터·기울기·optimizer 상태·activation·임시 버퍼·collective·체크포인트·평가를 분리하고 sharding·재계산 명시 |
| 관측 지표 | 토큰/도메인별 학습·검증 손실, nonfinite/overflow, 기울기/activation norm, 처리량·MFU·데이터 대기·collective/straggler 시간과 재구성 가능한 batch ID |
| 중단·복구 | 사전 수치/품질 임계값, sharded 모델/optimizer·scheduler/scaler·RNG·sampler·정확한 데이터 커서와 해시의 원자적 저장, checksum·보존·복제·복원 연습 |
| 평가·릴리스 | 손대지 않은 도메인·기반 역량 유지·안전·형식/도구·지연·비용·오류 게이트와 대응 불확실성, 담당자·관측 기간·롤백 리허설 |

관련 문서·합성 형제를 먼저 묶은 뒤 학습/개발/평가로 나누고, 공개·비공개 벤치마크·루브릭·의미 이웃·교사 변형을 모든 학습 혼합에서 격리하세요. 비교 가능한 실험으로 스케일링 계수를 맞추고 잔차·외삽 불확실성을 평가합니다. 부적절한 스케줄이나 누출된 검증셋은 잘못된 최적점을 만들 수 있습니다.

계산기에서 시간·GPU 수·학습 품질 보장이 나오지는 않습니다. FLOPs를 측정한 용량 계획으로 바꾸고 평가·복구 예산을 남기며 대규모 실행 전에 체크포인트 재개 동등성을 검증하세요. 분산 학습 장에서 실행 계약을 다룹니다.

## 4. 학습 최적과 배포 최적은 다릅니다

고정 학습 FLOPs에서 사전 학습 손실을 최소화하는 것과 목표 품질에서 전체 생애 비용을 최소화하는 것은 다릅니다. 작은 모델에 토큰을 더 쓰는 방식은 반복 추론에 유리할 수 있지만 품질·트래픽·서빙 절감이 추가 학습을 정당화할 때만 그렇습니다. 데이터 재사용·양질 데이터의 희소성·추론 지연·라이선스·보존 제약이 선택을 바꿉니다.

같은 후속 probe·릴리스 기준으로 여러 체크포인트/토큰 배분을 평가하세요. 학습·적응·평가·저장·성공 과업당 총 서빙 비용을 포함합니다. 8.3절은 과도 학습으로 논의를 확장합니다. 파라미터 수나 고정 토큰 비율만으로 경제적 결정을 내릴 수는 없습니다.
