# 8.1 신경망 스케일링 법칙과 손실 예측

연산 예산을 두 배로 늘리면 검증 손실이 3.4% 줄어든다는 예측을 받았습니다. 여기서 3.4%는 무엇을 기준으로 계산했을까요? 곡선에 양의 하한이 있으면 **전체 손실** 과 **하한을 뺀 초과 손실** 의 감소율이 달라집니다. [두 예산의 손실을 직접 비교](#scaling-loss-floor)해 보면 큰 학습의 비용을 추정할 때 확인할 숫자가 보입니다.

<a id="경험적-발견-the-empirical-discovery"></a>

## 기존 연구는 무엇을 측정했을까?

Hestness 등은 여러 분야에서 학습 데이터가 늘 때 테스트 오차가 멱법칙을 따르는 구간을 관찰했습니다 [[1]](#ref-1). Kaplan 등은 언어 모델의 교차 엔트로피를 서로 다른 세 조건에서 측정했습니다. 데이터가 충분할 때 임베딩을 제외한 파라미터 수 $N$ 에 대한 지수는 약 0.076이었습니다. 큰 모델을 조기 종료하며 데이터셋 크기 $D$ 를 바꾼 경우에는 약 0.095, 충분한 데이터를 두고 학습 연산량 $C$ 를 최적으로 배분했을 때는 약 0.050이었습니다. 논문의 식 (1.1–1.3)은 측정한 범위에서 **전체 테스트 손실** 에 직접 멱함수를 맞췄습니다 [[2]](#ref-2).

연산 예산을 어떻게 배분할지는 지수 하나로 결정할 수 없습니다. Kaplan 등은 데이터셋보다 모델 크기를 더 빠르게 늘리는 배분을 제안했습니다. 이후 Hoffmann 등은 파라미터 수와 학습 토큰 수를 모두 바꿔 실험했습니다. 주어진 연산량에서 손실이 가장 작았던 지점들을 따라가면 두 수가 대략 같은 **배수** 로 증가했습니다. 밀집 모델의 근사식 $C\propto ND$ 에서 두 수를 각각 두 배로 늘리면 연산량은 약 네 배가 됩니다. 이런 예측은 학습 설정과 목표가 같을 때 적용할 수 있는 조건부 추정입니다 [[2]](#ref-2) [[4]](#ref-4).

## 곡선에서 추정한 하한은 무엇일까?

고정된 검증 세트의 전체 교차 엔트로피를 토큰당 nat 단위로 예측하는 식의 한 예입니다.

$$
L(C) = E + AC^{-\alpha}, \qquad L(C)-E=AC^{-\alpha}.
$$

$C$ 는 일정한 단위로 센 양의 연산 예산이고, $A$ 는 양의 계수, $\alpha$ 는 양의 지수입니다. $E$ 는 이 모형이 가정한 점근값입니다. Hoffmann 등도 파라미터 수와 학습 토큰 수에 따른 손실을 추정할 때 이런 상수항을 뒀습니다. 연구진은 이상적인 경우 이를 주어진 문맥에서 다음 토큰을 예측할 때 남는 불확실성과 연결했습니다 [[4]](#ref-4). 측정한 예산이 몇 개뿐이면 서로 다른 하한과 지수의 조합으로도 관측값을 비슷하게 설명할 수 있습니다. 그래서 추정한 하한 $E$ 에도 오차가 따릅니다. 토크나이저, 문맥 길이, 평가 데이터 분포를 바꾸면 토큰당 손실의 의미 또한 달라질 수 있습니다.

## 전체 손실과 초과 손실 비교하기

설명을 위해 연산 예산 $C$ 를 상대 단위로 놓고 $L(C)=1.5+10C^{-0.05}$ 라는 곡선을 그려 봅시다. $C=100$ 에서 $C=200$ 으로 늘리면 전체 손실은 토큰당 **9.443에서 9.173 nat** 로 줄어듭니다. 양쪽에서 가정한 하한 1.5를 빼면 초과 손실은 **7.943에서 7.673 nat** 가 됩니다. 반올림하기 전 값으로 계산하면 둘 다 토큰당 약 0.271 nat 줄었습니다. 기준이 되는 시작값이 다르므로 **전체 손실은 2.87%**, **초과 손실은 3.41%** 감소합니다.

두 축에 로그를 취하면 초과 손실은 $\log(L-E)=\log A-\alpha\log C$ 라는 직선이 됩니다. 전체 손실에는 상수항이 더해져 기울기가 달라집니다. 아래에서 시작 예산을 열 배로 옮겨 보세요. 새 예산을 다시 두 배로 늘렸을 때도 그대로인 감소율은 어느 쪽인가요?

## 제약과 불확실성을 포함한 외삽

파일럿 학습에서 토크나이저, 데이터 스냅샷, 아키텍처 계열, 평가 방식을 고정합니다. 모델 크기와 학습 토큰 수를 바꾸고 시드를 달리해 반복합니다. 규모에 맞춰 학습률과 워밍업을 조정해야 최적화가 덜 된 모델을 스케일링 효과로 오해하는 일을 줄일 수 있습니다.

아래 PyTorch 예제의 검증 손실 다섯 개는 **설명을 위해 만든 값** 입니다. 작은 규모 네 개만 사용해 계수와 지수는 양수로, 하한은 0과 피팅에 사용한 최소 손실 사이로 제한합니다. 가장 큰 예산의 손실은 예측이 끝난 뒤에 비교합니다. 여기서 연산 예산은 누적 연산 횟수입니다. **1 ExaFLOP = 1,000 PetaFLOPs** 입니다.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

compute_pf = torch.tensor([10., 30., 100., 300., 1_000.])
validation_loss = torch.tensor([4.65, 4.02, 3.52, 3.18, 2.91])

class ConstrainedPowerLaw(nn.Module):
    def __init__(self, min_observed_loss):
        super().__init__()
        self.raw_amplitude = nn.Parameter(torch.tensor(1.0))
        self.raw_exponent = nn.Parameter(torch.tensor(-2.0))
        self.raw_floor_fraction = nn.Parameter(torch.tensor(0.0))
        self.register_buffer("min_loss", min_observed_loss)

    def forward(self, compute):
        amplitude = F.softplus(self.raw_amplitude)
        exponent = F.softplus(self.raw_exponent)
        floor = self.min_loss * torch.sigmoid(self.raw_floor_fraction)
        return amplitude * compute.pow(-exponent) + floor

training_compute = compute_pf[:-1]
training_loss = validation_loss[:-1]
model = ConstrainedPowerLaw(training_loss.min())
optimizer = torch.optim.Adam(model.parameters(), lr=1e-2)
for _ in range(5_000):
    prediction = model(training_compute)
    loss = F.mse_loss(torch.log(prediction), torch.log(training_loss))
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()

with torch.no_grad():
    forecast = model(compute_pf[-1]).item()
actual = validation_loss[-1].item()
print(f"forecast={forecast:.3f}, actual={actual:.3f}, error={forecast - actual:+.3f}")
```

코드를 실행하면 예측값은 **2.921**, 예제에서 따로 남겨 둔 값은 **2.910** 입니다. 토큰당 **0.011 nat** 만큼 높게 예측한 셈입니다. 홀드아웃 오차를 보면 작은 규모 네 개로, 그중 가장 큰 예산의 약 3.3배인 학습을 얼마나 잘 예측했는지 알 수 있습니다. 규모별로 파일럿을 반복했다면 같은 규모 안에서 학습 실행 단위로 부트스트랩 재표집한 뒤 곡선을 다시 맞춰 보세요. 예측 손실의 분포, 최대 규모 제외(leave-largest-out) 오차, 검증한 최대 연산 배수를 함께 보고합니다. 실제 예산을 결정할 때는 다운스트림 평가 결과와 실측 FLOP/s로 계산한 GPU 시간도 비교해야 합니다. 평가·체크포인트 저장·재시작 시간도 비용에 포함하세요.

## 손실은 조금 줄었는데 정확도가 뛸 수 있는 이유

보기가 두 개인 문제에서 정답에 부여한 확률이 0.49에서 0.51로 바뀌었다고 합시다. 정답의 로그 손실은 약 0.713 nat에서 0.673 nat로 조금 줄어듭니다. 반면 확률이 높은 보기를 고르면 이 한 문제의 점수는 0점에서 1점이 됩니다. 벤치마크 평균이 얼마나 뛸지는 이런 경계를 넘은 문항 수에 달려 있습니다. Schaeffer 등은 조사한 과제에서 채점 방식이 겉보기 임계점을 만들 수 있음을 보였습니다 [[3]](#ref-3). 모델 능력이 달라졌는지 판단하려면 문항별 확률의 변화도 점수와 함께 살펴보세요.
