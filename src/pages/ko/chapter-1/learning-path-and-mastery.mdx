# 1.5 학습 경로와 숙련도를 입증하는 방법

설명을 읽고 이해하는 것과 실패한 실험의 원인을 스스로 찾아내는 것은 다릅니다. 이 책을 **유도하기 → 구현하기 → 측정하기 → 반례 찾기 → 판단하기** 의 순서로 활용하세요. 좋은 학습 포트폴리오에는 읽은 페이지 목록보다 재현 가능한 증거와 틀렸던 가설이 담겨 있습니다.

## 출발점 진단하기

먼저 모델의 도움 없이 풀어보세요. 그다음 모델에게 풀이를 비판하게 하고, 어떤 생각을 바꾸었는지 기록합니다.

| 과제 | 정답 확인 | 막힌다면 |
|---|---|---|
| `[B,H,T,D]` 쿼리와 전치한 키를 곱하면 어떤 shape이 나오나요? | `D` 축을 축약하므로 점수는 `[B,H,T,T]`입니다. | 3.1–3.2로 돌아가 각 연산의 차원을 적어봅니다. |
| 입력에 이미 들어 있는 토큰 `t`를 예측하면 왜 손실이 비정상적으로 낮아질 수 있나요? | 정답이 보이기 때문입니다. 입력·정답을 한 칸 어긋나게 배치하고 인과 마스크를 적용해야 합니다. | 4.2를 읽은 뒤 7.5 실습을 실행합니다. |
| 2개 토큰의 손실 합이 4이고 7개 토큰의 합이 14이면 전체 평균은 얼마인가요? | 18/9 = 2입니다. 지역 평균의 단순 평균도 같은 것은 우연히 두 평균이 같아서입니다. 두 번째 합이 7이면 정답은 11/9이며 1.5가 아닙니다. | 6.6의 토큰 수가 다른 배치 예제를 유도합니다. |
| 100회 시험에서 실패가 없으면 실패율이 0.1% 미만이라고 할 수 있나요? | 아닙니다. 독립 Bernoulli 시행을 가정해도 단측 95% 상한은 약 2.95%입니다. | 출시 기준을 해석하기 전에 17.7을 실습합니다. |

선수 지식은 Python 함수와 배열, 행렬 곱, 미분과 연쇄 법칙, 로그, 조건부 확률과 기댓값입니다. 부족한 부분이 드러나면 작은 계산으로 그 의존성을 먼저 해결하세요. 수식은 실행 가능한 계산이 무엇인지 설명해야 합니다.

## 진입 경로를 고르고 공통 핵심으로 합류하기

| 경로 | 읽는 순서 | 만들어야 할 증거 |
|---|---|---|
| 아키텍처와 학습 | 1–4 → 6.1–6.3 → 6.6 → 7.5 → 5와 7 → 8–10 | 올바른 인과 디코더, 최적화 유도, 재실행 가능한 학습, 적응 학습 ablation. |
| 추론과 시스템 | 3–5 → 6.6 → 7.5 → 12–13 → 17.5–17.7 | 메모리 예산, 지연 시간 분포, 배칭·양자화 비교, 롤백 판단. |
| 평가와 에이전트 | 3–4 → 8–10 → 14–16 → 17 → 18 | 격리된 평가셋, 고정된 실행 환경, 대응 비교, 실패 분석과 출시 자료. |
| 멀티모달 연구 | 3–7 → 11 → 17 → 19–20 | 총 연산 예산을 맞춘 구조 비교와 시각·언어 능력 보존 평가. |

경로에 따라 시작점은 달라도 지켜야 할 기준은 같습니다. 모든 경로에 마스킹, 데이터 격리, 자원 계산, 불확실성 해석이 필요합니다. 역사적 설명은 해당 방법이 해결하려 했던 병목을 파악하는 데 활용하세요. 새 아이디어가 익숙한 절충처럼 보일 때 다시 읽으면 도움이 됩니다.

## 세 가지 숙련도 관문

**관문 A — 메커니즘을 설명하고 반증하기.** [최적화 절](../../chapter-6/optimization-mechanics/)과 [디코더 실습](../../chapter-7/tiny-decoder-lab/)을 마칩니다. 문맥 접근을 막으면 어떻게 될지 실행 전에 예측하세요. 목적함수, tensor shape, 손실 마스크, 측정 결과, 인과성 검사, 정확한 재개 결과를 제출합니다. 정답 유출로 낮춘 손실은 통과 증거가 아닙니다.

**관문 B — 제약 아래에서 한 속성 개선하기.** 적응 학습·검색·추론 중 하나를 바꿉니다. 기준 모델, 데이터, 채점기와 자원 예산을 고정하고 개발셋으로 설계를 결정합니다. 관련 사례를 같은 분할에 묶고 적어도 하나의 대안 설명을 검증하세요. 품질·비용·지연 시간 표에 불확실성과 중요한 세부 집단을 포함합니다. 추가 연산이 개선 원인이라면 그렇게 밝힙니다.

**관문 C — 출시 또는 기각 판단 방어하기.** 실제 평가 전에 [17.7 대응 평가 실습](../../chapter-17/experimental-design-and-uncertainty/)을 수행합니다. 불변 산출물 manifest, 독립 출시 평가셋, 사전 기준, 실패 분류, 단계적 배포와 복원 리허설을 제출합니다. 근거 있는 출시 기각도 통과입니다. 중요한 회귀를 확인하지 않은 채 평균 개선만 내세우면 통과할 수 없습니다.

## 종합 과제 평가표

도메인 문서 질의응답, 구조화 추출, 저장소 이슈 분류처럼 경계가 분명한 과제를 고르세요. CPU만 쓰는 과제는 작은 로컬 모델이나 결정론적 검색 기준선을 사용할 수 있습니다. 프론티어 API 구매는 필수가 아닙니다. 확보한 연산 자원으로 검증할 수 없는 파운데이션 모델 관련 주장을 명시합니다.

메커니즘 정확성, 데이터 계보·격리, 공정한 비교, 불확실성·세부 집단, 자원 계산, 복구를 각각 0–2점으로 평가합니다. **0점** 은 없거나 틀림, **1점** 은 설명만 있음, **2점** 은 독립 재현 가능입니다. 정확성과 격리가 모두 2점이 되기 전에는 성능 주장을 받아들이지 마세요. 총점이 높아도 약한 항목을 보완해야 합니다. 이 기준은 편집상 자기 진단 도구이며 공인 자격 기준이 아닙니다.

한 페이지 실험 기록에 질문, 예상 결과, 기준선과 변경점, 통제 변수, 독립 단위, 예산, 중단 규칙, 산출물 해시, 관찰, 대안 설명, 다음 실험을 담으세요. 동료에게 깨끗한 환경에서 재현을 부탁합니다. 작은 실습은 재현성을 연습하는 도구입니다. 폭넓은 전문성에는 낯선 데이터, 지속적인 디버깅, 논문 재현, 다른 엔지니어의 검토도 필요합니다. 연구 재현성 체크리스트로 기록의 빈틈을 점검할 수 있습니다 [[1]](#ref-1).

<summary>Quiz 1: 모델을 출시하지 않기로 한 과제도 성공일 수 있는 이유는 무엇인가요?</summary>
*평가하는 능력은 신뢰할 수 있는 추론과 공학적 판단입니다. 중요한 회귀를 재현하고 후보를 기각하는 것이 평균 개선만 보고 출시하는 것보다 강한 역량 증거입니다.*
</details>

<summary>Quiz 2: 어텐션은 설명하지만 정답 유출을 찾지 못한다면 어느 관문이 미완성인가요?</summary>
*관문 A입니다. 입력·정답 이동과 인과적 가시성 같은 불변 조건을 구현하고 검증해야 합니다. 말로 설명하는 것만으로는 충분하지 않습니다.*
</details>

<details>
<summary>Quiz 3: 데이터 격리가 0점이면 총점이 높아도 부족한 이유는 무엇인가요?</summary>

</details>
