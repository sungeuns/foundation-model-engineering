# 16.4 멀티 에이전트 협업

멀티 에이전트는 작업을 나누고 독립적인 검토 문맥을 마련하는 한 방법입니다. 역할 프롬프트만으로 전문가 역량이나 오류의 독립성이 생기지는 않습니다. 같은 모델과 근거를 쓰는 에이전트들은 같은 실수를 반복할 수 있고, 서로의 답을 읽으면서 틀린 합의에 도달할 수도 있습니다. 추가 통신 비용을 감수할 만큼 분업이 유용한지 먼저 평가해야 합니다.

## 1. 통신 구조 선택하기

AutoGen, MetaGPT와 토론 연구는 서로 다른 협업 구조를 탐색합니다. [[1]](#ref-1) [[2]](#ref-2) [[3]](#ref-3) 아래 표는 설계상의 절충을 정리한 것이며 성능 순위가 아닙니다.

| 구조 | 적합할 수 있는 작업 | 확인할 실패 |
| :--- | :--- | :--- |
| 순차 파이프라인 | 의존 단계가 명확한 작업 | 앞선 오류의 전파; 후속 단계의 수정 경로 |
| 관리자–작업자 | 나눌 수 있는 조사·구현 | 관리자의 병목, 정보 손실, 중복 작업 |
| 독립 검토와 토론 | 근거를 비교할 수 있는 후보 평가 | 상관된 오류, 동조, 반복 비용 |

순차 실행도 모델 출력까지 결정적으로 만들지는 않습니다. 토론의 합의는 중단 조건일 수 있지만 정답 인증은 아닙니다. 같은 총 토큰·시간·도구 예산에서 단일 에이전트, 독립 샘플링, 협업 시스템을 비교하고 오류율과 지연 시간 분포를 보고합니다.


## 2. 블랙보드와 충돌 관리

블랙보드는 구조화된 산출물을 공유 저장소에 기록하고 필요한 부분만 읽게 하는 설계입니다. 긴 대화 기록의 반복 전달을 줄일 수 있지만 요약이 중요한 근거를 버릴 수도 있습니다. MetaGPT의 SOP는 역할과 작업 흐름을 명시하는 사례이며 모든 출력이 맞는다는 보장은 아닙니다. [[2]](#ref-2)

산출물에 작업·버전 ID, 원본 근거, 소유자, 완료 상태, 의존성을 포함합니다. 동시에 수정할 수 있다면 비교 후 교체나 잠금 같은 충돌 정책이 필요합니다. 부수 효과가 있는 도구 호출에는 중복 방지 키, 권한 경계와 재시도·복구 규칙을 둡니다.

임베딩 거리는 모순 판정이 아닙니다. 비슷한 두 문장이 서로 반대일 수 있고, 다른 두 문장이 모두 참일 수도 있습니다. 충돌하는 주장을 출처·시점·범위와 함께 보존하고 검사기, 추가 근거 또는 책임 있는 판정으로 해결합니다. 벡터 평균은 사실 중재가 아닙니다.


## 3. 잠재 상태 통신의 조건

호환되는 표현과 학습된 인터페이스가 있다면 텍스트 대신 잠재 상태를 전달하는 구조를 연구할 수 있습니다. 같은 차원의 벡터라고 의미 공간까지 같은 것은 아닙니다. KV 캐시는 층 구조, 위치 인코딩, 체크포인트, 텐서 형태와 실행 상태에 묶여 있으므로 임의의 API 모델 사이에 그대로 전달할 수 없습니다.

> **학습되지 않은 텐서 연산 예제.** 무작위 벡터에 교차 어텐션을 적용해 형태만 보여 줍니다. 에이전트 협업이나 속도·품질 개선을 입증하지 않습니다. 실제로는 표현 정렬, 통신 목표, 체크포인트 호환성, 학습·평가 데이터, 마스킹·위치·장치·dtype 계약과 장애 복구가 필요합니다. 패딩 마스크의 true는 제외할 작업자 토큰입니다.

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class MultiAgentAttentionRouter(nn.Module):
    """
    A neural router for latent-space multi-agent communication.
    Allows a Manager agent to query the hidden states of multiple Worker agents
    using Cross-Attention, aggregating insights without decoding to text.
    """
    def __init__(self, hidden_dim: int = 1024, num_heads: int = 8):
        super().__init__()
        self.hidden_dim = hidden_dim

        # Cross-Attention: Manager queries, Workers provide Keys and Values
        self.cross_attention = nn.MultiheadAttention(
            embed_dim=hidden_dim,
            num_heads=num_heads,
            batch_first=True
        )

        # Feed-forward network to process the aggregated latent state
        self.ffn = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim * 4),
            nn.GELU(),
            nn.Linear(hidden_dim * 4, hidden_dim)
        )

        self.layer_norm1 = nn.LayerNorm(hidden_dim)
        self.layer_norm2 = nn.LayerNorm(hidden_dim)

    def forward(self, manager_query: torch.Tensor, worker_states: torch.Tensor, worker_padding_mask=None):
        """
        Args:
            manager_query: Tensor of shape (Batch, Seq_Len_M, Hidden_Dim)
                           The current latent state of the Manager agent.
            worker_states: Tensor of shape (Batch, Num_Workers * Seq_Len_W, Hidden_Dim)
                           The concatenated latent states of all Worker agents.

        Returns:
            aggregated_state: Tensor of shape (Batch, Seq_Len_M, Hidden_Dim)
                              The updated Manager state infused with Worker insights.
        """
        if worker_padding_mask is not None and worker_padding_mask.all(dim=1).any():
            raise ValueError("each example needs at least one unmasked worker token")
        # Manager queries the workers' states
        attn_output, attn_weights = self.cross_attention(
            query=manager_query,
            key=worker_states,
            value=worker_states,
            key_padding_mask=worker_padding_mask
        )

        # Residual connection and LayerNorm
        x = self.layer_norm1(manager_query + attn_output)

        # FFN with residual connection
        ffn_output = self.ffn(x)
        aggregated_state = self.layer_norm2(x + ffn_output)

        return aggregated_state, attn_weights

# --- Execution Example ---
if __name__ == "__main__":
    batch_size = 2
    hidden_dim = 64
    manager_seq_len = 16   # e.g., Manager's current thought vector length
    worker_seq_len = 64    # e.g., Each worker's latent scratchpad length
    num_workers = 3        # e.g., Coder, Searcher, QA

    # Initialize the Router
    router = MultiAgentAttentionRouter(hidden_dim=hidden_dim, num_heads=8)

    # Simulate Manager's current latent state
    manager_query = torch.randn(batch_size, manager_seq_len, hidden_dim)

    # Simulate latent states from 3 different workers
    worker_1_state = torch.randn(batch_size, worker_seq_len, hidden_dim)
    worker_2_state = torch.randn(batch_size, worker_seq_len, hidden_dim)
    worker_3_state = torch.randn(batch_size, worker_seq_len, hidden_dim)

    # Concatenate worker states along the sequence dimension to form the Key/Value pool
    combined_worker_states = torch.cat([worker_1_state, worker_2_state, worker_3_state], dim=1)
    # Shape: (2, 192, 64)

    # Route and aggregate
    updated_manager_state, attention_map = router(manager_query, combined_worker_states)

    print(f"Manager Query Shape: {manager_query.shape}")
    print(f"Combined Worker States Shape: {combined_worker_states.shape}")
    print(f"Updated Manager State Shape: {updated_manager_state.shape}")
    print(f"Attention Map Shape: {attention_map.shape}")
    # Attention Map Shape: (Batch, Manager_Seq, Total_Worker_Seq)
```

## 5. 실무적 정리

검토의 독립성, 근거의 품질과 복구 가능한 상태가 에이전트 수보다 중요할 수 있습니다. 총 작업 예산과 중단 조건을 정하고 결과물을 검증하세요. 다음 절에서는 이런 산출물을 장기 기억으로 보존할 때 필요한 출처·갱신·삭제 계약을 다룹니다.

</details>
