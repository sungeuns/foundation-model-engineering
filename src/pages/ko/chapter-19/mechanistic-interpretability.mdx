# 19.1 기계론적 해석 가능성

`A B X A`를 입력했더니 모델이 다음 토큰으로 `B`를 골랐다고 해보겠습니다. 학습 데이터에서 `A` 다음에 `B`가 자주 나와서일까요? 아니면 방금 본 두 토큰을 따라 쓴 걸까요? 이 예측 하나로는 구분하기 어렵습니다. 앞부분을 `A C X A`로 바꿔 보면 두 설명을 구별할 단서가 생깁니다. **기계론적 해석 가능성** 은 여기서 한 걸음 더 들어가, 모델 내부의 어떤 계산 때문에 답이 달라졌는지 묻습니다.

<a id="1-motivation-and-history"></a>

## 1. 예측이 달라진 이유 찾기

Olah 등은 이미지에서 곡선을 감지하는 회로를 조사하면서 앞선 층에서 어떤 특징을 전달받는지 추적했습니다 [[1]](#ref-1). 트랜스포머에서는 토큰 위치 사이의 정보 전달 경로를 살펴볼 수 있습니다. 어텐션 헤드는 한 위치에서 값을 읽고 다른 위치의 잔차 스트림에 더합니다. 이 경로에서 값을 기록하거나 바꾼 뒤 특정 출력이 얼마나 달라지는지 측정할 수 있습니다 [[2]](#ref-2).

<a id="왜-mechanistic-interpretability-가-필요한가"></a>

가령 검색된 문서에는 새 배송일이 적혀 있는데 챗봇은 계속 옛 날짜를 답한다고 해보겠습니다. 문서의 날짜를 바꿔 보면 답이 문서에 의존하는지 알 수 있습니다. 날짜를 바꾼 상태에서 특정 헤드의 출력만 원래 실행에서 기록한 값으로 되돌려 보면, 그 헤드가 날짜를 전달한다는 가설을 시험할 수 있습니다. 다른 날짜와 다른 문서에서도 같은 현상이 나타나는지 확인해야 원인을 좁힐 수 있습니다.

<a id="2-the-linear-representation-hypothesis"></a>

## 2. 선형 표현 가설

모델의 상태를 기록하면 좌표별 숫자가 나옵니다. 예측에 쓰이는 정보는 여러 좌표에 걸쳐 있을 수 있습니다. **선형 표현 가설** 에 따르면 단수와 복수 같은 구별이 벡터 공간의 한 방향에 나타날 수 있습니다. Park 등은 개념을 읽어 내는 경우와 개념에 개입하는 경우를 나누어 선형 표현의 의미를 수식으로 정리했습니다 [[4]](#ref-4).

토큰 하나의 잔차 상태를 $h \in \mathbb{R}^d$, 같은 $d$차원 공간에서 길이가 1인 방향 벡터를 $v$라고 합시다. 좌표계를 정하고 내적 $s=h^\top v$를 구하면 $h$에서 $v$ 방향의 성분을 읽을 수 있습니다. 이 점수로 단수와 복수가 구분되는지는 따로 시험해 봐야 합니다. 명사 몇 개로 방향을 구한 뒤, 다른 문장에 등장하는 새로운 명사에 적용해 보세요.

<a id="임의의-기저arbitrary-basis-문제"></a>

### 좌표가 달라져도 같은 방향일 수 있다

평면에서 좌표축 하나와 일치하는 방향은 $(1,0)$으로 적을 수 있습니다. 좌표축을 비스듬히 돌리면 같은 방향도 두 성분에 걸쳐 표현됩니다. 직교 좌표계에서 $h$와 $v$를 함께 변환하면 내적은 그대로입니다. 따라서 좌표 번호만 보고 그 좌표가 어떤 개념을 담당한다고 말하기는 어렵습니다. 방향 하나로 개념을 구분해 냈더라도 모델이 예측할 때 그 정보를 쓰는지는 또 다른 질문입니다. [19.3절에서 선형 프로브로 이 차이를 살펴봅니다.](../probing-classifiers/)

<a id="3-circuits-and-induction-heads"></a>

## 3. 귀납 헤드는 어디를 읽을까?

모델 안에서 여러 계산이 연결되어 특정 일을 수행할 때 그 경로를 **회로** 라고 부릅니다. Elhage 등은 어텐션 층만 있는 작은 트랜스포머에서 서로 다른 층의 두 헤드가 협력해 입력의 일부를 이어 쓰는 회로를 분석했습니다 [[2]](#ref-2). Olsson 등은 이 동작을 문맥 내 학습과 관련지었습니다. 두 현상의 인과관계에 대한 근거는 연구진이 직접 개입한 작은 모델에서 가장 분명했습니다 [[3]](#ref-3).

<a id="induction-head-의-알고리즘"></a>

### 토큰 한 칸 차이가 중요한 이유

`A B X A`의 위치를 0번부터 3번까지 매겨 보겠습니다. 이전 토큰을 읽는 헤드는 0번의 `A`에 관한 정보를 1번의 잔차 상태에 더합니다. 1번 토큰은 여전히 `B`입니다. 다만 이제 1번에는 바로 앞 토큰이 무엇이었는지에 관한 정보도 담겨 있습니다.

| 위치 | 입력 토큰 | 뒤쪽 층에서 알 수 있는 직전 토큰 |
| --- | --- | --- |
| 0 | A | 이 예시에는 앞 토큰이 없음 |
| 1 | B | A |
| 2 | X | B |
| 3 | A | X |

뒤쪽 층의 **귀납 헤드(induction head)** 는 3번의 `A`로 질의를 만듭니다. 바로 앞 토큰이 `A`였다는 단서가 붙은 곳은 **1번** 입니다. 여기서 값을 읽으면 **4번** 위치에 올 토큰을 예측할 때 `B` 쪽에 힘이 실릴 수 있습니다. 처음 `A`가 나온 곳은 0번, 그 뒤를 이어 쓰기 위해 값을 읽는 곳은 1번, 다음 토큰을 예측하는 계산이 일어나는 곳은 3번입니다. [[3]](#ref-3)

<a id="qk-와-ov-회로"></a>

### 어디를 읽는지와 무엇을 더하는지

행벡터 표기에서 $W_QW_K^\top$는 질의와 키가 얼마나 잘 맞는지를 결정합니다. $W_Q$와 $W_K$는 각각 잔차 상태를 질의와 키로 투영하는 가중치입니다. 기본적인 어텐션에서는 점수의 크기를 조정하고 미래 위치를 가린 뒤 읽을 수 있는 위치들 사이에서 가중치를 정규화합니다. 한편 $W_VW_O$는 읽어 온 상태가 어떤 값으로 바뀌어 잔차 스트림에 더해지는지를 나타냅니다. $W_V$는 값 투영, $W_O$는 출력 투영 중 이 헤드에 해당하는 부분입니다. 이후의 층과 최종 어휘 출력층도 답에 영향을 줍니다. 이 헤드가 더하는 벡터를 0으로 만들어도, 어텐션 가중치는 여전히 1번에 쏠릴 수 있습니다. [[2]](#ref-2)

## 4. PyTorch에서 한 층의 어텐션 기록하기

순전파 훅으로 기록할 수 있는 것은 모듈이 반환한 값입니다. PyTorch의 `MultiheadAttention`에서는 가중치를 반환하고 헤드별 값을 유지하도록 지정합니다. 설정에 따라 가중치가 생략되거나 여러 헤드의 평균이 반환될 수 있습니다. [[6]](#ref-6)

> **예제가 다루는 범위.** 가중치를 무작위로 초기화한 어텐션 층을 CPU에서 평가 모드로 실행합니다. 입력은 패딩 없는 시퀀스 하나이며 KV 캐시는 사용하지 않습니다. 가중치 행렬을 명시적으로 반환하는 방식으로 실행합니다. 전체 행렬을 저장하려면 배치 크기 $B$, 헤드 수 $H$, 시퀀스 길이 $T$에 대해 $O(BHT^2)$개의 원소가 필요합니다. 융합 커널을 쓰는 사전 학습 모델은 가중치를 다른 방식으로 노출할 수 있습니다.

```python
import torch
from torch import nn

torch.manual_seed(7)
attention = nn.MultiheadAttention(8, 2, batch_first=True).eval()
x = torch.randn(1, 4, 8)  # 배치, 토큰 수, 은닉 차원
future = torch.ones(4, 4, dtype=torch.bool).triu(1)
captured = []

def capture(_module, _inputs, output):
    captured.append(output[1].detach())

handle = attention.register_forward_hook(capture)
try:
    with torch.no_grad():
        attention(x, x, x, attn_mask=future,
                  need_weights=True, average_attn_weights=False)
finally:
    handle.remove()

weights, = captured
assert weights.shape == (1, 2, 4, 4)
assert torch.count_nonzero(weights[..., future]) == 0
torch.testing.assert_close(weights.sum(-1), torch.ones(1, 2, 4))
print(tuple(weights.shape))  # (1, 2, 4, 4)
```

축 순서는 배치, 헤드, 질의 위치, 키 위치입니다. 위의 네 토큰 예시에서 확인할 항목은 `weights[0, head, 3, 1]`입니다. 코드의 검증문은 미래 위치가 가려지고 행마다 합이 1인 행렬을 올바르게 기록했는지 확인합니다. 이 층은 토큰을 이어 쓰도록 학습한 적이 없습니다.

## 5. 앞서 나온 토큰 쌍을 바꿔 보기

아래 도구가 따르는 규칙은 하나입니다. 마지막 토큰과 같은 토큰이 앞에서 등장한 곳을 찾고, 그 바로 뒤 토큰을 읽습니다. 앞쪽 `B`를 `C`로 바꿔 본 다음 헤드의 출력을 0으로 설정해 보세요. 그때도 그대로인 것은 무엇인가요? 이 도구는 조건에 맞는 위치와 복사 후보를 표시합니다. 학습된 가중치나 예측 확률은 사용하지 않습니다.

<InductionHeadVisualizer client:visible lang="ko" />

`A` 뒤에 한 번은 `B`, 한 번은 `C`가 왔다면 둘 다 후보입니다. 학습된 모델에서는 한쪽을 더 강하게 참조할 수도, 두 곳에 가중치를 나눌 수도 있습니다. 다른 경로의 영향으로 전혀 다른 토큰을 예측할 수도 있습니다.

<a id="induction-probe"></a>

### 헤드 하나의 출력을 끄면 예측은 얼마나 달라질까?

사전 학습한 SmolLM2-135M에 `[BOS] A B x y C z w A` 순서로 토큰을 넣고 CPU에서 실행했습니다. 각 글자는 서로 다른 어휘 ID이고, 마지막 `A`만 앞에서 한 번 나온 토큰입니다. 모델이 앞선 짝을 보고 다음 토큰을 예측한다면 `C`보다 `B`에 높은 점수를 줄 겁니다. 그럼 앞쪽의 `B`와 `C` 자리만 맞바꾸면 어떨까요? 입력에 쓰인 토큰도, 마지막 쿼리 `A`도 그대로지만 이번에는 `C`가 유리해야 합니다. [[7]](#ref-7)

먼저 입력 16개로 살펴볼 헤드를 골랐습니다. 쿼리 헤드 270개 각각에 대해 마지막 위치에서 2번 위치(첫 `A` 바로 다음 자리)에 주는 어텐션 가중치를 쟀습니다. 마지막 `A`를 처음 등장하는 토큰 `D`로 바꾼 뒤 다시 쟀더니, 두 값의 평균 차이가 가장 큰 곳은 18번 층의 6번 헤드였습니다(번호는 0부터 시작). 헤드를 고르는 데 쓴 어휘 ID와 겹치지 않는 **새 입력 32개** 로 시험했습니다. 마지막에 `A`를 되풀이했을 때 이 헤드가 2번 위치에 준 가중치는 평균 **78.17%**, 새 토큰 `D`를 넣었을 때는 **0.084%** 였습니다.

이 헤드가 읽은 정보가 실제 예측에 얼마나 기여했을까요? 마지막 위치에서 어텐션 출력 투영을 적용하기 직전에 헤드 하나의 출력 벡터를 0으로 만들었습니다. 표는 새 입력 32개에서 `B`의 로짓에서 `C`의 로짓을 뺀 평균값입니다. 양수이면 모델이 `B`를 더 유력하게 본다는 뜻입니다. 원래 순서에서 측정한 값에서 두 자리를 맞바꿨을 때의 값을 빼면, 토큰 순서가 모델의 선호를 얼마나 움직였는지 알 수 있습니다.

| 마지막 위치에서 바꾼 조건 | 원래 순서 | B와 C의 자리를 바꾼 뒤 | 두 순서의 차이 |
| --- | ---: | ---: | ---: |
| 모든 헤드를 그대로 둠 | 6.55 | −7.06 | 13.61 |
| 18번 층 6번 헤드의 출력 제거 | 4.86 | −5.35 | 10.21 |
| 같은 층의 이웃인 7번 헤드의 출력 제거 | 6.31 | −6.90 | 13.21 |

6번 헤드의 출력을 끄자 순서를 바꾼 효과가 줄었습니다. 그래도 예상한 방향으로 점수가 움직인 입력은 32개 중 30개였습니다. 모든 헤드를 그대로 뒀을 때는 32개였습니다. 이 예측을 뒷받침하는 경로가 더 있다는 뜻입니다. 여기서 비교한 것은 합성 입력에 대한 후보 토큰 두 개의 상대 점수입니다. 전체 어휘에서 각각 몇 등을 했는지 알려면 다른 후보들의 로짓도 봐야 하고, 어느 앞쪽 층이 이 헤드에 정보를 전달했는지는 별도 실험이 필요합니다.

## 6. 특징에서 회로까지 추적하기

Ameisen 등은 2025년 회로 추적 연구에서 언어 모델의 일부 층을 근사하는 모델을 학습했습니다. 이를 이용해 특정 입력에서 해석 가능한 특징 사이에 어떤 기여가 오가는지 그래프로 나타냈습니다 [[5]](#ref-5). 그래프는 어디에 개입해 볼지 알려 줍니다. 결론의 범위는 근사 모델이 원래 동작을 얼마나 충실하게 재현하고, 표시한 경로들이 전체 계산의 얼마를 설명하는지에 달려 있습니다.

배송일 예시로 돌아가 보겠습니다. 새 날짜와 옛 날짜의 로짓 차이를 기록합니다. 날짜만 다른 두 프롬프트 사이에서 원인으로 추정되는 활성값을 바꾸고, 대조군의 다른 활성값을 바꿨을 때와 비교합니다. 처음 분석에 쓰지 않은 날짜와 문서 양식으로도 반복합니다. 개입해도 변화가 없었던 경우까지 기록해야 가설이 어디까지 맞는지 알 수 있습니다.

*0번부터 세면 질의 위치는 3번입니다. 처음 A 다음에 C가 있는 1번을 읽고, 4번 위치의 후보로 C를 밀어 줄 수 있습니다.*
</details>

<details>
<summary>Quiz 2: 1번 위치에 어텐션 가중치가 쏠리는데도 헤드의 출력을 0으로 바꾼 뒤 같은 답이 나왔습니다. 무엇을 알 수 있을까요?</summary>
*헤드가 그 위치를 읽었고, 이번 조건에서 개입해도 관찰한 답은 달라지지 않았습니다. 헤드가 더한 값이 작았거나 다른 경로가 같은 답을 뒷받침했을 수 있습니다. 최상위 토큰이 그대로여도 로짓은 달라졌을 수 있으니 함께 확인합니다.*
</details>

<details>
<summary>Quiz 3: 선형 프로브가 학습에 사용한 문장에서 복수 명사를 잘 구별합니다. 무엇을 추가로 확인해야 할까요?</summary>
*새로운 명사와 문장 틀에서 서로 대응하는 단수형과 복수형을 검사합니다. 이렇게 하면 프로브가 읽은 정보가 새 사례에도 적용되는지 알 수 있습니다. 모델도 예측에 그 정보를 쓰는지 알아보려면 개입 후 행동 변화를 측정해야 합니다.*
</details>

<details>
<summary>Quiz 4: A B X A C X A에서 정확히 일치하는 토큰만 찾는 규칙은 B와 C 중 어느 쪽을 고를까요?</summary>
*앞서 나온 두 A의 다음 토큰이 모두 보입니다. 1번에는 B, 4번에는 C가 있어 둘 다 후보입니다. 어느 쪽이 실제 예측에서 앞설지 알려면 학습된 어텐션 가중치와 각 위치에서 읽은 값이 어휘 로짓에 미치는 영향까지 알아야 합니다.*
</details>
