# 19.1 Mechanistic Interpretability

현대의 대규모 언어 모델(LLM)은 종종 **블랙박스** (Black Box)로 묘사됩니다. 우리는 테라바이트 단위의 데이터를 주입하고, 경사하강법을 사용해 단순한 목적 함수(다음 토큰 예측)를 최적화합니다. 그리고 그 결과로 논리적 추론, 번역, 코딩과 같은 복잡한 행동이 창발(Emergence)합니다.

**Mechanistic Interpretability** (기계적 해석 가능성, 이하 MechInterp) 는 이 블랙박스를 역공학(Reverse-engineering)하려는 야심 찬 과학적 시도입니다. 모델을 불투명한 통계 엔진으로 취급하는 대신, 컴파일된 컴퓨터 프로그램으로 바라봅니다. 수십억 개의 연속적인 가중치(Weights)를 인간이 이해할 수 있는 알고리즘, 자료구조, 논리 회로로 디컴파일하는 것이 목표입니다.

이는 마치 인공 두뇌를 연구하는 뇌과학이나, 외계 우주선을 역공학하는 것과 같습니다. 우리에게 하드웨어(가중치)는 있지만, 소스 코드는 없는 상태입니다.

---

## 1. Motivation and History

역사적으로 딥러닝은 모델을 더 크고 정확하게 만드는 **Capability** (성능) 에 집중해 왔습니다. 하지만 모델이 단순한 연구 결과물을 넘어 핵심 인프라로 전환됨에 따라, 모델이 *어떻게* 작동하는지 이해하는 것은 행동 평가·실행 통제와 함께 디버깅과 안전 연구를 지원할 수 있습니다.

### 왜 Mechanistic Interpretability 가 필요한가?
1. **Alignment and Safety** (정렬과 안전): 내부 근거는 원치 않는 행동을 조사하는 데 도움이 됩니다. 일부 회로의 설명만으로 안전성을 인증하거나 기만이 없다고 입증할 수는 없습니다.
2. **Debugging Hallucinations** (환각 디버깅): 개입 실험으로 사실 오류의 원인 가설을 검증할 수 있습니다. 지식 편집은 관련 능력을 훼손할 수도 있습니다.
3. **Auditing** (감사): 메커니즘 근거는 기술 감사를 지원할 수 있지만 배포 시스템과 행동 통제의 검증을 대체하지는 않습니다.

이 분야의 현대적 뿌리는 Chris Olah (Distill, OpenAI, Anthropic) 와 같은 연구자들이 주도한 합성곱 신경망(CNN)의 Feature Visualization으로 거슬러 올라갑니다. 초기 연구는 CNN의 얕은 층이 어떻게 엣지(Edge)를 감지하고, 깊은 층이 개 코나 자동차 바퀴 같은 복잡한 개념을 감지하는지 시각화했습니다 [[1]](#ref-1).

Transformer 의 등장과 함께, 연구의 초점은 공간적 특징 맵(Spatial feature maps)에서 **Residual Stream** 과 **Attention Matrices** 로 이동했습니다. Anthropic의 기념비적인 논문인 *A Mathematical Framework for Transformer Circuits* [[2]](#ref-2) 는 현대 MechInterp 의 어휘를 정립하며, Transformer 를 거대한 단일 블록이 아니라 공유 메모리 대역폭(Residual Stream)을 통해 통신하는 'Head'들의 네트워크로 해석했습니다.

## 2. The Linear Representation Hypothesis

회로를 찾기 전에, 신경망이 개념을 어떻게 저장하는지 이해해야 합니다. 유용하고 실증적으로 연구된 가설 중 하나가 **Linear Representation Hypothesis** (선형 표현 가설) 입니다 [[4]](#ref-4). 모든 개념에 맥락과 무관한 하나의 방향이 있다는 증명은 아닙니다.

이 가설은 신경망이 개념(Feature)을 개별 뉴런이 아닌 **활성화 공간(Activation space)의 방향** 으로 표현한다고 가정합니다.

Transformer의 Residual Stream이 고차원 벡터 공간 $\mathbb{R}^d$라면, "성별", "복수형", 또는 "개라는 개념"과 같은 특징은 특정 단위 벡터 $v \in \mathbb{R}^d$ 로 나타납니다. 이 특징의 존재 여부는 활성화 벡터 $h$ 가 이 방향으로 투영(Projection)된 값으로 결정됩니다:

$$
\text{Activation of Feature } i = h \cdot v_i
$$

### 임의의 기저(Arbitrary Basis) 문제
Residual Stream 은 밀집 가중치 행렬(Dense weight matrices)에 의해 변환되기 때문에 (네트워크의 용량을 변경하지 않고도 임의로 회전할 수 있음), 개별 기저 차원(문자 그대로의 뉴런 $h_1, h_2, \dots, h_d$)이 깔끔한 단일 개념과 일치하는 경우는 드뭅니다.

이로 인해 **Polysemanticity** (다의성) 문제가 발생합니다. 즉, 단일 뉴런이 서로 관련 없는 여러 개념에 대해 활성화되는 현상입니다 (예: "거미"와 "프랑스어" 모두에 반응하는 뉴런). 이를 분리하기 위해 Sparse Autoencoders (SAE) 를 사용하는 방법은 19.4장에서 다루겠지만, 지금은 *특징(Feature)은 뉴런이 아니라 방향(Direction)이다* 라는 점만 이해하면 됩니다.

## 3. Circuits and Induction Heads

**Circuit** (회로) 은 인식 가능한 알고리즘을 구현하는 신경망의 부분 그래프(특정 Attention Head와 MLP 뉴런의 집합)입니다.

LLM 에서 발견된 가장 유명하고 근본적인 회로는 **Induction Head** (귀납 헤드) 입니다 [[3]](#ref-3). Induction Head는 가중치 업데이트 없이 프롬프트의 패턴에 적응하는 **In-Context Learning (ICL)** 을 지원하는 한 메커니즘의 근거입니다. 모든 ICL 행동을 설명하지는 않습니다.

### Induction Head 의 알고리즘
Induction Head 는 `[A] [B] ... [A] -> [B]` 와 같은 단순한 패턴을 찾습니다.
만약 `[A]` 라는 토큰을 보게 되면, 과거 컨텍스트에서 이전의 `[A]` 인스턴스를 검색하고, 그 바로 뒤에 온 토큰(`[B]`)을 확인한 후, `[B]` 를 다음 예측 토큰으로 승격시킵니다.

고전적인 attention-only 구현에서는 서로 다른 층의 두 헤드가 협력합니다:

1. **Previous Token Head (Layer $L_1$)**:
   이 헤드는 단순히 현재 토큰 바로 앞의 토큰에 Attention 을 줍니다. `[A]` 의 정보를 `[B]` 의 Residual Stream 위치로 이동시킵니다. 이제 토큰 `[B]` 에는 "내 앞에는 A가 있다"라는 특징(Feature)이 포함됩니다.

2. **Induction Head (Layer $L_2$, 단 $L_2 > L_1$)**:
   모델이 두 번째 `[A]` 인스턴스를 처리할 때, Induction Head 의 Query ($Q$) 는 "내 앞에는 A가 있다"라는 특징을 포함하는 Key ($K$) 를 검색합니다. 이전의 `[B]` 를 찾아 Attention 을 주고, Value ($V$) 투영을 통해 "B-ness(B의 정체성)"를 최종 Residual Stream 에 복사하여 `[B]` 를 예측합니다.

![이전 토큰 헤드와 귀납 헤드의 작동 예시](../../../assets/images/chapter-19/induction_head_circuit.png)

*Olsson et al. [[3]](#ref-3)의 메커니즘을 설명하는 저장소의 교육용 도식입니다. Attention 측정값이 아닙니다.*

### QK 와 OV 회로
MechInterp 는 Attention 을 두 개의 독립적인 연산으로 수학적으로 분해합니다:
* **The QK Circuit ($W_Q W_K^T$)**: 정보를 *어디로* 이동시킬지 결정합니다 (Attention 가중치).
* **The OV Circuit ($W_V W_O$)**: Attention 이 주어졌을 때 *어떤* 정보를 이동시킬지 결정합니다.

Induction Head 의 경우, QK 회로는 "현재 토큰 A"와 "A가 선행된 토큰" 사이의 일치도를 계산합니다. OV 회로는 복사(Copy) 연산으로 작동하여 `[B]` 의 정체성을 추출하고 출력 Logit 에 씁니다.

## 4. Engineering the Interception: PyTorch Hooks

Mechanistic Interpretability 를 수행하려면 단순히 최종 Loss 만 봐서는 안 됩니다. 순전파(Forward pass) 중에 중간 활성화 값(Residual Stream, Attention 행렬, MLP 은닉 상태)을 추출해야 합니다.

Hook은 모듈이 실제로 반환한 값을 관찰합니다. 은닉 상태 텐서에서 attention 확률을 만들어낼 수는 없습니다. 융합 커널은 가중치를 명시적으로 생성하지 않을 수 있고, 출력 튜플의 의미도 모델마다 다릅니다.

> **교육용 예제의 한계:** 아래 함수는 `batch_first=True`인 `torch.nn.MultiheadAttention`에서 헤드별 가중치를 명시적으로 요청하고, 패딩 없이 인과적 배치를 처리하는 예제입니다. 사전 학습 모델 통합을 smoke test한 코드가 아닙니다. 실제 모델 API, 패딩·캐시 의미, device/dtype, 메모리 예산에 맞게 수정해야 합니다. 배치 크기 $B$, 헤드 수 $H$, 시퀀스 길이 $T$일 때 전체 attention 저장 공간은 $O(BHT^2)$입니다.

```python
import torch
from torch import nn

@torch.no_grad()
def capture_attention(module: nn.MultiheadAttention, x: torch.Tensor):
    # x: [B, T, D]; caller supplies matching dtype/device and eval mode.
    if not module.batch_first or x.ndim != 3:
        raise ValueError("Requires batch_first=True and [B, T, D] input")
    captured = []

    def hook(_module, _inputs, output):
        weights = output[1]
        if weights is None or weights.ndim != 4:
            raise RuntimeError("Expected unaveraged [B, H, T, T] weights")
        captured.append(weights.detach().cpu())

    handle = module.register_forward_hook(hook)
    try:
        length = x.shape[1]
        causal_mask = torch.ones(
            length, length, dtype=torch.bool, device=x.device
        ).triu(1)
        module(x, x, x, attn_mask=causal_mask,
               need_weights=True, average_attn_weights=False)
        return captured[0]
    finally:
        handle.remove()
```

귀납 패턴은 설명의 후보입니다. 원본·교란 프롬프트를 비교하고, 제안된 헤드를 제거하거나 활성화를 패치한 뒤 예측한 출력 변화가 생기는지 대조 실험으로 확인해야 합니다. Attention 관찰만으로 ICL의 인과적 책임을 입증할 수는 없습니다.

## 6. Feature에서 Circuit Tracing으로

**2026-10-13 기준 연구 정리.** Circuit tracing은 학습한 feature 표현과 attribution graph를 이용해 중간 계산이 출력에 어떻게 기여하는지 조사합니다. Anthropic의 2025년 방법은 replacement model과 국소 기여도 분석 절차를 설명하며, 충실도와 설명 범위의 한계를 명시합니다 [[5]](#ref-5). 읽기 쉬운 그래프가 원본 모델 전체의 설명인 것은 아닙니다.

Feature 발견은 첫 단계입니다. 어떤 입력에서 활성화되는지, 어떤 후속 계산에 영향을 주는지, 통제된 개입이 그래프가 예측한 행동 변화를 만드는지 물어야 합니다.

실무 조사에는 다음과 같은 접근이 유용합니다.

1. **반복되는 사실 오류:** 중간 후보 예측을 비교하고, 제안한 원인을 patching이나 ablation으로 검증합니다.
2. **튜닝 후 과잉 거부:** 대응되는 정상·금지 요청을 비교하고 행동 변화를 측정합니다. 특정 방향에 안전 보장을 부여하지 않습니다.
3. **Prompt template 차이:** attention 패턴을 가설로 삼고 과제 내용은 고정한 채 개입 실험을 합니다.
4. **RAG 근거 사용:** 근거를 교체하거나 제거하고 출력 민감도를 확인합니다. 문서에 대한 attention·attribution만으로 답이 그 문서에 의존한다고 입증할 수는 없습니다.
5. **편집과 steering:** 개입을 배포하기 전에 관련 능력과 반례를 평가합니다.

이 도구들은 가설을 좁히고, 사고 로그·통제된 행동 평가·권한 경계를 보완합니다. 설명 범위, replacement model의 충실도, 관찰한 프롬프트 밖으로의 일반화는 여전히 한계입니다.

## 7. Summary and Open Questions

**Mechanistic Interpretability** 는 대규모 언어 모델의 내부 메커니즘을 이해하기 위한 엄밀하고 수학적인 프레임워크를 제공합니다. 네트워크를 Linear Representation Hypothesis, QK/OV 회로, 그리고 Induction Head 와 같은 알고리즘적 부분 그래프로 분해함으로써, 우리는 AI 를 연금술로 취급하던 것에서 벗어나 소프트웨어 공학으로 다룰 수 있게 됩니다.

하지만 모델이 수조 개의 파라미터로 확장됨에 따라, 수동적인 회로 발견은 계산적으로나 인지적으로 불가능해지고 있습니다.
* 회로 발견을 어떻게 자동화할 수 있을까요?
* 모델의 세계 지식 대부분을 포함하고 있는 거대한 MLP 레이어는 어떻게 해석해야 할까요?
* 여러 개념이 동일한 뉴런 세트에 쑤셔 넣어질 때(Superposition) 어떤 일이 발생할까요?

이러한 질문에 답하기 위해, 우리는 다음 장인 **19.2 Logit Lens & Attention Visualization** 과 **19.4 Sparse Autoencoders (SAE)** 에서 고급 시각화 기법과 Superposition 문제에 대해 탐구할 것입니다.

*Attention Head 에는 해석하기 쉬운 자연스러운 병목(Bottleneck)인 Attention 행렬이 있습니다. QK 회로는 어떤 토큰들이 통신하고 있는지 명시적으로 알려주고, OV 회로는 무엇이 통신되고 있는지 알려줍니다. 반면, MLP 레이어는 고도로 다의적인(Polysemantic) 뉴런을 가진 거대하고 밀집된 Key-Value 메모리로 작동하기 때문에, Sparse Autoencoders 와 같은 고급 기술 없이는 특정 논리적 라우팅을 분리해내기가 훨씬 더 어렵습니다.*
</details>

<details>
<summary>Quiz 4: QK 관찰만으로 토큰 복사를 입증할 수 없는 이유는 무엇일까요?</summary>
*QK는 attention의 목적지를 설명합니다. Value/output 경로와 embedding·unembedding의 합성이 참조한 정보를 복사 대상 토큰의 예측으로 바꾸는지 결정합니다. 큰 attention 값만으로 복사 연산을 입증할 수는 없습니다.*
</details>
