# 7.5 작은 디코더를 학습하고 검증하고 재개하기

어텐션 수식은 모델을 조립하고 학습시키고 잘못된 개선을 가려낼 수 있을 때 공학적 지식이 됩니다. 이 실습은 다운로드하고 내부를 읽어볼 수 있는 하나의 프로그램으로 3·4·6장을 연결합니다.

## 노트북으로 먼저 실행하기

[Colab에서 한국어 노트북 열기](https://colab.research.google.com/github/sungeuns/foundation-model-engineering/blob/main/public/labs/tiny-decoder-lab-ko.ipynb) 또는 [Jupyter용 노트북 내려받기](../../../labs/tiny-decoder-lab-ko.ipynb)로 시작하세요. CPU 런타임을 사용합니다. 실습에 필요한 기호 데이터를 직접 생성하므로 모델 다운로드나 API 키는 필요하지 않습니다. 로컬에서는 아래 안내에 따라 Python과 PyTorch를 설치하세요. 노트북에는 스크립트와 같은 실습 소스가 들어 있습니다.

실행 전에 두 가지를 예측해보세요. 미래 기호를 바꾸면 이전 위치의 예측도 달라질까요? 앞선 기호를 보지 못하게 하면 복사 성능이 떨어질까요? 셀을 순서대로 실행해 측정값을 살펴보고, 체크포인트에서 재개한 뒤 남은 갱신이 그대로 재현되는지 확인합니다. 장 전체를 먼저 읽지 않아도 노트북에서 각 결과를 설명합니다. 아래 본문은 실험의 정확한 조건과 한계를 다룹니다.

Colab은 GitHub 노트북을 불러와 호스팅된 런타임에서 실행하며, 실행하려면 Google 로그인이 필요합니다. 자원과 세션 유지 시간에는 제한이 있습니다. 내려받은 노트북은 로컬 Jupyter 환경에서도 실행할 수 있습니다. 실행 경로 안내는 **2026-11-18 기준** 확인했습니다. [[3]](#ref-3)

## 범위와 입력 계약

**의도적으로 단순화했으며 smoke test를 거친 교육용 구현입니다.** 한 층짜리 합성 복사 과제이며 언어 사전 학습이나 SFT가 아닙니다. 분산 실행, 혼합 정밀도, chat template, 자연어 데이터, sample packing, 원격 체크포인트 복제, serving을 생략합니다. 프론티어 모델로의 확장성을 입증하지 않습니다. 참조 체크포인트, 교사 모델, judge 모델은 없습니다.

[causal_lab.py](../../../labs/causal_lab.py)를 내려받아 Python 3.12 이상과 CPU PyTorch가 있는 격리 환경에서 실행하세요. 검증 환경은 2026-11-17의 PyTorch 2.15.0+cpu였습니다. 버전이나 하드웨어가 달라도 같은 수치 경로를 보장하지는 않습니다 [[1]](#ref-1).

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install torch==2.15.0 --index-url https://download.pytorch.org/whl/cpu
python causal_lab.py --output /tmp/causal-lab --steps 160 --seed 7
```

설치 명령은 Linux CPU wheel을 대상으로 합니다. 다른 플랫폼은 [공식 설치 안내](https://pytorch.org/get-started/locally/)를 따르세요. 곱셈 스케줄이므로 실제 학습률은 정확히 0.003에 도달하지 않습니다.

로컬 생성기는 ID 1–16에서 서로 다른 기호 네 개를 골라 반복한 17토큰 시퀀스를 만듭니다. 순환 이동한 패턴은 같은 의미 집단으로 묶습니다. 이 정규화는 train/validation/test를 128/16/16개 집단으로 나누기 **전** 에 수행합니다. 외부 문서, 개인정보, 비밀정보, 제3자 데이터 권리는 사용하지 않습니다. 불변 manifest에 생성기 버전, seed, 집단 규칙, 혼합 비율, 정수 tokenizer 버전과 모든 집단의 기호를 기록합니다. 집단 ID는 해시로 재구성할 수 있습니다. 체크포인트는 manifest, 설정, 코드 해시와 PyTorch 버전을 연결합니다.

입력은 `[B,16]`, 출력 logit은 `[B,16,17]`입니다. 처음 네 기호가 관측한 prompt입니다. 위치 3–15의 logit으로 위치 4–16의 정답을 예측하므로 **시퀀스당 감독 대상은 13개** 입니다. 처음 prompt 내부 예측에는 손실을 주지 않습니다. Padding, BOS, EOS, chat template, generation prompt, 가변 길이, sample 간 attention은 없고 ID 0은 쓰지 않습니다. 응답 길이는 이어지는 기호 13개로 고정합니다. 이 tokenizer 정책을 SFT에 옮기면 안 됩니다. [9.1 SFT 기초](../../../ko/chapter-9/sft-fundamentals/)의 tokenizer 고유 템플릿 규칙을 따라야 합니다.

## 메커니즘 조립하기

프로그램은 토큰·위치 임베딩 → 사전 정규화한 인과적 2-head attention → 잔차 더하기 → 사전 정규화한 feed-forward network → 잔차 더하기 → 어휘 투영을 구현합니다. 폭은 32이고 FFN은 GELU와 함께 32 → 64 → 32로 변환합니다. 배치의 각 행은 독립 attention 행렬을 가집니다. 큰 디코더의 일부 레시피와 달리 마지막 정규화 층은 생략합니다. 이 차이도 고정된 실험 구조의 일부입니다.

`MultiheadAttention`에서는 boolean `True`가 해당 위치를 가립니다. 모든 PyTorch attention API가 같은 규약을 쓰는 것은 아닙니다. 정답 이동은 예측할 토큰을 정하고, 마스킹은 볼 수 있는 입력을 정하는 별개의 작업입니다.

Ablation은 매개변수, 초기값, 샘플링, 최적화기, 갱신 예산을 유지하면서 현재 위치 외의 attention을 막습니다. 두 모델 모두 임베딩, 위치 정보, 비선형 층을 가집니다. 앞 기호에 접근할 수 있는지가 성능 차이를 설명하는지 묻는 실험입니다. 실행 시간을 같게 맞추거나 특정 head의 복사 표현을 증명하는 실험은 아닙니다.

## 학습과 자원 계약

AdamW 설정은 학습률 스케일 0.003, betas `(0.9,0.95)`, epsilon `1e-8`, 전체 매개변수 감쇠 0.01, 배치 16입니다. 10회 선형 warmup 계수와 전체 예산에 걸쳐 10% 하한으로 접근하는 cosine 계수를 곱하며 전역 기울기 norm을 1.0으로 클리핑합니다. 160회 갱신으로 감독 토큰 33,280개를 학습합니다. Ablation에도 같은 마스크의 손실 대상과 예산을 적용합니다.

학습 매개변수는 10,161개입니다. FP32 매개변수, 기울기, Adam의 두 moment를 합하면 작은 optimizer counter를 제외하고 약 **158.8 KiB** 입니다. 전체 프로세스 메모리가 아닙니다. 임베딩·잔차, attention 점수, 역전파 버퍼, optimizer 임시값, Python/PyTorch 런타임, 데이터 tensor, 체크포인트 사본과 평가 메모리가 추가됩니다. Sharding, 재계산, collective 통신, 활성 expert 구분은 없습니다. 여유 메모리 1 GiB는 이 작은 CPU 실습을 위한 보수적 계획치이며 측정한 peak가 아닙니다. 확장 추정 전에는 peak RSS를 측정하세요.

`trace.json`에는 토큰 정규화 학습 손실, 학습률, 클리핑 전 기울기 norm, 배치 ID, 감독 토큰 수를 저장합니다. `result.json`에는 보류 손실, 비유한값 횟수, 매개변수 수, 시간과 target 처리량이 들어갑니다. 시간에는 학습, 체크포인트 I/O와 후반부 재실행이 포함되지만 ablation과 보류 평가는 제외됩니다. 검증된 하드웨어 peak/FLOP 모델이 없으므로 MFU는 `null`입니다. 운영용으로 확장할 때는 6.3의 activation·갱신 norm, 데이터 대기, 평가 시간, straggler와 collective도 계측해야 합니다.

## 예측하고 실행한 뒤 설명하기

실행 전에 attention 제한의 효과와 미래 기호를 바꿀 때 이전 logit이 변할지 예측하세요. 프로그램은 인과성 불변 조건을 검사하고 중간 체크포인트를 저장한 뒤 학습을 마칩니다. 이어서 복원해 후반부를 다시 실행합니다. 체크포인트에는 가중치, optimizer moment, step·감독 토큰 수, torch·sampler RNG, 스케줄 정의, 데이터 커서, 설정·manifest 해시가 있습니다. FP32이므로 scaler는 없습니다. 임시 파일을 rename하고 SHA-256 marker가 일치해야 로드합니다. 로컬 복구 교육 절차이지 분산 atomic publication이나 world size 변경 복구는 아닙니다 [[2]](#ref-2).

Seed 7의 기록된 실행에서 검증 손실은 **0.0453**, test 손실은 **0.0508**, 자기 위치만 보는 모델의 test 손실은 **2.7042 nats/target**이었습니다. 유효 기호 16개에 균등 확률을 주는 기준선은 $\log16\approx2.773$입니다. 제공한 합성 과제의 측정값이며 외부 모델 성능 점수가 아닙니다. 정확한 재개와 인과성 검사는 통과했습니다. Greedy 생성의 토큰 정답률은 98.08%, 전체 시퀀스 정답률은 93.75%(보류 시퀀스 16개 중 15개)였습니다. 정답 문맥을 주는 teacher forcing과 자유 생성은 다른 질문에 답합니다. [Seed 7 기록](../../../labs/verified-seed-7.json)에 코드 해시와 예시를 보존했으며 장비별 실행 시간은 제외했습니다. Seed와 실행 환경에 따라 달라질 수 있으므로 이 숫자를 통과 임계값으로 쓰지 말고 직접 재실행하세요.

손실·기울기가 비유한값이 되거나 불변 조건, 체크포인트 무결성, 재개 일치 검사가 실패하면 중단합니다. 검사를 통과하고 보류 비교를 설명하기 전에는 변경한 실습 산출물을 배포하지 않습니다. 이전 정상 스크립트와 출력 폴더를 보존해 되돌릴 수 있게 하세요. Test 결과를 본 뒤 레시피를 바꾸었다면 새 일반화 주장에는 새로운 보류셋이 필요합니다.

## 자신을 속이지 않고 실험 확장하기

1. Seed 7·19·31을 서로 다른 출력 폴더로 반복합니다. 각 결과를 보고하세요. 세 seed는 민감도 점검이지 모든 학습 실행에 대한 정밀한 신뢰구간이 아닙니다.
2. 정답을 올바르게 이동한 버전과 일부러 이동하지 않은 진단용 버전을 비교합니다. 이미 보이는 입력을 예측하는 것이 모델 개선이 아니라 과제 변경인 이유를 설명하세요.
3. 처음 네 기호만 주고 한 번에 한 예측을 덧붙이는 프로그램의 greedy 자기회귀 생성을 살펴봅니다. 정답 이전 기호를 공급하는 teacher-forced 손실과 비교하고 전체 시퀀스 정답률을 셉니다. 초반 오류가 전파될 수 있습니다.
4. 더 긴 패턴과 집단이 겹치지 않는 새 데이터로 바꿉니다. 어떤 메커니즘을 시험하며 위치 암기가 대안 설명인지 적으세요. Test를 열기 전에 validation으로 선택합니다.

Manifest, 코드 해시, trace, 결과, 틀린 가설 하나, 자연어 일반화에 관해 이 실습이 말해주지 못하는 것을 제출하세요. 과제 표본의 불확실성과 학습 seed의 불확실성은 17.7에서 구분합니다.
