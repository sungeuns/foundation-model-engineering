# 2.4 NLP를 위한 CNN (CNNs for NLP)

영화 리뷰에 “This movie was not good at all”이라고 적혀 있습니다. *not* 과 *good* 이 몇 번 나왔는지만 세면 두 단어의 자리를 바꿔도 결과가 같습니다. TextCNN의 필터는 짧은 구절 안에서도 위치마다 다른 가중치를 적용합니다. [직접 계산해 보는 예제](#textcnn-filter-example)에서는 단어 두 개의 순서만 바꿔도 풀링 결과가 2에서 1로 바뀝니다. 분류기는 이런 차이를 문장 레이블을 예측하는 데 쓸 수 있습니다.

## 동기: 속도와 병렬성

일반적인 RNN은 직전 은닉 상태를 구해야 다음 상태를 계산할 수 있습니다. 반면 합성곱 레이어 안에서는 각 위치가 같은 입력의 서로 다른 구간을 읽으므로 여러 위치를 동시에 계산할 수 있습니다. 실제 속도는 레이어 수, 텐서 크기, 커널과 하드웨어에 따라서도 달라집니다.

### 세 단어만 보이는 돋보기

한 번에 세 단어만 보이는 돋보기를 한 단어씩 옮겨 보세요. 멈출 때마다 필터가 한 구간의 점수를 냅니다. 시간축 최대 풀링(max-over-time pooling)은 그 필터에서 가장 큰 응답 하나를 남깁니다. 분류기에 전달되는 숫자만 보고는 어느 구간에서 나온 응답인지 알 수 없습니다.

## 텍스트에서 1D 합성곱이 작동하는 방식

토큰이 $n$ 개이고 토큰마다 임베딩 좌표가 $d$ 개라면 문장 하나를 $X\in\mathbb{R}^{n\times d}$ 행렬로 쓸 수 있습니다. 폭이 $k$ 인 필터에는 $W\in\mathbb{R}^{k\times d}$ 모양의 가중치와 스칼라 편향 $b$ 가 있습니다. 필터는 연속된 토큰 $k$ 개에서 임베딩 좌표 $d$ 개를 모두 읽고 토큰 축을 따라서만 이동합니다.

### 메커니즘

시작 위치를 0부터 세어 $i$ 라 하면 활성화 전 점수는 $z_i=b+\sum_{j=0}^{k-1}W_j\cdot X_{i+j}$ 입니다. 각 내적은 같은 상대 위치의 임베딩과 필터 행을 짝지어 계산합니다. PyTorch의 `Conv1d`는 필터 행의 순서를 유지하는 상호상관(cross-correlation)을 계산합니다 [[5]](#ref-5). 수학에서 정의하는 합성곱은 필터의 순서를 뒤집습니다 [[2]](#ref-2).

한 토큰씩 이동하고 패딩을 붙이지 않으면 $n\geq k$ 일 때 완전한 구간은 $n-k+1$ 개입니다. 각 점수에 ReLU를 적용한 $a_i=\max(0,z_i)$ 를 순서대로 모은 것이 특징 맵입니다. 이 필터의 풀링 결과는 $\max_i a_i$ 입니다.

## 예제: 슬라이딩 윈도우 합성곱 (Sliding Window Convolution)

*not* 의 임베딩은 $(1,0)$, *good* 은 $(0,1)$, 나머지 단어는 모두 $(0,0)$ 으로 둡니다. 두 좌표는 설명을 위해 정한 부정 단서와 긍정 단서입니다. 필터의 세 행은 차례로 $(2,0)$, $(0,1)$, $(-1,2)$ 이고 편향은 $-1$ 입니다. 위치 3에서 시작하는 **not good at** 은 $2+1+0-1=2$ 점을 냅니다. 위치 2에서 시작하는 **was not good** 은 $0+0+2-1=1$ 점입니다. 두 구간에 같은 단서가 들어 있지만 필터 안에서 차지하는 자리가 다릅니다.

단어 순서를 바꾸기 전 다섯 구간의 점수는 $[-1,-2,1,2,-1]$ 입니다. ReLU를 적용하면 $[0,0,1,2,0]$ 이므로 풀링 결과는 2입니다. *not* 과 *good* 을 맞바꾸면 위치 1과 4가 1점으로 공동 최댓값을 냅니다. 두 곳에서 나왔어도 분류기로 전달되는 숫자는 1 하나입니다. 이 값은 계산 과정을 보여 주려고 정한 필터의 응답입니다. 클래스 확률을 얻으려면 학습한 분류기와 확률로 바꾸는 출력 연산이 필요합니다.

## 획기적인 아키텍처들

Kim의 2014년 문장 분류 모델은 폭 3, 4, 5마다 필터를 100개씩 사용했습니다. 필터 하나당 최댓값이 하나이므로 분류기에 들어가는 특징은 $3\times100=300$ 개입니다. 논문은 문장 분류 벤치마크에서 무작위로 초기화한 단어 벡터, 사전 학습한 뒤 고정한 벡터, 미세조정한 벡터 등을 비교했습니다. 학습으로 얻은 필터가 사람이 이름 붙인 언어 규칙과 일대일로 대응할 필요는 없습니다 [[1]](#ref-1).

## PyTorch TextCNN

첫 번째 CPU 예제는 위 실습을 필터 하나로 재현합니다. 가중치 텐서의 모양 `[1, 2, 3]`은 출력 채널 하나, 임베딩 좌표 두 개, 토큰 위치 세 개를 뜻합니다. 입력도 PyTorch가 기대하는 `[배치, 채널, 위치]` 순서에 맞춰 축을 바꿉니다 [[5]](#ref-5).

```python
import torch
import torch.nn.functional as F

def feature_map(sentence):
    embeddings = [[word == "not", word == "good"] for word in sentence.split()]
    inputs = torch.tensor(embeddings, dtype=torch.float32).T.unsqueeze(0)
    # Conv1d weights are [output channel, input channel, window offset].
    kernel = torch.tensor([[[2., 0., -1.], [0., 1., 2.]]])
    raw = F.conv1d(inputs, kernel, bias=torch.tensor([-1.])).flatten()
    return raw, raw.relu()

raw, features = feature_map("This movie was not good at all")
assert raw.tolist() == [-1, -2, 1, 2, -1]
assert features.tolist() == [0, 0, 1, 2, 0]
_, swapped = feature_map("This movie was good not at all")
assert swapped.tolist() == [0, 1, 0, 0, 1]
```

**길이가 다른 문장을 함께 풀링할 때** 는 패딩에 걸친 구간을 빼야 합니다. 실제 토큰의 임베딩은 모두 1, 패딩 임베딩은 0이고 폭 3인 필터의 가중치는 $[-1,-1,-1]$, 편향은 2라고 해 봅시다. 실제 토큰 셋으로 채운 구간은 모두 $-1$ 점이어서 ReLU 출력이 0입니다. 그런데 실제 토큰 다섯 개 뒤에 패딩 두 개를 붙이면 마지막 구간 $[1,0,0]$ 은 1점을 받습니다. 메모리에 할당된 모든 위치를 대상으로 최댓값을 구하면 패딩 때문에 특징값이 커집니다.

아래 CPU 분류기는 **오른쪽에 패딩을 붙인** 배치를 받습니다. 행마다 실제 길이를 넘겨주세요. 길이를 생략하면 입력한 모든 위치를 실제 토큰으로 간주합니다. 폭이 $k$ 일 때 구간의 끝 경계 $i+k$ 가 실제 길이 이하인 경우에만 풀링합니다. 해당 폭의 구간이 하나도 없으면 이 구현은 그 필터의 특징값을 0으로 둡니다. 마스크를 적용하기 전에 임베딩을 조회하므로 패딩 자리에도 어휘 범위 안의 ID가 필요합니다. 이 코드는 세 종류의 필터와 선형 분류기를 구현하며, 사전 학습 벡터나 드롭아웃을 사용하지 않고 학습 과정도 생략합니다.

```python
import torch
from torch import nn
import torch.nn.functional as F

class TextCNN(nn.Module):
    def __init__(self, vocab_size, embed_dim, num_classes):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.conv1 = nn.Conv1d(embed_dim, 100, kernel_size=3)
        self.conv2 = nn.Conv1d(embed_dim, 100, kernel_size=4)
        self.conv3 = nn.Conv1d(embed_dim, 100, kernel_size=5)
        self.fc = nn.Linear(300, num_classes)

    def forward(self, x, lengths=None):
        if x.ndim != 2 or x.size(0) == 0:
            raise ValueError("expected token IDs shaped [batch, positions]")
        batch, slots = x.shape
        if lengths is None:
            lengths = torch.full((batch,), slots, device=x.device)
        else:
            lengths = torch.as_tensor(lengths, device=x.device)
        if lengths.shape != (batch,) or lengths.dtype not in (torch.int32, torch.int64):
            raise ValueError("supply one integer length per example")
        if ((lengths < 0) | (lengths > slots)).any():
            raise ValueError("length outside the supplied sequence")

        embedded = self.embedding(x).transpose(1, 2)  # [batch, channels, slots]
        # Conv1d needs at least the filter width even when no real window fits.
        embedded = F.pad(embedded, (0, max(0, 5 - slots)))
        pooled = []
        for conv in (self.conv1, self.conv2, self.conv3):
            features = conv(embedded).relu()
            width = conv.kernel_size[0]
            starts = torch.arange(features.size(-1), device=x.device)
            complete = starts + width <= lengths[:, None]
            peak = features.masked_fill(~complete[:, None, :], -torch.inf).amax(dim=-1)
            pooled.append(torch.where(lengths[:, None] >= width, peak, 0.0))
        return self.fc(torch.cat(pooled, dim=1))

torch.manual_seed(7)
model = TextCNN(vocab_size=8, embed_dim=2, num_classes=2).eval()
ids = torch.tensor([[1, 2, 3, 4, 5]])
batch = torch.tensor([[1, 2, 3, 4, 5, 0, 0], [5, 4, 3, 2, 1, 6, 7]])
with torch.no_grad():
    torch.testing.assert_close(model(ids)[0], model(batch, lengths=[5, 7])[0])
    # Encode "on" as 1 and "off" as 2.
    logs = torch.tensor([[1, 2, 1, 2, 1, 2], [2, 1, 2, 1, 2, 1]])
    logits = model(logs)
    torch.testing.assert_close(logits[0], logits[1])
```

## 국소 수용장에서 전역 attention으로

이 분류기로 스위치가 마지막에 켜져 있었는지 알 수 있을까요? 스위치 상태를 여섯 번 기록한 `on off on off on off`와 `off on off on off on`을 비교해 보세요. 다섯 칸씩 읽으면 두 기록 모두 `on`으로 시작하는 구간과 `off`로 시작하는 구간이 하나씩 나옵니다. 폭을 3이나 4로 줄여도 두 가지 패턴이 모두 나옵니다. 위 분류기의 각 필터가 읽는 구간의 종류는 두 기록에서 같으므로, 어떤 가중치를 학습해도 필터별 최댓값은 같습니다. 한 스위치는 꺼져 있고 다른 스위치는 켜져 있는데도요. 이 문제라면 마지막 실제 토큰 하나를 읽는 것으로 충분합니다.

폭 $k$ 인 합성곱 레이어를 $L$ 층 쌓고 각 층이 한 칸씩 이동하며 팽창(dilation)이 없으면, 한 출력이 볼 수 있는 입력의 범위는 $1+L(k-1)$ 위치입니다. 팽창 합성곱은 필터가 읽는 위치 사이의 간격을 벌려 이 범위를 넓힙니다. ByteNet은 문자 단위 번역에 팽창 합성곱을 사용했고 [[3]](#ref-3), WaveNet은 자기회귀 오디오 생성에 인과적 팽창 합성곱을 사용했습니다 [[4]](#ref-4). 이 절의 단층 TextCNN은 각 구간을 따로 읽고 문장 전체에 최대 풀링을 적용합니다. 어디에서 발견한 패턴이든 분류에 반영할 수 있지만 발견한 위치는 잃습니다.

</details>

<details>
<summary>Quiz 4: 서로 다른 두 구간이 같은 최댓값을 냈을 때 풀링으로 잃는 정보는 무엇인가요?</summary>
*분류기는 최댓값 하나를 받습니다. 위치 정보를 따로 넘기지 않으면 한 곳에서만 그 값이 나왔는지, 여러 곳에서 나왔는지, 그 위치가 어디인지 구분하지 못합니다.*
</details>

<details>
<summary>Quiz 5: 0으로 패딩해도 최대 풀링 뒤의 로짓이 달라질 수 있는 이유는 무엇인가요?</summary>
*일부만 실제 토큰으로 채워진 구간이 그 토큰의 임베딩과 편향 때문에 더 높은 점수를 낼 수 있습니다. 실제 길이를 넘어서는 구간은 최댓값을 구하기 전에 제외해야 합니다.*
</details>

<details>
<summary>Quiz 6: 레이어의 깊이와 이동 간격에 따라 수용장은 어떻게 달라지나요?</summary>
*팽창이 없으면 $R_0=1$ 에서 시작합니다. 폭이 $k_l$ 인 $l$ 번째 층은 이전 층들의 이동 간격 $s_i$ 에 따라 입력 수용장의 폭을 $(k_l-1)\prod_{i=1}^{l-1}s_i$ 만큼 늘립니다. 폭이 모두 $k$ 이고 이동 간격이 1이면 $R_l=1+l(k-1)$ 입니다.*
</details>
