# 14.3 Advanced Retrieval & Reranking

An exact error code and a description of its symptoms require different retrieval signals. A dense retriever may match the concept while missing an identifier; a lexical retriever may find the identifier while missing a synonym. Hybrid retrieval combines their candidate sets, and reranking spends more computation on the candidates most likely to matter. Neither stage can manufacture evidence absent from the corpus.

## 1. Learned Sparse Retrieval

BM25 scores lexical matches with term-frequency saturation and document-length normalization. An exact identifier can be useful, but a query containing only “automobile” can miss a document containing only “car” unless preprocessing or expansion bridges the terms.

SPLADE learns vocabulary-weighted sparse representations using a masked-language-model head, nonnegative log-saturated weights, pooling, and sparsity regularization [[1]](#ref-1). Expansion can assign weight to a term absent from the original passage. The actual sparsity and retrieval cost depend on the trained checkpoint and indexing policy; there is no universal “95% zero” guarantee. Audit postings volume, query expansion, latency, and relevance together.

## 2. Reciprocal Rank Fusion

Dense similarity and BM25 scores use different scales. Score normalization or learned fusion can work, but calibration may shift across queries and domains. **Reciprocal rank fusion (RRF)** avoids directly comparing these score magnitudes [[2]](#ref-2):

$$
\mathrm{RRF}(d)=\sum_{m\in M_d}\frac{1}{k+r_m(d)}.
$$

Here $d$ is a document, $M_d$ the retrieval lists containing it, $r_m(d)\ge1$ its rank in list $m$, and $k\ge0$ the smoothing constant. An absent document contributes **zero from that list**, rather than receiving an invented rank. Fix candidate depth and tie handling before comparing runs.

The original study used $k=60$; this is a baseline, not a universal optimum. Increasing $k$ compresses rank differences, making repeated appearances relatively influential. It does not require a winner to occur in every list or guarantee that a bad hit cannot win. A document ranked first everywhere has score $|M|/(k+1)$; rank scores are not relevance probabilities.

In the authored example, specialists have ranks $(1,4)$ and $(4,1)$, while the balanced candidate has $(2,2)$. They tie exactly at $k=2$. Below that value the specialists lead; above it the balanced candidate leads. The result follows from comparing $1/(k+1)+1/(k+4)$ with $2/(k+2)$.

## 3. Query Transformation Without Losing the Question

HyDE generates a hypothetical relevant document, embeds it, and retrieves real documents near that representation [[5]](#ref-5). The hypothetical text is a search aid, not a factual source. Query expansion can improve recall but can also drift toward an invented entity or interpretation.

Retain the original query and exact identifiers alongside expansions. Log transformation versions, compare against an unexpanded baseline, and measure whether useful evidence survives the final context budget. Evaluate recall at candidate depth and downstream answer quality separately: more retrieved text can increase cost or introduce distractors.

## 4. Spend Joint Attention on a Candidate Pool

A bi-encoder can precompute document vectors. A cross-encoder jointly processes the query and each candidate, allowing token-level interaction before producing a relevance score. Across $N$ candidates it needs roughly $N$ pair evaluations, each with its own sequence-length and architecture cost. This is distinct from saying that its complete computation is merely $O(N)$.

Choose the candidate pool by a measured recall/latency trade-off, not a fixed “top 100” rule. First-stage misses are unavailable to the reranker. Account for batching, truncation, document length, language, and query-domain shift. A high reranking score is neither proof of truth nor permission to expose a document.

## 5. Late Interaction and MaxSim

ColBERT independently encodes queries and documents but preserves multiple token vectors, then computes a fine-grained interaction [[3]](#ref-3):

$$
S(q,d)=\sum_{i\in I_q}\max_{j\in I_d}\langle E_{q_i},E_{d_j}\rangle.
$$

$I_q$ and $I_d$ are the valid query/document token positions and $E$ the token representations. With normalized vectors, the dot product is cosine similarity. Taking the best document match per query token preserves local evidence that a single pooled vector can lose.

Mask document padding **before** taking the maximum: a zero padding vector can otherwise beat every negative real-token similarity. Mask query padding after the maximum; reject an empty document explicitly. Define special-token filtering and query augmentation consistently with the selected checkpoint. A dense batched implementation materializing $[B,Q,D]$ similarities needs approximately $B Q D s$ bytes just for that tensor, where $s$ is bytes per value; it is not a production memory estimate for the full pipeline. Chunking and index-specific kernels change the trade-off.

ColBERT can support indexed retrieval as well as reranking; it is not restricted to a second stage. Multi-vector storage and index construction must be included in its cost comparison.

## 6. Generative and Decision-based Reranking

RankGPT studies prompted LLM reranking, including listwise identifier permutations [[4]](#ref-4). A listwise system may use sliding windows rather than fitting the entire corpus into one prompt. Pointwise, pairwise, and listwise methods trade query budget, context, calibration, and ordering sensitivity; none universally replaces cross-encoders.

Validate identifier membership, duplicates, omissions, truncation, and output order. Treat passage text as untrusted data and test instruction injection inside passages. Randomize candidate order for evaluation and report variation. Typed relevance judgments offer another bounded interface; [Section 16.7](/chapter-16/decision-models-and-selective-prediction) explains why typed outputs still require semantic and calibration checks.

## 7. A Release Gate for Retrieval Changes

Compare lexical-only, dense-only, fused, and reranked systems on the same frozen queries and corpus version. Report recall@K, nDCG@K or MRR where appropriate, paired uncertainty, language/domain slices, and downstream citation-supported answer quality. Measure index build/storage, p95 latency, token cost, and empty-result/error rates.

Apply tenant/ACL filters before evidence reaches the model, preserving authorization through caches and reranking. Pin corpus lineage, deletion tombstones, embedding/tokenizer versions, index parameters, fusion policy, reranker, and prompt as an artifact bundle. Keep a known-good index route and test rollback without resurrecting deleted content. Next, GraphRAG considers when explicit relationships improve evidence traversal beyond a ranked list.

## Quizzes

<details>
<summary>Quiz 1: Why can a document absent from one list still win RRF?</summary>
*It receives no contribution from the missing list but can accumulate enough rank contribution elsewhere. Candidate depth, k, and competing documents determine the result.*
</details>

<details>
<summary>Quiz 2: Why must document padding be masked before MaxSim?</summary>
*A zero padded vector can beat negative similarities from real tokens. Query masking alone does not prevent that document-side error.*
</details>

<details>
<summary>Quiz 3: Does listwise reranking establish that a passage is true?</summary>
*No. It estimates ordering under a prompt and candidate set. Validate source support, identifiers, access permissions, and injection resistance independently.*
</details>

<details>
<summary>Quiz 4: Why measure downstream quality as well as recall?</summary>
*More candidates can add cost, distractors, or context truncation. A retrieval gain need not survive the reranker and generator.*
</details>

<details>
<summary>Quiz 5: What happens at k = 2 in the interactive example?</summary>
*The (1,4), (4,1), and (2,2) documents all score 0.5. An identifier tie-break affects display order, not relevance.*
</details>
